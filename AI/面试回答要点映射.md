## 内容沉淀区

### 01. 如何理解 DeepSeek Harness，它有什么特点和优势？

- 一句话结论：DeepSeek Harness 是一套以 Cordis 微内核为底座的全插件化 Agent 运行框架，它把 Agent Loop、模型、工具和会话等运行时能力都做成可组合、可替换的插件，并通过时空可组合性处理插件撤销和依赖变化。
- 30秒回答：DeepSeek Harness 不是一个开箱即用的具体 Agent，而是一套组装 Agent 的运行框架。它的微内核 Cordis 负责插件注册、生命周期、依赖和动态装卸，Agent Loop、模型适配器、工具、Session、文件系统等能力由插件提供。它的优势是可以按业务快速组合不同的垂直 Agent，也能替换甚至动态修改运行时能力。更关键的是，Cordis 用时间可组合性管理插件卸载后的资源撤销，用空间可组合性处理插件依赖失效和恢复，为 Agent 自我修改及回退提供基础。
- 1分钟展开：
  - **先讲本质**：DeepSeek Harness 是全插件化的 Agent 运行框架。微内核 Cordis 只负责插件注册、生命周期、依赖和动态装卸；模型、工具、Agent Loop、Session、文件系统等具体能力都由插件提供。
  - **再做类比**：它可以类比 Vite 的插件体系，但插件化程度更深，因为它不只扩展外围能力，连 Agent Loop 和模型适配器也能替换。
  - **第一个优势是易扩展**：企业接入内部模型、数据库、搜索系统或安全策略时，主要通过新增或替换插件完成，不必反复修改框架核心。
  - **第二个优势是按业务组合**：Coding Agent 可以组合文件系统、Shell、Git 和代码模型；Research Agent 可以组合搜索、浏览器和文档工具，同一底座能形成不同的垂直 Harness。
  - **第三个优势是支持自我优化**：Agent 发现能力不足时，可以创建或调整插件，并在任务结束后决定保留、回退或删除。但这也带来核心问题：Agent 改完自己以后，能不能安全恢复原状？
  - **接着说明时空可组合性**：时间维度负责撤销单个插件对 Runtime 注册的 Tool、Listener、Service 等影响，使运行时尽可能回到安装前；空间维度负责处理插件之间的依赖关系，依赖失效时暂停相关插件，兼容能力恢复后再继续运行。
  - **最后做方案对比**：Pi 更像“固定 Agent Core 加 Extension、Skill”，DeepSeek Harness 更像“插件运行时加一组组成 Agent 的插件”，连 Runtime 本身也可以重组。
  - **落到适用方向**：它适合快速组合垂直 Agent、建设企业内部共享插件生态，以及探索 Agent 对自身 Runtime 的持续修改、评估和优化。
- 高频关键词：DeepSeek Harness、Cordis、微内核、全插件化、Agent Runtime、Agent Loop、依赖注入、生命周期、动态装卸、时间可组合性、空间可组合性、垂直 Agent、自我修改、回退
- 易追问：Cordis 和普通插件系统有什么区别？为什么 Agent Loop 也要插件化？时间可组合性是否等于完整事务回滚？插件依赖失效后如何恢复？自修改插件如何验证安全性？DeepSeek Harness 和 Pi、LangGraph、Codex 的抽象层级有什么区别？
- 回答雷区：不要把 DeepSeek Harness 说成具体模型或已经完成的 Agent 产品；不要把“插件可卸载”直接等同于所有外部副作用都能自动回滚，数据库、文件和外部 API 的影响仍需额外治理；不要把自我修改直接说成安全可靠的自进化，它还需要测试、沙箱、权限、版本和评估机制；对比 Pi 时应强调抽象层级和设计取向，不要简单下结论说谁更先进。
