## 相关面试真题


### 请详细说明FFmpeg中**简单滤镜**与**复杂滤镜**的本质区别，并解释Filtergraph滤镜图的核心语法规则


#### 考察点

- 对滤镜系统底层执行机制的理解
- Filtergraph语法的掌握程度
- 能否根据业务需求选择正确的滤镜类型


#### 示例解答


简单滤镜与复杂滤镜是FFmpeg滤镜系统中两个严格区分的概念，二者的本质区别在于**输入输出流的数量与处理能力**，对应不同的语法与适用场景：


1. **简单滤镜（Simple Filters）**

   - 定义：只有**一个输入流**和**一个输出流**，且输入输出流的媒体类型（视频/音频）必须完全相同
   - 语法：使用`-vf`（视频滤镜）或`-af`（音频滤镜）参数调用
   - 能力边界：只能对单一流进行线性处理，无法处理多个输入、无法产生多个输出、无法进行跨类型流操作
   - 典型示例：缩放（scale）、裁剪（crop）、旋转（transpose）、音量调节（volume）等单一变换操作
2. **复杂滤镜（Complex Filters）**

   - 定义：支持**任意数量的输入流**和**任意数量的输出流**，支持不同类型流之间的混合与操作
   - 语法：必须使用`-filter_complex`参数调用，是实现所有复杂媒体效果的唯一途径
   - 核心能力：可以构建任意拓扑结构的处理流水线，实现多视频拼接、画中画、音频混合、多轨道输出等复杂功能
   - 典型示例：xfade转场、xstack网格拼接、amix多音频混合、overlay画中画等


#### Filtergraph滤镜图核心语法规则

Filtergraph是FFmpeg定义的用于描述滤镜连接关系的领域特定语言，核心语法包括四个基本单元：

1. **流标记（Pad Labels）**：用方括号`[]`标记输入输出流，格式为`[文件索引:流类型]`（如`[0:v]`表示第一个输入的视频流），自定义输出流标记用于连接后续滤镜
2. **单个滤镜**：语法为`滤镜名=参数1=值1:参数2=值2`，多个参数用冒号分隔，含特殊字符的参数值需用引号包裹
3. **滤镜链（Filter Chain）**：多个滤镜串联而成，前一个滤镜的输出作为后一个滤镜的输入，滤镜之间用逗号`,`分隔
4. **滤镜图（Filter Graph）**：多个滤镜链并行或交叉连接而成，滤镜链之间用分号`;`分隔，通过流标记实现不同链之间的数据传递


### 请使用FFmpeg实现**2×2四宫格视频拼接**，要求四个输入视频分辨率不同，输出为1920×1080分辨率，并解释关键参数与常见错误原因


#### 考察点

- 复杂滤镜图的构建能力
- xstack滤镜的实际应用
- 多视频处理中的常见问题排查
- 业务需求到FFmpeg命令的转化能力


#### 示例解答

对于分辨率不同的多视频拼接，必须先将所有输入视频统一缩放到相同的子窗口尺寸，再使用`xstack`滤镜进行网格布局。完整命令如下：


```Bash
ffmpeg -i input1.mp4 -i input2.mp4 -i input3.mp4 -i input4.mp4 \
-filter_complex "
# 第一步：将所有输入视频统一缩放到960×540（四宫格每个子窗口尺寸）
[0:v]scale=960:540:force_original_aspect_ratio=decrease,pad=960:540:(ow-iw)/2:(oh-ih)/2:black[v0];
[1:v]scale=960:540:force_original_aspect_ratio=decrease,pad=960:540:(ow-iw)/2:(oh-ih)/2:black[v1];
[2:v]scale=960:540:force_original_aspect_ratio=decrease,pad=960:540:(ow-iw)/2:(oh-ih)/2:black[v2];
[3:v]scale=960:540:force_original_aspect_ratio=decrease,pad=960:540:(ow-iw)/2:(oh-ih)/2:black[v3];
# 第二步：使用xstack进行2×2网格拼接
[v0][v1][v2][v3]xstack=inputs=4:layout=0_0|1_0|0_1|1_1[out_v]
" \
-map "[out_v]" -map 0:a \ # 取第一个输入的音频作为输出音频
-c:v libx264 -crf 28 -preset medium \
-c:a aac -b:a 128k \
output_4grid.mp4
```


#### 关键参数解释

1. `scale=960:540:force_original_aspect_ratio=decrease`：将视频缩放到不超过960×540的最大尺寸，保持原始宽高比，避免拉伸变形
2. `pad=960:540:(ow-iw)/2:(oh-ih)/2:black`：将缩放后的视频填充到960×540的画布，不足部分用黑色填充，居中对齐
3. `xstack=inputs=4:layout=0_0|1_0|0_1|1_1`：指定4个输入流，布局为第一行0_0、1_0，第二行0_1、1_1
4. `-map "[out_v]"`：将滤镜输出的视频流映射到输出文件


### 在大规模批量视频处理场景中，如何优化FFmpeg滤镜处理的性能？请至少说出3种核心优化方案并说明原理


#### 考察点

- 对FFmpeg性能瓶颈的理解
- 硬件加速的实际应用能力
- 工程化批量处理的经验
- 性能与质量的权衡能力


#### 核心答案

FFmpeg滤镜处理是计算密集型任务，在大规模批量处理场景中，性能优化至关重要。以下是三种最有效的核心优化方案：


##### 方案1：全链路硬件加速

这是性能提升最显著的优化方式，将滤镜处理和编解码操作全部卸载到GPU执行，速度提升5-10倍。


**实现原理**：现代GPU内置专用的视频处理单元，能够并行执行像素级计算，远快于CPU的串行执行。FFmpeg支持NVIDIA NVENC/NVDEC、Intel QSV、Apple VideoToolbox等多种硬件加速方案。


**实战示例（NVIDIA GPU）**：

```Bash
ffmpeg -hwaccel cuda -hwaccel_output_format cuda \
-i input.mp4 \
-vf "scale_cuda=1280:720,overlay_cuda=x=10:y=10" \
-c:v h264_nvenc -preset p6 -rc constqp -qp 28 \
-c:a copy \
output_hw.mp4
```

- `-hwaccel cuda`：启用CUDA硬件解码
- `-hwaccel_output_format cuda`：解码后的数据保留在GPU显存中，避免CPU与GPU之间的数据拷贝
- `scale_cuda`/`overlay_cuda`：使用GPU加速的滤镜，直接在显存中处理数据
- `h264_nvenc`：使用NVENC硬件编码器


**💡 提示**

需要注意的是，执行前最好检测机器对应命令是否存在：
ffmpeg -encoders | grep nvenc
ffmpeg -encoders | grep qsv
ffmpeg -filters | grep scale_cuda


##### 方案2：滤镜链优化与计算量控制

通过合理设计滤镜链，减少不必要的计算，能够显著提升处理速度。


**核心优化原则**：

1. **尽早降采样**：将缩放操作放在滤镜链的最前面，降低后续所有滤镜的处理分辨率
2. **合并冗余操作**：将多个可以合并的滤镜操作合并为一个，例如同时调整亮度和对比度使用`eq`滤镜，而不是分开使用多个滤镜
3. **选择低复杂度滤镜**：在效果满足需求的前提下，优先使用计算量小的滤镜，例如使用`boxblur`代替`gblur`实现快速模糊
4. **避免不必要的颜色空间转换**：确保滤镜输入输出的像素格式与编码器要求一致，减少自动转换的开销

**反例与优化示例**：

```Bash
# 反例：先处理再缩放，计算量大
-vf "eq=brightness=0.1,unsharp=3:3:1.5,scale=1280:720"

# 优化：先缩放再处理，计算量减少75%
-vf "scale=1280:720,eq=brightness=0.1,unsharp=3:3:1.5"
```


##### 方案3：编码参数优化

编码是FFmpeg处理中计算量最大的环节之一，合理调整编码参数能够在质量损失可接受的前提下大幅提升速度。


**核心优化参数**：

1. **调整preset**：preset控制编码速度与压缩率的权衡，批量处理推荐使用`medium`或`fast`，实时处理推荐使用`veryfast`或`superfast`
2. **使用CRF模式**：相比CBR模式，CRF模式在相同质量下编码速度更快，压缩率更高
3. **限制参考帧数量**：减少`-refs`参数值，降低编码复杂度
4. **禁用B帧**：在对延迟不敏感的场景下，禁用B帧可以显著提升编码速度

**实战示例**：

```Bash
# 快速编码配置，适合批量处理
-c:v libx264 -preset fast -crf 28 -refs 3 -bf 0
```


## 课程导入与滤镜系统核心价值


### 滤镜系统的重要性


FFmpeg的核心竞争力不仅在于其全面的编解码与封装支持，更在于其**可编程的滤镜系统**。如果说基础转码与裁剪是FFmpeg的“躯干”，那么滤镜系统就是FFmpeg的“灵魂”——它允许开发者对解码后的原始音视频数据进行任意粒度的修改与组合，实现从简单几何变换到复杂特效合成的所有功能。


在工业级场景中，滤镜系统是所有自动化媒体处理流水线的核心。短视频平台的批量内容生产、直播平台的实时特效叠加、在线教育的课件与讲师画面合成、广电行业的节目后期制作，都深度依赖FFmpeg滤镜系统的强大能力。掌握滤镜系统，意味着能够脱离专业剪辑软件，通过代码实现全自动化的媒体处理流程。

- **在线教育**：讲师摄像头与课件画面合成、多讲师画面布局、板书叠加

- **媒体资产管理**：批量转码、缩略图生成、关键帧提取、内容审核预处理


## FFmpeg滤镜系统核心原理与Filtergraph语法


### 滤镜系统的执行位置与数据流向


FFmpeg的完整处理流程可以精确划分为以下7个阶段：


```Plain Text
解协议 → 解封装 → 解码 → 滤镜处理 → 编码 → 封装 → 输出
```


滤镜处理是唯一操作**原始未压缩数据**的阶段：视频滤镜操作YUV格式的原始像素数据，音频滤镜操作PCM格式的原始音频数据。这一特性决定了滤镜系统的两个核心特点：


1. **能力无限**：可以对音视频数据进行任意修改
2. **计算密集**：所有操作都基于原始数据，是FFmpeg中计算量最大的阶段

这也解释了为什么`-c copy`（流复制模式）无法使用任何滤镜——流复制模式直接跳过了解码和编码阶段，没有原始数据可供滤镜处理。任何使用滤镜的命令，都必然会触发重新编码。


### 简单滤镜与复杂滤镜


FFmpeg滤镜分为两个严格区分的类别，二者的语法与能力边界完全不同。


**简单滤镜（Simple Filters）**：只有一个输入流和一个输出流，且输入输出流的类型完全相同。使用`-vf`（视频滤镜）或`-af`（音频滤镜）参数指定。示例包括缩放、裁剪、旋转、音量调节等。简单滤镜无法处理多个输入流，无法产生多个输出流，无法进行不同类型流之间的操作。


**复杂滤镜（Complex Filters）**：支持任意数量的输入流和输出流，支持不同类型流之间的操作。必须使用`-filter_complex`参数指定。示例包括多视频拼接、画中画、音频混合、多轨道输出等。复杂滤镜是实现所有复杂媒体处理效果的唯一途径。


### Filtergraph滤镜图完整语法详解


Filtergraph是FFmpeg定义的一种用于描述滤镜连接关系的领域特定语言（DSL），是所有复杂滤镜操作的基础。其核心语法规则如下：


#### 基本组成单元


一个完整的Filtergraph由以下基本单元组成：


1. **流标记（Pad Labels）**：用方括号`[]`标记的输入输出流，格式为`[输入标识]`

   - 输入流标记：`[n:t]`，其中`n`是输入文件索引（从0开始），`t`是流类型（`v`视频、`a`音频、`s`字幕）
   - 示例：`[0:v]`表示第一个输入文件的视频流，`[1:a]`表示第二个输入文件的音频流
   - 输出流标记：自定义名称，用于连接后续滤镜
2. **滤镜（Filter）**：单个滤镜的语法为`滤镜名=参数1=值1:参数2=值2`

   - 多个参数用冒号`:`分隔
   - 参数值包含特殊字符时，需用单引号或双引号括起来
3. **滤镜链（Filter Chain）**：多个滤镜串联而成，前一个滤镜的输出作为后一个滤镜的输入

   - 滤镜之间用逗号`,`分隔
   - 示例：`[0:v]scale=1280:-2,crop=in_h:in_h[output]`
4. **滤镜图（Filter Graph）**：多个滤镜链并行或交叉连接而成

   - 滤镜链之间用分号`;`分隔
   - 通过流标记实现不同滤镜链之间的连接

#### 完整语法示例


以下是一个典型的复杂滤镜图示例，实现画中画效果：


```Bash
-filter_complex "[0:v]scale=1920:1080[bg];[1:v]scale=320:180[pip];[bg][pip]overlay=10:10"
```


该滤镜图的执行流程：

1. 取第一个输入文件的视频流`[0:v]`，缩放到1920×1080，标记为`[bg]`
2. 取第二个输入文件的视频流`[1:v]`，缩放到320×180，标记为`[pip]`
3. 将`[pip]`叠加到`[bg]`的(10,10)位置，最终输出标记为`[out]`

#### 输出流映射


复杂滤镜产生的输出流需要通过`-map`参数映射到输出文件：


```Bash
ffmpeg -i background.mp4 -i pip.mp4 \
-filter_complex "[0:v]scale=1920:1080,split=2[bg_for_overlay][bg_debug];[1:v]scale=320:180,split=2[pip_for_overlay][pip_debug];[bg_for_overlay][pip_for_overlay]overlay=10:10[out]" \
-map "[bg_debug]" -map "[pip_debug]" -map "[out]" \
-c:v libx264 -crf 28 -c:a aac \
output.mp4
```


这里`-map "[out_v]"`将滤镜产生的`[out_v]`流作为输出文件的视频流，`-map 0:a`将第一个输入文件的音频流直接复制到输出文件。


#### 滤镜表达式与变量


FFmpeg滤镜支持丰富的表达式计算，可以使用内置变量和函数动态计算参数值。常用变量包括：


| 变量 | 含义 |
|-|-|
| `W`, `H` | 主视频的宽度和高度 |
| `w`, `h` | 叠加层（水印/子视频）的宽度和高度 |
| `tw`, `th` | 文字宽度和高度（用于drawtext） |
| `t` | 当前时间（秒） |
| `n` | 当前帧序号（从0开始） |
| `between(t, start, end)` | 判断t是否在区间内 |
| `if(cond, true_val, false_val)` | 条件判断 |


示例：动态水印位置（右下角留边10像素）`overlay=W-w-10:H-h-10`；只在第5到15秒显示水印：`overlay=10:10:enable='between(t,5,15)'`。


#### 复杂滤镜的调试技巧


开发复杂滤镜图时，建议采用以下方法逐步验证：


1. **分段输出中间结果**：临时添加输出映射，检查每个滤镜链的输出是否正确

   ```Bash
   -filter_complex "[0:v]scale=1920:1080[bg];[1:v]scale=320:180[pip];[bg][pip]overlay=10:10[out]" \
   -map "[bg]" -map "[pip]" -map "[out]" \
   # 会生成三个输出文件，便于检查
   ```
2. **使用null输出**：不产生实际文件，仅验证语法正确性

   ```Bash
   ffmpeg -i input.mp4 -filter_complex "..." -f null -
   ```
3. **利用ffprobe查看流信息**：确认滤镜输出的像素格式、分辨率等是否符合预期


## 核心滤镜分类详解


### 视频基础变换与画面进阶处理


#### 基础几何变换滤镜


这是最常用的一类滤镜，用于对视频进行基本的几何调整。


| 滤镜名 | 功能 | 核心参数 | 常用示例 |
|-|-|-|-|
| `scale` | 调整分辨率 | `w`宽度, `h`高度<br>`-1`表示自动等比 | `scale=1280:-2`（宽1280，高自动）<br>`scale=-1:720`（高720，宽自动） |
| `crop` | 裁剪画面 | `w`裁剪宽度, `h`裁剪高度<br>`x`左上角x坐标, `y`左上角y坐标 | `crop=in_h:in_h`（裁剪中间正方形）<br>`crop=1080:1920`（裁剪为9:16竖屏） |
| `transpose` | 旋转画面 | `0`逆时针90°<br>`1`顺时针90°<br>`2`逆时针180°<br>`3`顺时针180° | `transpose=1`（顺时针旋转90°） |
| `hflip`/`vflip` | 水平/垂直翻转 | 无参数 | `hflip`（水平翻转） |
| `pad` | 添加边框 | `w`输出宽度, `h`输出高度<br>`x`水平偏移, `y`垂直偏移<br>`color`边框颜色 | `pad=1080:1920:(ow-iw)/2:(oh-ih)/2:black`（上下加黑边） |


**特别注意**：使用`scale`时，若高度或宽度为奇数，某些编码器（如H.264）会报错。建议使用偶数对齐：`scale=1280:trunc(ow/a/2)*2`。


#### 画面进阶处理滤镜


##### 颜色校正类滤镜


- `colorbalance`：调整颜色平衡，修正偏色问题

  ```Bash
  # 增加红色和绿色，减少蓝色
  -vf "colorbalance=rs=0.1:gs=0.1:bs=-0.1"
  ```
- `eq`：调整亮度、对比度、饱和度

  ```Bash
  # 亮度+0.1，对比度+1.2，饱和度+1.3
  -vf "eq=brightness=0.1:contrast=1.2:saturation=1.3"
  ```

##### 模糊与锐化类滤镜


- `boxblur`：方框模糊，速度快

  ```Bash
  # 半径5，功率1
  -vf "boxblur=5:1"
  ```
- `gblur`：高斯模糊，效果更自然

  ```Bash
  # 标准差5
  -vf "gblur=sigma=5"
  ```
- `unsharp`：锐化，提升画面清晰度

  ```Bash
  # 亮度锐化量1.5，半径3
  -vf "unsharp=3:3:1.5"
  ```

##### 去噪类滤镜


- `nlmeans`：非局部均值去噪，效果最好但速度慢

  ```Bash
  # 去噪强度10
  -vf "nlmeans=10"
  ```

#### 像素格式与色彩空间转换


滤镜处理过程中，像素格式的一致性至关重要。大多数编码器要求输入为`yuv420p`格式。使用`format`滤镜可以强制转换：


```Bash
# 在滤镜链末尾添加格式转换
-vf "scale=1280:-2,format=yuv420p"
```


如果涉及颜色空间转换（如BT.709到BT.601），可以使用`colorspace`滤镜：

```Bash
-vf "setparams=colorspace=bt709:color_trc=bt709:color_primaries=bt709,colorspace=space=bt709:trc=bt709:primaries=bt709:range=pc"
```


### 叠加类滤镜


叠加类滤镜用于将多个元素（图片、视频、文字）叠加到主视频上，是实现水印、画中画、字幕等效果的基础。


#### overlay滤镜（核心）


`overlay`是FFmpeg中最常用的复杂滤镜，用于将一个视频或图片叠加到另一个视频上。


**基本语法**：

```Plain Text
[主视频][叠加层]overlay=x:y[输出]
```


**核心参数**：

- `x`/`y`：叠加层左上角相对于主视频的坐标
- `enable`：时间条件表达式，控制叠加层何时显示
- `alpha`：透明度控制表达式

**常用位置示例**：

```Bash
# 左上角
overlay=10:10
# 右上角
overlay=W-w-10:10
# 左下角
overlay=10:H-h-10
# 右下角
overlay=W-w-10:H-h-10
# 居中
overlay=(W-w)/2:(H-h)/2
```


**高级用法：定时显示与淡入淡出**

```Bash
# 第5秒开始显示，第15秒消失
overlay=10:10:enable='between(t,5,15)'

# 前3秒淡入，最后3秒淡出（alpha值范围0-1）
[1:v]format=yuva420p,fade=t=in:st=0:d=3:alpha=1,fade=t=out:st=17:d=3:alpha=1[wm];
[0:v][wm]overlay=10:10[out]
```


#### drawtext滤镜（文字叠加）


用于在视频上叠加文字，支持自定义字体、字号、颜色、位置等。


**基本语法**：

```Plain Text
drawtext=text='文字内容':fontfile=字体路径:fontsize=字号:fontcolor=颜色:x=x坐标:y=y坐标
```


**核心参数**：

- `text`：文字内容，支持`%{pts}`等时间变量
- `fontfile`：字体文件路径（必须指定，否则无法显示中文）
- `fontsize`：字号
- `fontcolor`：文字颜色（支持十六进制如`0xFFFFFF`）
- `x`/`y`：文字位置，支持与overlay相同的内置变量，其中`tw`/`th`为文字宽度/高度
- `shadowcolor`、`shadowx`、`shadowy`：文字阴影

**示例**：

```Bash
# 在视频底部居中添加白色文字，字号36
-vf "drawtext=text='这是测试文字':fontfile=/path/to/simhei.ttf:fontsize=36:fontcolor=white:x=(W-tw)/2:y=H-th-20"

# 动态显示当前时间（pts格式）
-vf "drawtext=text='%{pts\:hms}':fontfile=simhei.ttf:fontsize=24:fontcolor=yellow:x=10:y=10"
```


### 多流拼接类滤镜


用于将多个视频或图片拼接成一个视频，是在线剪辑工具的核心功能。


#### hstack / vstack 滤镜


用于横向或纵向拼接多个视频。所有输入视频的高度（hstack）或宽度（vstack）必须相同。


```Bash
# 横向拼接两个视频
ffmpeg -i input1.mp4 -i input2.mp4 \
-filter_complex "[0:v][1:v]hstack=inputs=2[out]" \
-map "[out]" -map 0:a \
output.mp4

# 纵向拼接三个视频
ffmpeg -i input1.mp4 -i input2.mp4 -i input3.mp4 \
-filter_complex "[0:v][1:v][2:v]vstack=inputs=3[out]" \
-map "[out]" -map 0:a \
output.mp4
```


#### xstack 滤镜（任意网格拼接）


`xstack`是功能最强大的拼接滤镜，支持任意数量的输入和任意网格布局。


**基本语法**：

```Plain Text
xstack=inputs=输入数量:layout=布局字符串
```


**布局字符串格式**：`列_行|列_行|...`，每个位置对应一个输入视频。列和行从0开始编号。


**常用布局示例**：

```Bash
# 2×2四宫格
layout=0_0|1_0|0_1|1_1

# 3×3九宫格
xstack=inputs=9:grid=3x3
# 或者
xstack=inputs=4:layout=0_0|w0_0|0_h0|w0_h0

# 1大3小布局（第一行一个大图，第二行三个小图）
layout=0_0|1_1|2_1|3_1
```


**完整示例：九宫格视频**

```Bash
ffmpeg -i v1.mp4 -i v2.mp4 -i v3.mp4 -i v4.mp4 -i v5.mp4 -i v6.mp4 -i v7.mp4 -i v8.mp4 -i v9.mp4 \
-filter_complex "
[0:v]scale=320:180[v0];
[1:v]scale=320:180[v1];
[2:v]scale=320:180[v2];
[3:v]scale=320:180[v3];
[4:v]scale=320:180[v4];
[5:v]scale=320:180[v5];
[6:v]scale=320:180[v6];
[7:v]scale=320:180[v7];
[8:v]scale=320:180[v8];
[v0][v1][v2][v3][v4][v5][v6][v7][v8]xstack=inputs=9:xstack=inputs=9:grid=3x3[out]
" \
-map "[out]" -map 0:a \
-c:v libx264 -crf 28 \
output_9grid.mp4
```


### 音频核心处理滤镜


FFmpeg提供了完整的音频处理能力，覆盖音量调节、混合、变速、降噪等常见需求。


#### 基础音频滤镜


| 滤镜名 | 功能 | 示例 |
|-|-|-|
| `volume` | 调节音量 | `volume=1.5`（放大1.5倍）<br>`volume=0.5`（降低50%） |
| `afade` | 音频淡入淡出 | `afade=t=in:ss=0:d=3`（前3秒淡入）<br>`afade=t=out:st=27:d=3`（最后3秒淡出） |
| `atempo` | 调整播放速度 | `atempo=1.5`（1.5倍速）<br>`atempo=0.8`（0.8倍速） |
| `amix` | 混合多个音频流 | `amix=inputs=2`（混合两个音频） |
| `pan` | 声道映射与混音 | \`pan=stereo |


#### 音频混合实战


将背景音乐与人声混合，背景音乐音量降低50%：


```Bash
ffmpeg -i vocal.wav -i background.wav \
-filter_complex "[1:a]volume=0.5[bg];[0:a][bg]amix=inputs=2[out_a]" \
-map "[out_a]" \
-c:a aac -b:a 128k \
output_mixed.aac
```


#### 音频音量标准化（loudnorm）


直播录制或用户上传的音频音量差异很大，需要使用`loudnorm`滤镜统一到国际标准（如EBU R128）：


```Bash
# 单遍处理（快速，但不精确）
ffmpeg -i input.aac -af loudnorm=I=-16:LRA=11:TP=-1.5 output.aac

# 双遍处理（精确，推荐）
ffmpeg -i input.aac -af loudnorm=I=-16:LRA=11:TP=-1.5:print_format=json -f null -
# 将输出的分析参数填入第二遍命令
ffmpeg -i input.aac -af loudnorm=I=-16:LRA=11:TP=-1.5:measured_I=-23:measured_LRA=7:measured_TP=-2:measured_thresh=-31 output.aac
```

### 滤镜输出与编码器参数优化


滤镜处理的输出直接作为编码器的输入，合理匹配滤镜输出与编码器参数能够显著提升编码效率和质量。


**像素格式统一**：确保滤镜输出的像素格式为编码器支持的格式，Web视频推荐使用`yuv420p`

```Bash
-vf "scale=1280:-2,format=yuv420p"
```


**帧率统一**：所有输入视频的帧率应统一，避免编码器进行帧率转换

```Bash
-r 30
```


**GOP长度匹配**：根据业务需求设置合适的GOP长度，点播推荐2-5秒

```Bash
-g 60  # 30fps下2秒一个I帧
```


**编码预设选择**：根据处理时间要求选择合适的preset，批量处理推荐`medium`或`slow`

```Bash
-preset medium
```


**滤镜线程优化**：对于计算密集的滤镜，可以指定多线程数（默认自动）

```Bash
-filter_threads 4
```

### 高级视频滤镜

#### 转场特效：xfade滤镜

xfade是FFmpeg 4.3+版本引入的专业转场滤镜，支持30+种平滑过渡效果，彻底解决了传统硬切的突兀感，是短视频、影视后期自动化制作的核心工具。


xfade通过对两个输入视频的帧进行像素级混合计算，实现从第一个视频到第二个视频的平滑过渡。转场过程持续指定时长，期间两个视频同时显示并按预设算法混合。


**基本语法**

```Bash
-filter_complex "[0:v][1:v]xfade=transition=转场类型:duration=时长:offset=开始时间[out]"
```


**核心参数**

- `transition`：转场类型，支持fade、wipeleft、wiperight、slideleft、slideright、circlecrop、rectcrop、dissolve等30+种
- `duration`：转场持续时长，单位秒
- `offset`：转场开始时间，即第一个视频播放到该时间点时开始转场


**常用转场示例**

```Bash
# 淡入淡出转场（最常用），持续1秒
ffmpeg -i video1.mp4 -i video2.mp4 \
-filter_complex "[0:v][1:v]xfade=transition=fade:duration=1:offset=4[outv];[0:a][1:a]acrossfade=d=1[outa]" \
-map "[outv]" -map "[outa]" \
-c:v libx264 -crf 28 \
output_fade.mp4

# 左滑转场
xfade=transition=slideleft:duration=0.5:offset=4

# 圆形裁剪转场
xfade=transition=circlecrop:duration=1:offset=4

# 溶解转场
xfade=transition=dissolve:duration=1:offset=4
```


**💡 提示**

注意：视频转场需要配合音频转场滤镜`acrossfade`使用，实现音画同步过渡。


#### 颜色分级：lut3d滤镜

LUT（Look Up Table）是影视行业标准的颜色校正工具，通过3D查找表将原始像素颜色映射为目标颜色，实现电影级调色效果。lut3d滤镜支持导入行业标准的.cube格式LUT文件，一键实现专业调色。


3D LUT是一个三维数组，每个维度对应RGB颜色空间的一个分量。对于输入的每个RGB像素值，通过查找表找到对应的输出颜色值，实现颜色的整体变换。


**基本语法**

```Bash
-vf "lut3d=file=调色文件.cube"
```


**实战示例**

```Bash
# 应用电影级暖色调LUT
ffmpeg -i input.mp4 \
-vf "lut3d=file=warm_film.cube" \
-c:v libx264 -crf 28 \
output_graded.mp4

# 先调整亮度对比度，再应用LUT
ffmpeg -i input.mp4 \
-vf "eq=brightness=0.05:contrast=1.1,lut3d=file=cinematic.cube" \
-c:v libx264 -crf 28 \
output_graded.mp4
```


**💡 提示**

行业常用LUT资源：柯达Kodak LUT、索尼S-Log LUT、大疆D-Log LUT等，可从相机厂商官网免费下载。


#### 视频稳定：vidstabdetect + vidstabtransform

vidstab是FFmpeg集成的专业视频稳定滤镜，采用特征点跟踪算法，有效消除手持拍摄带来的画面抖动，广泛应用于vlog、运动相机视频后期处理。


视频稳定分为两个独立步骤：

1. **分析阶段**：使用`vidstabdetect`滤镜分析视频中的特征点，生成抖动数据文件
2. **变换阶段**：使用`vidstabtransform`滤镜根据抖动数据对视频进行几何变换，消除抖动


**完整实战命令**

```Bash
# 第一步：分析视频抖动，生成transforms.trf数据文件
ffmpeg -i shaky_video.mp4 \
-vf "vidstabdetect=shakiness=10:accuracy=15:result=transforms.trf" \
-f null -

# 第二步：应用稳定变换
ffmpeg -i shaky_video.mp4 \
-vf "vidstabtransform=smoothing=30:input=transforms.trf:crop=black" \
-c:v libx264 -crf 28 \
output_stabilized.mp4
```


**核心参数**

- `shakiness`：抖动程度评估，1-10，值越大表示抖动越剧烈
- `accuracy`：特征点检测精度，1-15，值越高精度越高但速度越慢
- `smoothing`：平滑窗口大小，单位帧，值越大稳定效果越好但画面裁切越多
- `crop`：边缘处理方式，`black`（填充黑边）、`keep`（保持原尺寸）、`zoom`（缩放填充）

ocr滤镜基于Tesseract OCR引擎，能够实时识别视频帧中的文字内容，并输出为字幕或元数据，广泛应用于视频内容审核、自动字幕生成、监控视频分析等场景。

# macOS

```


**基本语法**

```


**实战示例**

### 高级音频滤镜


#### 多声道处理：pan滤镜

pan滤镜是FFmpeg最强大的多声道处理工具，支持任意声道重映射、混合和提取，能够实现从单声道到5.1环绕声的各种声道转换需求。


pan滤镜通过定义声道混合矩阵，将输入声道的信号按指定比例混合到输出声道。语法采用"输出声道=输入声道混合公式"的形式。


**基本语法**

```Bash
-af "pan=输出声道布局|输出声道1=混合公式1|输出声道2=混合公式2..."
```


**常用示例**

```Bash
# 5.1环绕声转立体声（行业标准下混）
ffmpeg -i input_5.1.wav \
-af "pan=stereo|FL=0.707*FC+1.0*FL+0.707*BL+0.5*LFE|FR=0.707*FC+1.0*FR+0.707*BR+0.5*LFE" \
-c:a aac -b:a 128k \
output_stereo.wav

# 立体声转单声道
ffmpeg -i input_stereo.wav \
-af "pan=mono|c0=0.5*FL+0.5*FR" \
-c:a aac -b:a 64k \
output_mono.wav

# 提取立体声中的左声道
ffmpeg -i input_stereo.wav \
-af "pan=mono|c0=FL" \
-c:a aac -b:a 64k \
output_left.wav
```


#### 音频降噪：afftdn滤镜

afftdn（Audio Frequency Domain Denoiser）是FFmpeg中效果最好的降噪滤镜，基于频域分析算法，能够有效去除背景噪声，同时最大程度保留原始语音质量。


afftdn将音频信号转换到频域，通过分析噪声的频谱特征，将噪声分量从信号中分离出来，然后再转换回时域。相比传统的时域降噪滤镜，afftdn在处理平稳背景噪声（如空调声、电流声）时效果显著。


**基本语法**

```Bash
-af "afftdn=nf=噪声帧数:tn=噪声阈值"
```


**核心参数**

- `nf`：用于分析噪声的帧数，默认10，值越大噪声分析越准确
- `tn`：噪声阈值，-30到-10，默认-20，值越大降噪强度越高
- `tnf`：噪声衰减系数，0到1，默认0.9，值越大噪声衰减越多


**实战示例**

```Bash
# 标准降噪处理
ffmpeg -i noisy_audio.wav \
-af "afftdn=nr=12:nf=-35" \
-c:a aac -b:a 128k \
output_denoised.wav

# 强降噪（适合高噪声环境）
ffmpeg -i noisy_audio.wav \
-af "afftdn=nf=30:tn=-30:tnf=0.95" \
-c:a aac -b:a 128k \
output_denoised_strong.wav
```


#### 回声与混响：aecho + reverb滤镜

aecho和reverb滤镜用于为音频添加回声和混响效果，模拟不同空间的声学特性，广泛应用于音乐制作、影视配音等场景。


##### aecho 回声滤镜

```Bash
# 添加单回声效果
ffmpeg -i input.wav \
-af "aecho=0.8:0.9:500:0.5" \
-c:a aac -b:a 128k \
output_echo.wav

# 参数说明：输入增益:输出增益:延迟1:衰减1:延迟2:衰减2...
# 0.8: 输入增益
# 0.9: 输出增益
# 500: 延迟时间（毫秒）
# 0.5: 衰减系数
```


##### reverb混响滤镜【需要确认是否有该滤镜】

```Bash
# 添加大厅混响效果
ffmpeg -i input.wav \
-af "reverb=roomsize=0.8:damping=0.5:wet=0.3:dry=0.7" \
-c:a aac -b:a 128k \
output_reverb.wav

# 核心参数：
# roomsize: 房间大小，0-1，值越大空间感越强
# damping: 阻尼系数，0-1，值越大声音越沉闷
# wet: 混响信号比例
# dry: 原始信号比例
```


#### 音效生成：aevalsrc滤镜

aevalsrc是一个强大的音频信号生成器，能够通过数学表达式生成任意波形的音频信号，包括正弦波、方波、三角波、白噪声等，常用于测试音生成、音效制作等场景。


**基本语法**

```Bash
-f lavfi -i aevalsrc=表达式:duration=时长:sample_rate=采样率
```


**常用示例**

```Bash
# 生成440Hz标准音（A4），持续1秒
ffmpeg -f lavfi -i aevalsrc="sin(440*2*PI*t):d=1" \
-c:a aac -b:a 128k \
440hz_tone.wav

# 生成白噪声，持续5秒
ffmpeg -f lavfi -i aevalsrc="random(0)*2-1:d=5" \
-c:a aac -b:a 128k \
white_noise.wav

# 生成双声道扫频信号（20Hz到20000Hz，持续10秒）
ffmpeg -f lavfi -i aevalsrc="sin(20*2*PI*t+20000*2*PI*t*t/20):d=10:c=2" \
-c:a aac -b:a 128k \
sweep.wav
```


### 实时滤镜处理：Pipe协议与流处理

#### Pipe协议基础

#### FFmpeg滤镜基本结构

一个FFmpeg滤镜主要包含以下四个部分：

1. **注册函数**：向FFmpeg框架注册滤镜
2. **初始化函数**：分配资源，解析参数
3. **帧处理函数**：处理输入帧，生成输出帧
4. **清理函数**：释放资源

#### 简单灰度滤镜实现示例

创建`vf_gray.c`文件，实现一个将彩色视频转为灰度的滤镜：


```C
#include "libavutil/imgutils.h"
#include "libavutil/internal.h"
#include "libavutil/opt.h"
#include "avfilter.h"
#include "internal.h"
#include "video.h"

typedef struct GrayContext {
    const AVClass *class;
} GrayContext;

static int filter_frame(AVFilterLink *inlink, AVFrame *in)
{
    AVFilterLink *outlink = inlink->dst->outputs[0];
    AVFrame *out = ff_get_video_buffer(outlink, outlink->w, outlink->h);
    
    if (!out) {
        av_frame_free(&in);
        return AVERROR(ENOMEM);
    }
    
    av_frame_copy_props(out, in);
    
    // 灰度转换公式：Y = 0.299*R + 0.587*G + 0.114*B
    for (int y = 0; y < in->height; y++) {
        for (int x = 0; x < in->width; x++) {
            uint8_t r = in->data[0][y * in->linesize[0] + x * 3];
            uint8_t g = in->data[0][y * in->linesize[0] + x * 3 + 1];
            uint8_t b = in->data[0][y * in->linesize[0] + x * 3 + 2];
            uint8_t gray = 0.299 * r + 0.587 * g + 0.114 * b;
            
            out->data[0][y * out->linesize[0] + x * 3] = gray;
            out->data[0][y * out->linesize[0] + x * 3 + 1] = gray;
            out->data[0][y * out->linesize[0] + x * 3 + 2] = gray;
        }
    }
    
    av_frame_free(&in);
    return ff_filter_frame(outlink, out);
}

static const AVFilterPad avfilter_vf_gray_inputs[] = {
    {
        .name         = "default",
        .type         = AVMEDIA_TYPE_VIDEO,
        .filter_frame = filter_frame,
    },
};

static const AVFilterPad avfilter_vf_gray_outputs[] = {
    {
        .name = "default",
        .type = AVMEDIA_TYPE_VIDEO,
    },
};

const AVFilter ff_vf_gray = {
    .name        = "gray",
    .description = NULL_IF_CONFIG_SMALL("Convert video to grayscale."),
    .priv_size   = sizeof(GrayContext),
    FILTER_INPUTS(avfilter_vf_gray_inputs),
    FILTER_OUTPUTS(avfilter_vf_gray_outputs),
};
```


#### 编译与集成

1. 将`vf_gray.c`添加到`libavfilter/Makefile`中：

   ```Makefile
   OBJS-$(CONFIG_GRAY_FILTER) += vf_gray.o
   ```
2. 在`libavfilter/allfilters.c`中注册滤镜：

   ```C
   extern const AVFilter ff_vf_gray;
   REGISTER_FILTER(GRAY, gray, vf);
   ```
3. 重新编译FFmpeg：

   ```Bash
   make -j$(nproc)
   sudo make install
   ```
4. 测试自定义滤镜：

   ```Bash
   ffmpeg -i input.mp4 -vf "gray" output_gray.mp4
   ```
