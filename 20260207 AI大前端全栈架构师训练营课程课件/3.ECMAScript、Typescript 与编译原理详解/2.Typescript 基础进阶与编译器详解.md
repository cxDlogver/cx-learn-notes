## 相关面试真题

以下是三个关于 TypeScript 的常见面试题，以及详细的答案：


### 什么是 TypeScript？它与 JavaScript 有什么区别？


TypeScript 是由微软开发的一种开源编程语言，它是 JavaScript 的超集，主要增加了静态类型和一些面向对象的特性。


**TypeScript 的特点和优势**：

1. **静态类型检查**：TypeScript 通过类型系统在编译时进行类型检查，可以在代码运行之前捕获潜在的错误。
2. **现代 JavaScript 特性**：TypeScript 支持最新的 JavaScript 特性，并可以编译为兼容旧版 JavaScript 引擎的代码。
3. **面向对象编程支持**：TypeScript 增加了类、接口、泛型等面向对象的编程特性。
4. **IDE 支持**：TypeScript 提供了丰富的编辑器支持，如智能感知、自动补全和代码重构等功能。


**TypeScript 与 JavaScript 的主要区别**：

1. **类型系统**：JavaScript 是一种动态类型语言，而 TypeScript 是静态类型语言。TypeScript 通过类型注解和类型推断来提供静态类型检查。
2. **编译步骤**：TypeScript 代码需要编译为 JavaScript 才能在浏览器或 Node.js 中运行，而 JavaScript 是解释执行的。
3. **语法扩展**：TypeScript 增加了很多新的语法特性，如接口、泛型、枚举等，这些特性可以帮助开发者编写更健壮和可维护的代码。


### TypeScript 中的 `interface` 和 `type` 有什么区别？


在 TypeScript 中，`interface` 和 `type` 都可以用于定义对象的类型，但它们有一些细微的区别和使用场景。


**`interface`**：

- `interface` 用于定义对象的结构，可以包括属性和方法。
- `interface` 支持继承，可以使用 `extends` 关键字从其他接口继承属性和方法。
- `interface` 可以进行声明合并，即如果定义了多个同名接口，这些接口会自动合并。


**示例**：

```TypeScript
interface Person {
  name: string;
  age: number;
}

interface Employee extends Person {
  employeeId: number;
}

const employee: Employee = {
  name: "John",
  age: 30,
  employeeId: 12345
};
```


**`type`**：

- `type` 用于定义类型别名，可以用于任何类型，包括原始类型、联合类型、元组等。
- `type` 不能继承其他类型，但可以通过交叉类型（`&`）进行组合。
- `type` 更灵活，可以用于定义复杂类型。


**示例**：

```TypeScript
type Person = {
  name: string;
  age: number;
};

type Employee = Person & {
  employeeId: number;
};

const employee: Employee = {
  name: "John",
  age: 30,
  employeeId: 12345
};
```


**区别**：

1. **继承**：`interface` 支持继承，而 `type` 不能继承，但可以通过交叉类型组合。
2. **声明合并**：`interface` 支持声明合并，而 `type` 不支持。
3. **用途**：`type` 更加灵活，可以定义更复杂的类型结构。


### TypeScript 中 `infer` 关键字用途？请举例说明


`infer` 关键字是 TypeScript 2.8 引入的，用于推断类型。`infer` 关键字可以在类型检查过程中提取和捕获某些类型信息


**示例**：

假设我们有一个函数类型 `ReturnType`，用于提取函数的返回类型，我们可以使用 `infer` 关键字实现：


```TypeScript
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : any;

// 示例函数
function exampleFunction(): string {
  return "Hello, TypeScript!";
}

// 使用 ReturnType 提取返回类型
type ExampleReturnType = ReturnType<typeof exampleFunction>;

// ExampleReturnType 的类型是 string
```


**解释**：

1. `ReturnType` 是一个条件类型，接受一个类型参数 `T`。
2. `T extends (...args: any[]) => infer R` 表示如果 `T` 是一个函数类型，那么我们使用 `infer R` 推断其返回类型 `R`。
3. 如果推断成功，`ReturnType` 的结果类型为 `R`；否则，结果类型为 `any`。


**更多示例**：

使用 `infer` 关键字提取元组类型的第一个元素类型：


```TypeScript
type First<T extends any[]> = T extends [infer U, ...any[]] ? U : never;

// 示例
type FirstElement = First<[string, number, boolean]>;
// FirstElement 的类型是 string
```


**解释**：

1. `First` 是一个条件类型，接受一个元组类型参数 `T`。
2. `T extends [infer U, ...any[]]` 表示如果 `T` 是一个包含至少一个元素的元组类型，那么我们使用 `infer U` 推断其第一个元素的类型 `U`。
3. 如果推断成功，`First` 的结果类型为 `U`；否则，结果类型为 `never`。


### TypeScript 中的 `unknown` 和 `any` 有什么区别？


`unknown` 和 `any` 都是 TypeScript 中的顶级类型，但它们在类型检查和使用场景上有明显区别


**`any`**：

- `any` 类型表示任意类型的值。使用 `any` 类型时，TypeScript 会完全放弃类型检查。
- 赋值给 `any` 类型的变量后，可以对其进行任何操作，而不会有类型错误。
- 适用于需要临时绕过类型检查的场景，但不推荐大量使用，因为会失去类型安全的优势。


**示例**：

```TypeScript
let value: any;

value = 123;
value = "Hello";
value = true;

value.foo(); // 没有类型错误，即使 foo 方法不存在
value.toUpperCase(); // 没有类型错误，即使 value 可能不是字符串
```


**`unknown`**：

- `unknown` 类型表示我们尚不知道的类型，通常在接收任意类型值时使用。
- 与 `any` 不同，`unknown` 类型更安全，因为在对其进行操作前，必须进行类型检查。
- 可以将任何类型的值赋给 `unknown` 类型的变量，但不能直接对其进行操作，除非进行类型断言或类型检查。


**示例**：

```TypeScript
let value: unknown;

value = 123;
value = "Hello";
value = true;

value.foo(); // 错误：类型“unknown”上不存在属性“foo”
(value as string).toUpperCase(); // 类型断言后安全使用
```


**示例：类型检查**：

```TypeScript
function processValue(value: unknown) {
  if (typeof value === "string") {
    console.log(value.toUpperCase()); // 类型检查后安全使用
  } else if (typeof value === "number") {
    console.log(value.toFixed(2)); // 类型检查后安全使用
  } else {
    console.log("Unknown type");
  }
}
```

### 环境搭建

Typescript 环境支持有很多种选择，我们可以基于 babel、也可以基于 tsc，或者直接使用 swc，如果是使用 webpack，我们可以借助 ts-loader。

我们提供两种模式进行 Typescript 编译，tsc 和 babel。


#### 基于 TypeScript CLI 的环境搭建


tsc 是 Typescript 库提供的命令行工具，使用 tsc 命令可以将 ts 文件编译输出为 js，并能根据类型定义，输出类型定义文件

TypeScript 提供了官方的命令行工具 `tsc`，用于编译 TypeScript 代码。以下是详细的搭建步骤：


##### 安装 TypeScript


首先，在项目目录下初始化一个新的 npm 项目并安装 TypeScript：


```Bash
mkdir my-ts-project
cd my-ts-project
npm init -y
npm install typescript --save-dev
```


##### 创建 tsconfig.json 文件


`tsconfig.json` 文件用于配置 TypeScript 编译选项。在项目根目录下创建 `tsconfig.json` 文件，并添加以下内容：


```JSON
{
  "compilerOptions": {
    "target": "ES6",
    "module": "commonjs",
    "strict": true,
    "esModuleInterop": true,
    "outDir": "./dist"
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules"]
}
```


##### 创建 TypeScript 源文件


在项目根目录下创建 `src` 目录，并在其中添加一个示例 TypeScript 文件 `index.ts`：


```TypeScript
// src/index.ts
const message: string = "Hello, TypeScript!";
console.log(message);
```


##### 编译 TypeScript 代码


在 `package.json` 文件中添加一个脚本来编译 TypeScript 代码：


```JSON
{
  "scripts": {
    "build": "tsc"
  }
}
```


运行以下命令来编译 TypeScript 代码：


```Bash
pnpm build
```


编译后的 JavaScript 文件将输出到 `dist` 目录中。


#### 基于 Babel 的环境搭建


Babel 是一个 JavaScript 编译器，可以将 TypeScript 编译为 JavaScript。以下是详细的搭建步骤：


##### 1. 安装必要的依赖


首先，在项目目录下初始化一个新的 npm 项目并安装 Babel 和 TypeScript 相关的依赖：


```Bash
mkdir my-babel-ts-project
cd my-babel-ts-project
npm init -y
npm install @babel/core @babel/cli @babel/preset-env @babel/preset-typescript --save-dev
```


##### 2. 创建 Babel 配置文件


在项目根目录下创建 `.babelrc` 文件，并添加以下内容：


```JSON
{
  "presets": [
    "@babel/preset-env",
    "@babel/preset-typescript"
  ]
}
```


##### 3. 创建 TypeScript 源文件


在项目根目录下创建 `src` 目录，并在其中添加一个示例 TypeScript 文件 `index.ts`：


```TypeScript
// src/index.ts
const message: string = "Hello, Babel and TypeScript!";
console.log(message);
```


##### 4. 编译 TypeScript 代码


在 `package.json` 文件中添加一个脚本来使用 Babel 编译 TypeScript 代码：


```JSON
{
  "scripts": {
    "build": "babel src --out-dir dist --extensions '.ts'"
  }
}
```


运行以下命令来编译 TypeScript 代码：


```Bash
npm run build
```


编译后的 JavaScript 文件将输出到 `dist` 目录中。


通过上述步骤，可以分别基于 TypeScript CLI 和 Babel 搭建 TypeScript 的开发环境。两种方法各有优劣，TypeScript CLI 更加直接和官方支持，而 Babel 可以更灵活地与现有的 Babel 工具链集成。选择哪种方法取决于具体的项目需求和开发者的偏好。


### 基础类型定义

TypeScript 提供了丰富的基础类型定义，这些类型可以帮助开发者在编译时捕获错误，确保代码的健壮性和可维护性。以下是 TypeScript 中常见的基础类型及其定义和使用示例。


#### 基础类型


##### 1. 布尔值 (`boolean`)

布尔类型表示 `true` 或 `false`。

```TypeScript
let isDone: boolean = true;
```


##### 2. 数字 (`number`)

TypeScript 中的所有数字都是浮点数。`number` 类型用于表示整数和浮点数。

```TypeScript
let decimal: number = 6;
let hex: number = 0xf00d;
let binary: number = 0b1010;
let octal: number = 0o744;
```


##### 3. 字符串 (`string`)

字符串类型表示文本数据。可以使用双引号（`"`）、单引号（`'`）或反引号（`` ` ``）来表示字符串。

```TypeScript
let color: string = "blue";
color = 'red';

let fullName: string = `John Doe`;
let age: number = 25;
let sentence: string = `Hello, my name is ${fullName}. I'll be ${age + 1} years old next month.`;
```


##### 4. 数组 (`Array`)

数组类型有两种定义方式：使用元素类型后加方括号，或使用泛型数组类型。

```TypeScript
let list: number[] = [1, 2, 3];
let list: Array<number> = [1, 2, 3];
```


##### 5. 元组 (`Tuple`)

元组类型允许表示一个已知元素数量和类型的数组，各元素的类型不必相同。

```TypeScript
let x: [string, number];
x = ["hello", 10]; // OK
// x = [10, "hello"]; // Error
```


##### 6. 枚举 (`enum`)

枚举类型用于定义一组命名的常量。可以为这些常量指定具体的值，也可以让 TypeScript 自动为其赋值。

```TypeScript
enum Color { Red, Green, Blue }
let c: Color = Color.Green;

enum Color { Red = 1, Green, Blue }
let c: Color = Color.Green;

enum Color { Red = 1, Green = 2, Blue = 4 }
let c: Color = Color.Green;

let colorName: string = Color[2];
console.log(colorName); // Displays 'Green'
```


##### 7. `any`

`any` 类型表示任意类型。使用 `any` 类型的变量可以赋值为任何类型的值。

```TypeScript
let notSure: any = 4;
notSure = "maybe a string instead";
notSure = false;
```


##### 8. `unknown`

`unknown` 类型表示未知类型。与 `any` 类型不同，`unknown` 类型更安全，因为必须进行类型检查后才能对其进行操作。

```TypeScript
let notSure: unknown = 4;
notSure = "maybe a string instead";
notSure = false;

if (typeof notSure === "string") {
  console.log(notSure.toUpperCase());
}
```


##### 9. `void`

`void` 类型表示没有任何类型。当一个函数没有返回值时，其返回类型是 `void`。

```TypeScript
function warnUser(): void {
  console.log("This is my warning message");
}
```


##### 10. `null` 和 `undefined`

`null` 和 `undefined` 类型分别表示空值和未定义值。它们是所有其他类型的子类型。

```TypeScript
let u: undefined = undefined;
let n: null = null;
```


##### 11. `never`

`never` 类型表示那些永不存在的值的类型。例如，永远不会有返回值的函数的返回类型。

```TypeScript
function error(message: string): never {
  throw new Error(message);
}

function infiniteLoop(): never {
  while (true) {}
}
```


##### 12. `object`

`object` 类型表示非原始类型，即除了 `number`、`string`、`boolean`、`symbol`、`null` 或 `undefined` 之外的类型。

```TypeScript
let obj: object = { name: "John", age: 30 };
```


### 自定义类型

自定义类型用于定义新的约束类型，例如在 React 源码中，对于组件 key 的类型定义为 Key。

```TypeScript
type Key = string | number | symbol
```

`interface` 用于定义数据描述


### 类型断言


类型断言用于手动指定一个值的类型。它可以通过两种方式进行：

```TypeScript
let someValue: any = "this is a string";
let strLength: number = (someValue as string).length;
// 或
let strLength: number = (<string>someValue).length;
```


### 联合类型与交叉类型


联合类型和交叉类型是 Typescript 中的两个重要概念，用于创建复杂的类型定义。


#### 联合类型 (Union Types)


联合类型表示一个值可以是几种类型。使用竖线（`|`）分隔不同类型。


**示例**：

```TypeScript
let value: string | number;
value = "hello"; // OK
value = 42;      // OK
// value = true; // Error: Type 'boolean' is not assignable to type 'string | number'.
```


**应用场景**：

1. **函数参数**：

联合类型可以用来表示函数参数可能接受多种类型的值。

```TypeScript
function printId(id: number | string) {
    console.log("Your ID is: " + id);
}

printId(101); // OK
printId("202"); // OK
// printId(true); // Error: Argument of type 'boolean' is not assignable to parameter of type 'number | string'.
```


1. **对象属性**：

联合类型可以用于对象属性，以表示属性可能具有多种类型的值。

```TypeScript
interface User {
    name: string;
    age: number | string; // age 可以是数字或字符串
}

const user1: User = { name: "Alice", age: 25 };
const user2: User = { name: "Bob", age: "unknown" };
```


#### 交叉类型 (Intersection Types)


交叉类型表示一个值同时具有多种类型。使用和符号（`&`）将多种类型组合在一起。


**示例**：

```TypeScript
interface Person {
    name: string;
    age: number;
}

interface Employee {
    employeeId: number;
    department: string;
}

type Staff = Person & Employee;

const staff: Staff = {
    name: "John",
    age: 30,
    employeeId: 12345,
    department: "HR"
};
```


**应用场景**：

1. **对象合并**：

交叉类型可以用于对象合并，使对象同时具有多个接口的属性。

```TypeScript
interface Address {
    street: string;
    city: string;
}

interface Contact {
    phone: string;
    email: string;
}

type ContactDetails = Address & Contact;

const contact: ContactDetails = {
    street: "123 Main St",
    city: "Springfield",
    phone: "555-1234",
    email: "john.doe@example.com"
};
```


1. **扩展类**：

交叉类型可以用于创建具有多个类特性的实例。

```TypeScript
class Car {
    drive() {
        console.log("Driving a car");
    }
}

class Boat {
    sail() {
        console.log("Sailing a boat");
    }
}

type AmphibiousVehicle = Car & Boat;

const amphibiousVehicle: AmphibiousVehicle = {
    drive() {
        console.log("Driving on land");
    },
    sail() {
        console.log("Sailing on water");
    }
};

amphibiousVehicle.drive(); // OK
amphibiousVehicle.sail();  // OK
```


- **联合类型** 用于表示一个值可以是几种类型之一，用竖线（`|`）分隔不同的类型。
- **交叉类型** 用于表示一个值同时具有多种类型，用和符号（`&`）将多种类型组合在一起。


### 泛型


泛型（Generics）是 TypeScript 中的一项强大功能，可以让你创建可重用的组件，使组件不仅能够支持一种数据类型，而是能够支持多种数据类型，从而在类型安全的前提下提高代码复用性。


####  泛型函数


泛型函数是使用泛型的最常见方式。你可以在函数名称后面添加一个泛型参数，这样函数就可以处理任意类型的数据。


**示例**：

```TypeScript
function identity<T>(arg: T): T {
    return arg;
}

let output1 = identity<string>("myString"); // 显式地传入类型参数
let output2 = identity("myString"); // 类型推断
```


在这个示例中，`identity` 函数接收一个类型参数 `T`，然后使用 `T` 作为参数和返回值的类型。这使得 `identity` 函数可以处理任何类型的数据。


####  泛型接口


你可以使用泛型定义接口，使接口中的属性和方法能够使用泛型参数。


**示例**：

```TypeScript
interface GenericIdentityFn<T> {
    (arg: T): T;
}

function identity<T>(arg: T): T {
    return arg;
}

let myIdentity: GenericIdentityFn<number> = identity;
```


在这个示例中，`GenericIdentityFn` 接口接收一个类型参数 `T`，并将其用于接口的方法签名。然后，我们定义了一个 `identity` 函数，并将其赋值给 `myIdentity` 变量，指定其类型为 `GenericIdentityFn<number>`。


####  泛型类


类也可以使用泛型，这样类中的属性和方法就可以根据传入的类型参数来进行定义。


**示例**：

```TypeScript
class GenericNumber<T> {
    zeroValue: T;
    add: (x: T, y: T) => T;
}

let myGenericNumber = new GenericNumber<number>();
myGenericNumber.zeroValue = 0;
myGenericNumber.add = (x, y) => x + y;
```


在这个示例中，`GenericNumber` 类接收一个类型参数 `T`，并将其用于类的属性和方法。然后，我们创建了一个 `GenericNumber<number>` 实例，并为其属性赋值和定义方法。


####  泛型约束


有时你可能希望对泛型参数进行一些约束，以确保传入的类型具有某些属性或方法。你可以使用 `extends` 关键字来实现泛型约束。


**示例**：

```TypeScript
interface Lengthwise {
    length: number;
}

function loggingIdentity<T extends Lengthwise>(arg: T): T {
    console.log(arg.length); // 现在可以访问 length 属性了
    return arg;
}

// loggingIdentity(3); // Error: number 类型没有 length 属性
loggingIdentity({ length: 10, value: 3 }); // OK
```


在这个示例中，`loggingIdentity` 函数接收一个类型参数 `T`，并使用 `extends Lengthwise` 对其进行约束，确保 `T` 类型具有 `length` 属性。


#### 泛型工具类型


TypeScript 还提供了一些内置的泛型工具类型，可以帮助你更方便地操作类型。


**示例**：

- **Partial<T>**：将某个类型的属性变为可选。

  ```TypeScript
  interface Person {
      name: string;
      age: number;
  }
  
  let partialPerson: Partial<Person> = {};
  partialPerson.name = "John";
  ```


- **Readonly<T>**：将某个类型的属性变为只读。

  ```TypeScript
  let readonlyPerson: Readonly<Person> = {
      name: "John",
      age: 30
  };
  
  // readonlyPerson.age = 31; // Error: Cannot assign to 'age' because it is a read-only property.
  ```


- **Record<K, T>**：构造一个对象类型，其属性键为 `K`，属性值为 `T`。

  ```TypeScript
  type PersonRecord = Record<string, Person>;
  let persons: PersonRecord = {
      "john": { name: "John", age: 30 },
      "jane": { name: "Jane", age: 25 }
  };
  ```


## Typescript 进阶

### 类型保护


类型保护是 TypeScript 中的一种机制，用于在运行时缩小变量的类型范围，从而更精确地进行类型检查。类型保护可以通过多种方式实现，包括使用 `typeof`、`instanceof`、用户自定义的类型保护函数等。


#### 1. 使用 `typeof` 类型保护


`typeof` 操作符可以用来判断一个变量的类型，它对于判断基本类型（如字符串、数字、布尔值）非常有用。


**示例**：

```TypeScript
function padLeft(value: string, padding: number | string) {
    if (typeof padding === "number") {
        return Array(padding + 1).join(" ") + value;
    }
    if (typeof padding === "string") {
        return padding + value;
    }
    throw new Error(`Expected number or string, but got ${typeof padding}.`);
}

console.log(padLeft("Hello", 4));    // "    Hello"
console.log(padLeft("Hello", ">>>")); // ">>>Hello"
```


在这个示例中，`typeof` 操作符用于检查 `padding` 变量的类型，并根据不同的类型执行不同的操作。


#### 2. 使用 `instanceof` 类型保护


`instanceof` 操作符可以用来判断一个对象是否是某个类的实例。它对于判断复杂对象类型（如类实例）非常有用。


**示例**：

```TypeScript
class Bird {
    fly() {
        console.log("Flying");
    }
}

class Fish {
    swim() {
        console.log("Swimming");
    }
}

function move(animal: Bird | Fish) {
    if (animal instanceof Bird) {
        animal.fly();
    } else if (animal instanceof Fish) {
        animal.swim();
    }
}

const bird = new Bird();
const fish = new Fish();

move(bird); // "Flying"
move(fish); // "Swimming"
```


在这个示例中，`instanceof` 操作符用于检查 `animal` 变量的类型，并根据不同的类型执行相应的方法。


#### 3. 使用 `in` 操作符类型保护


`in` 操作符可以用来检查对象是否具有某个属性。


**示例**：

```TypeScript
interface Bird {
    fly(): void;
    layEggs(): void;
}

interface Fish {
    swim(): void;
    layEggs(): void;
}

function getPet(): Bird | Fish {
    // 返回一个 Bird 或 Fish 实例
}

let pet = getPet();

if ("fly" in pet) {
    pet.fly();
} else {
    pet.swim();
}
```


在这个示例中，`in` 操作符用于检查 `pet` 对象是否具有 `fly` 方法，并根据结果调用不同的方法。


#### 4. 自定义类型保护函数


你可以定义自定义的类型保护函数，通过这种方式，可以实现更复杂的类型检查逻辑。


**示例**：

```TypeScript
interface Bird {
    fly(): void;
    layEggs(): void;
}

interface Fish {
    swim(): void;
    layEggs(): void;
}

function isBird(pet: Bird | Fish): pet is Bird {
    return (pet as Bird).fly !== undefined;
}

function move(pet: Bird | Fish) {
    if (isBird(pet)) {
        pet.fly();
    } else {
        pet.swim();
    }
}

const bird: Bird = {
    fly() { console.log("Flying"); },
    layEggs() { console.log("Laying eggs"); }
};

const fish: Fish = {
    swim() { console.log("Swimming"); },
    layEggs() { console.log("Laying eggs"); }
};

move(bird); // "Flying"
move(fish); // "Swimming"
```


在这个示例中，`isBird` 函数通过检查 `pet` 对象是否具有 `fly` 方法来确定其类型，并使用 `pet is Bird` 语法声明类型保护。这使得在 `move` 函数中可以安全地调用 `pet.fly` 方法。


#### 5. `null` 和 `undefined` 类型保护


在处理 `null` 和 `undefined` 时，类型保护也非常有用。


**示例**：

```TypeScript
function getValue(x: string | null | undefined): string {
    if (x == null) {
        return "default";
    }
    return x;
}

console.log(getValue(null));       // "default"
console.log(getValue(undefined));  // "default"
```

### 类型推导 infer


`infer` 关键字是 TypeScript 2.8 引入的一部分，用于在条件类型中推断类型。它允许你在类型检查过程中提取和捕获某些类型信息，从而实现更灵活和动态的类型推断。


#### 基本语法


`infer` 关键字通常与条件类型一起使用，用于从复杂类型中提取子类型。


**示例**：

```TypeScript
type ReturnType<T> = T extends (...args: any[]) => infer R ? R : any;

function exampleFunction(): string {
    return "Hello, TypeScript!";
}

type ExampleReturnType = ReturnType<typeof exampleFunction>;
// ExampleReturnType 的类型是 string
```


在这个示例中，`ReturnType` 是一个条件类型，用于提取函数类型的返回类型：

- `T extends (...args: any[]) => infer R`：表示如果 `T` 是一个函数类型，则使用 `infer R` 推断其返回类型 `R`。
- `? R : any`：如果推断成功，`ReturnType` 的结果类型为 `R`，否则为 `any`。


#### 更多示例


**1. 提取数组元素类型**


我们可以使用 `infer` 从数组类型中提取元素类型。


```TypeScript
type ElementType<T> = T extends (infer U)[] ? U : T;

type StringArray = string[];
type NumberArray = number[];
type MixedArray = (string | number)[];

type StringElement = ElementType<StringArray>; // string
type NumberElement = ElementType<NumberArray>; // number
type MixedElement = ElementType<MixedArray>;   // string | number
```


在这个示例中，`ElementType` 类型用于提取数组的元素类型：

- `T extends (infer U)[]`：表示如果 `T` 是一个数组类型，则使用 `infer U` 提取其元素类型 `U`。
- `? U : T`：如果 `T` 是数组类型，结果类型为 `U`，否则为 `T`。


**2. 提取元组中的第一个元素类型**


使用 `infer` 从元组类型中提取第一个元素的类型。


```TypeScript
type First<T> = T extends [infer U, ...infer R] ? U : never;

type Tuple1 = [string, number, boolean];
type Tuple2 = [number, boolean];

type FirstElement1 = First<Tuple1>; // string
type FirstElement2 = First<Tuple2>; // number
```


在这个示例中，`First` 类型用于提取元组的第一个元素类型：

- `T extends [infer U, ...any[]]`：表示如果 `T` 是一个包含至少一个元素的元组类型，则使用 `infer U` 提取其第一个元素的类型 `U`。
- `? U : never`：如果 `T` 是元组类型，结果类型为 `U`，否则为 `never`。


**3. 提取函数参数类型**


我们可以使用 `infer` 从函数类型中提取参数类型。


```TypeScript
type Parameters<T> = T extends (...args: infer P) => any ? P : never;

function exampleFunction(arg1: string, arg2: number): void {}

type ExampleParameters = Parameters<typeof exampleFunction>;
// ExampleParameters 的类型是 [string, number]
```


在这个示例中，`Parameters` 类型用于提取函数的参数类型：

- `T extends (...args: infer P) => any`：表示如果 `T` 是一个函数类型，则使用 `infer P` 提取其参数类型 `P`。
- `? P : never`：如果 `T` 是函数类型，结果类型为 `P`，否则为 `never`。

Zod 提供了一种声明式的方式来定义数据的结构，并进行验证。它也可以与 TypeScript 的类型系统无缝集成。

#### 使用 Refine 进行自定义验证

```TypeScript
import { z } from "zod";

// 定义一个 Zod schema
const PasswordSchema = z

  })
  .refine((password) => /[a-z]/.test(password), {
    message: "Password must contain at least one lowercase letter",
  })
  .refine((password) => /[0-9]/.test(password), {

});

const userData: User = {
  username: "john_doe",
  password: "Password123",
};

  UserSchema.parse(userData); // 验证通过
  console.log("Validation succeeded");
} catch (e) {
  console.error("Validation failed", e.errors);
}
```


在这个示例中，`PasswordSchema` 使用 `refine` 方法添加了自定义的验证逻辑，确保密码至少有8个字符，并包含至少一个大写字母、小写字母和数字。


### 注解【仅了解，nestjs 项目常用】


除了基本的类型支持外，TypeScript 还支持类装饰器（Class Decorators）、方法装饰器（Method Decorators）、属性装饰器（Property Decorators）等高级功能。这些装饰器是通过注解的形式对类及其成员进行扩展和修改的。

#### 装饰器概述

装饰器（Decorator）是 TypeScript 中一种特殊类型的声明，常用于类、方法、访问符、属性和参数上。装饰器本质上是一个函数，可以修改类的定义或行为。它们常用于：

- 为类或类成员添加额外的元数据
- 修改类的行为或方法的行为
- 实现 AOP（面向切面编程）

TypeScript 提供了几个内置装饰器，开发者也可以自定义装饰器。

#### 装饰器的配置

为了使 TypeScript 支持装饰器，需要在 `tsconfig.json` 配置文件中开启装饰器选项。具体步骤如下：

```JSON
{
  "compilerOptions": {
    "experimentalDecorators": true,
    "target": "ES6"
  }
}
```

- `experimentalDecorators`: 启用实验性装饰器功能。默认情况下，TypeScript 不支持装饰器，因此需要显式地启用这个选项。

#### 装饰器的类型

TypeScript 支持以下几种装饰器：

- **类装饰器（Class Decorator）**：用于类声明之前，可以修改类的构造函数或添加元数据。
- **方法装饰器（Method Decorator）**：用于类的方法，可以修改方法的行为。
- **属性装饰器（Property Decorator）**：用于类的属性，通常用于为属性添加元数据。
- **访问器装饰器（Accessor Decorator）**：用于类的访问器（getter 和 setter）。
- **参数装饰器（Parameter Decorator）**：用于方法参数。

#### 装饰器的基本使用

下面是一些装饰器的基础示例，包括类装饰器、方法装饰器和属性装饰器的应用。

##### 类装饰器

类装饰器接收一个参数，这个参数是类的构造函数。类装饰器常用于为类添加元数据或修改类的行为。

```TypeScript
function LogClass(constructor: Function) {
  console.log(`Class Decorated: ${constructor.name}`);
}
@LogClass
class MyClass {
  constructor() {
    console.log('MyClass constructor');
  }
}
const myClassInstance = new MyClass();
```

**输出**：

```Plain Text
Class Decorated: MyClass
MyClass constructor
```

##### 方法装饰器

方法装饰器接收三个参数：

- `target`: 被装饰的方法所属的类的原型对象。
- `propertyKey`: 被装饰方法的名称。
- `descriptor`: 方法的属性描述符，它可以修改方法的行为。

```TypeScript
function LogMethod(target: Object, propertyKey: string, descriptor: PropertyDescriptor) {
  console.log(
Method Decorated: ${propertyKey}
);
}
class MyClass {
  @LogMethod
  myMethod() {
    console.log('Hello from myMethod');
  }
}
const myClassInstance = new MyClass();
myClassInstance.myMethod();
```

**输出**：

```Plain Text
Method Decorated: myMethod
Hello from myMethod
```

##### 属性装饰器

属性装饰器接收两个参数：

- `target`: 被装饰的类的原型。
- `propertyKey`: 被装饰的属性名称。

```TypeScript
function LogProperty(target: Object, propertyKey: string) {
  console.log(
Property Decorated: ${propertyKey}
);
}
class MyClass {
  @LogProperty
  myProperty: string = 'Hello';
}
const myClassInstance = new MyClass();
```

**输出**：

```Plain Text
Property Decorated: myProperty
```

##### 综合示例

将类装饰器、方法装饰器和属性装饰器结合使用，展示它们的协同工作。

```TypeScript
function LogClass(constructor: Function) {
  console.log(
Class Decorated: ${constructor.name}
);
}
function LogMethod(target: Object, propertyKey: string, descriptor: PropertyDescriptor) {
  console.log(
Method Decorated: ${propertyKey}
);
}
function LogProperty(target: Object, propertyKey: string) {
  console.log(
Property Decorated: ${propertyKey}
);
}
@LogClass
class MyClass {
  @LogProperty
  myProperty: string = 'Hello';
  @LogMethod
  myMethod() {
    console.log('Hello from myMethod');
  }
}
const myClassInstance = new MyClass();
myClassInstance.myMethod();
```

**输出**：

```Plain Text
Class Decorated: MyClass
Property Decorated: myProperty
Method Decorated: myMethod
Hello from myMethod
```

#### 注解的高级用法

##### 装饰器工厂

装饰器工厂是返回装饰器的函数。它允许装饰器接受参数，并提供更灵活的装饰器定义。

```TypeScript
function Log(message: string) {
  return function(target: Object, propertyKey: string) {
    console.log(
${message}: ${propertyKey}
);
  };
}
class MyClass {
  @Log('Custom Message')
  myProperty: string = 'Hello';
}
const myClassInstance = new MyClass();
```

**输出**：

```Plain Text
Custom Message: myProperty
```

##### 修改方法行为

通过修改 `descriptor`，我们可以更改方法的行为。例如，我们可以在方法调用前后添加日志：

```TypeScript
function LogMethod(target: Object, propertyKey: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value;
  descriptor.value = function(...args: any[]) {
    console.log(
Calling method: ${propertyKey}
);
    const result = originalMethod.apply(this, args);
    console.log(
Method ${propertyKey} called
);
    return result;
  };
}
class MyClass {
  @LogMethod
  myMethod() {
    console.log('Hello from myMethod');
  }
}
const myClassInstance = new MyClass();
myClassInstance.myMethod();
```

**输出**：

```Plain Text
Calling method: myMethod
Hello from myMethod
Method myMethod called
```

```JSON
  "compilerOptions": {
    // 编译器选项
  },
  "include": [
    // 包含的文件
  ],
  "exclude": [
    // 排除的文件
  ],
  "files": [
    // 明确列出的文件
  ]

```


#### compilerOptions


`compilerOptions` 是 `tsconfig.json` 中最重要的部分，用于配置 TypeScript 编译器的行为。


**常见配置项**：


##### **`target`**：指定编译后 JavaScript 的版本。

```JSON
{
  "compilerOptions": {
    "target": "ES6"
  }
}
```


##### **`module`**：指定使用的模块系统。

```JSON
{
  "compilerOptions": {
    "module": "commonjs"
  }
}
```


##### **`outDir`**：指定输出目录。

```JSON
{
  "compilerOptions": {
    "outDir": "./dist"
  }
}
```


##### **`rootDir`**：指定输入文件的根目录。

```JSON
{
  "compilerOptions": {
    "rootDir": "./src"
  }
}
```


##### **`strict`**：启用所有严格类型检查选项。

```JSON
{
  "compilerOptions": {
    "strict": true
  }
}
```


##### **`baseUrl`** 和 **`paths`**：配置模块解析。

```JSON
{
  "compilerOptions": {
    "baseUrl": "./",
    "paths": {
      "@app/*": ["src/app/*"]
    }
  }
}
```


##### **`esModuleInterop`**：启用对 ES 模块的互操作性。

```JSON
{
  "compilerOptions": {
    "esModuleInterop": true
  }
}
```


##### **`lib`**：指定要包含在编译中的库文件。

```JSON
{
  "compilerOptions": {
    "lib": ["ES6", "DOM"]
  }
}
```


##### **`sourceMap`**：生成相应的 `.map` 文件，以便调试。

```JSON
{
  "compilerOptions": {
    "sourceMap": true
  }
}
```


##### **`declaration`**：生成相应的 `.d.ts` 文件，以便其他 TypeScript 项目使用。

```JSON
{
  "compilerOptions": {
    "declaration": true
  }
}
```


#### include 和 exclude


`include` 和 `exclude` 用于指定哪些文件应包含或排除在编译过程中。


**示例**：


```JSON
{
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```


- `include`：指定需要包含的文件或文件夹。
- `exclude`：指定需要排除的文件或文件夹。


#### files


`files` 用于显式地列出要编译的文件。


**示例**：


```JSON
{
  "files": ["src/index.ts"]
}
```


#### extends


`extends` 属性允许一个 `tsconfig.json` 文件扩展另一个配置文件。这对于在大型项目中共享配置非常有用。


**示例**：


```JSON
{
  "extends": "./base-tsconfig.json",
  "compilerOptions": {
    "outDir": "./dist"
  }
}
```


#### composite 和 incremental


这些选项用于支持增量编译和项目引用。


- **`composite`**：启用项目引用时需要设置。

  ```JSON
  {
    "compilerOptions": {
      "composite": true
    }
  }
  ```


- **`incremental`**：启用增量编译，以加快编译速度。

  ```JSON
  {
    "compilerOptions": {
      "incremental": true
    }
  }
  ```

## Typescript 插件【简单了解】

Typescript 插件体系用于增强解析，语言服务插件是一种基于现有 TypeScript 文件向用户提供附加信息的方式。它们可以增强 TypeScript 与编辑器之间的现有信息，或提供自己的错误信息。

## Typescript 源码详解


### TypeScript 源码核心流程


1. **命令行参数解析**
2. **配置文件解析**
3. **文件解析**
4. **词法分析 (Scanner)**
5. **语法分析**
6. **类型检查**
7. **代码生成**
8. **输出结果**


### 对应的核心文件


#### 1. 命令行参数解析

- **文件**：`src/tsc/tsc.ts`
- **功能**：`tsc.ts` 是 TypeScript 编译器的入口文件，它负责解析命令行参数并启动编译过程。


#### 2. 配置文件解析

- **文件**：`src/compiler/commandLineParser.ts`
- **功能**：该文件处理 `tsconfig.json` 配置文件的解析，并将解析结果转换为编译器选项。


#### 3. 文件解析

- **文件**：`src/compiler/program.ts`
- **功能**：`program.ts` 负责创建编译器的程序实例，解析所有输入文件并创建源文件对象。


#### 4. 词法分析

- **文件**：`src/compiler/scanner.ts`
- **功能**：`scanner.ts` 负责将输入的 TypeScript 源代码转换为一系列的词法单元 (Tokens)。


#### 5. 语法分析

- **文件**：`src/compiler/parser.ts`
- **功能**：该文件包含将 TypeScript 代码转换为抽象语法树（AST）的逻辑，是 TypeScript 语法解析的核心。


#### 6. 类型检查

- **文件**：`src/compiler/checker.ts`
- **功能**：`checker.ts` 包含类型检查器的主要逻辑，负责遍历 AST 并执行类型检查。


#### 7. 代码生成

- **文件**：`src/compiler/emitter.ts`
- **功能**：`emitter.ts` 负责将类型检查后的 AST 转换为 JavaScript 代码。


#### 8. 结果输出

- **文件**：`src/tsc/tsc.ts` 和 `src/compiler/sys.ts`
- **功能**：`tsc.ts` 负责输出编译结果，`sys.ts` 负责文件系统的交互，用于写入生成的 JavaScript 文件。

```JavaScript
import * as ts from "../compiler/_namespaces/ts";
import { createProgram } from "../compiler/program";
import { sys } from "../compiler/sys";

export function executeCommandLine(commandLine: ParsedCommandLine): void {
    const program = createProgram(commandLine.fileNames, commandLine.options);
    const emitResult = program.emit();
    sys.writeFile("output.js", emitResult.outputText);
}
```
