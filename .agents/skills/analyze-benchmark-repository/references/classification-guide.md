# Benchmark 分类与证据检查

## 1. 评测层级

| 层级 | 判定条件 | 常见输入输出 | 常见判分 |
|---|---|---|---|
| 静态模型评测 | 单轮或固定多轮生成，不改变外部状态 | 题目/上下文 → 选项、短答案、文本 | Accuracy、Exact Match、LLM Judge |
| 工具增强模型评测 | 允许检索、计算器或代码，但目标仍是回答单题 | 题目 + 工具观察 → 答案 | 最终答案正确率 |
| Agent 组件评测 | 专门测工具选择、记忆、规划或反馈预测 | Schema/历史/状态 → 调用或下一状态 | 调用匹配、状态差异、Rubric |
| 端到端 Agent 评测 | 从用户目标出发，多步行动并改变真实或模拟环境 | 目标 + 环境 → 轨迹 + 最终状态 | Final-state Verifier、任务成功率 |
| Artifact 评测 | 交付完整代码仓、网页、表格或其他可执行产物 | 需求 → Artifact | 测试、渲染、性能、人工/Rubric |
| 人类/元评估 | 研究标注者、监督者、Judge 或校准本身 | 人类判断/反馈 | 一致性、准确率、校准、时间 |

同一仓库可以同时包含多个层级。报告要分别定性，不能取最高层级概括整个 Benchmark。

## 2. 数据消费角色

同一个字段可能存在于数据文件中，却不会进入模型输入。必须按消费方分类：

- **任务输入**：发送给模型或 Agent 的题目与上下文；
- **环境初始化**：开始任务前为工具或模拟环境准备的初始状态；
- **隐藏参考**：被评测对象看不见、只用于判分的答案、测试或目标状态；
- **Judge**：根据输出和隐藏参考判断任务是否成功的评分程序；
- **聚合**：把多道任务的单题结果汇总成最终指标。

| 消费角色 | 用途 | 典型内容 |
|---|---|---|
| 任务输入 | 构造 Prompt、Observation 或用户目标 | 问题、上下文、资源、需求 |
| 环境初始化 | 建立 Agent 的起始世界状态 | 文件、数据库、浏览器状态、账户与工具配置 |
| 隐藏参考 | 对被评测对象不可见 | 标准答案、隐藏测试、目标状态、Rubric |
| Judge 输入 | 判定任务是否成功 | 模型输出、轨迹、最终状态、隐藏参考 |
| 聚合输入 | 把单题结果汇总为最终指标 | 正确性、任务类型、运行次数、成本 |

报告只列后续评测实际消费的字段，并说明一条记录如何转成任务实例，以及每个字段是否对模型、Agent、环境、Judge 可见。“数据中存在”不等于“模型看见”。标注、质检或分析字段若不进入任务、Judge 或最终指标，不在报告中枚举。

## 3. Agent 流程要素

存在多步交互时，按状态循环还原：

```text
Observation → Decision → Action → Tool/Environment Result
      ↑                                      ↓
      └──────────── State / History ─────────┘
```

逐项确认：

- 初始 Observation 从哪些字段和环境状态构造；
- Agent 每轮能做哪些决定，Action Schema 是什么；
- 工具/环境返回什么，是否改变持久状态；
- 哪些历史被保留、截断或摘要；
- 预算、停止条件、超时、拒答和重试；
- 最终提交物是答案、轨迹、Artifact 还是环境状态；
- Judge 检查最终输出、过程还是二者。

若不存在该循环，应明确写为静态或单轮模型评测，不要为了“Agent”叙事虚构规划和工具使用。

## 4. Judge 类型

| Judge | 要确认的内容 | 主要风险 |
|---|---|---|
| Exact Match / 选项匹配 | 规范化、解析失败、拒答计分 | 格式敏感、忽略推理质量 |
| 规则或 Schema | 规则覆盖、边界条件 | Verifier 漏洞 |
| 单元/集成测试 | 隐藏测试、回归测试、环境版本 | 覆盖不足、依赖漂移 |
| Final-state Verifier | 检查哪些状态、是否检查副作用 | “看起来完成”但遗漏质量或安全 |
| 人工评分 | 专家资质、盲测、一致性 | 成本、主观性、样本小 |
| LLM Judge | Judge 版本、Prompt、温度、Rubric | 偏好、漂移、不可复现 |
| 混合 | 各阶段门槛与聚合逻辑 | 一个总分掩盖失败来源 |

## 5. 指标

至少写清分母、聚合方式和失败处理：

- Accuracy、Resolved/Success Rate；
- Macro/Micro Average；
- Pass@k 与 Pass^k；
- Elo/Bradley-Terry；
- Rubric Score；
- Cost、Latency、Token、Tool Calls；
- 置信区间、运行次数和随机种子。

## 6. Agent 能力维度

按证据选择，不机械全部勾选：

- 知识与专业推理；
- 长上下文与记忆；
- 指令遵循与输出控制；
- 规划与任务分解；
- 工具选择与参数生成；
- 环境状态追踪；
- 错误恢复与长时程执行；
- 搜索与证据使用；
- 代码、浏览器、办公或多模态操作；
- Artifact 质量；
- 稳定性、成本、安全和权限控制。

## 7. 证据标签

- **事实**：数据、源码、已保存输出或一手文献直接支持。
- **计算**：由本地数据可重复计算。
- **推断**：从代码结构或多个证据推导，必须明确标注。
- **未知**：证据不足，不猜测。
