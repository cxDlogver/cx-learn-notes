# 讲稿要点

## 开场：0-5 min

今天不讲“AI 帮我写一个按钮”这种局部效率，而是讲前端团队真正落地时会遇到的问题：模型不知道我们的组件库、不知道我们的设计规范，也不知道哪些封装是团队已经沉淀过的。

核心观点：AI 编程的上限，不只取决于模型能力，还取决于团队能不能把上下文工程化。

## 大厂前端 AI 工程化沉淀：5-15 min

可以把前端 AI 工程化拆成三层：

- Prompt：解决当次任务怎么描述。
- Skill：解决稳定流程怎么复用，例如代码评审、需求拆解、设计还原检查。
- MCP：解决模型如何访问外部系统和私有知识，例如组件库、接口文档、设计 token、业务物料。

大厂里真正有价值的不是“每个人都会写提示词”，而是把提示词、上下文、工具和验收沉淀成团队能力。

## 设计还原重难点：15-25 min

设计还原难，不是因为 CSS 难，而是因为设计稿里有大量隐性规则：

- 视觉 token：颜色、字号、间距、圆角。
- 组件约束：按钮有哪些 variant，表单错误态怎么展示。
- 布局语义：哪些是页面区域，哪些是卡片，哪些是工具栏。
- 业务组件：团队已经有沉淀，但模型默认不知道。

所以只把设计稿截图丢给 AI，通常会得到一份“看起来差不多，但工程上不可维护”的代码。

## 最小组件库基建：25-40 min

Demo 里只做四个组件：Button、Input、Card、Modal。

这么做的原因：

- 组件少，便于公开课讲清楚 API 设计。
- 覆盖常见页面的动作、表单、容器、反馈四类基础能力。
- 不引入 Storybook、主题系统、复杂发布流程，避免偏离主线。

讲解重点：

- `@demo/ui` 通过 tsup 输出 ESM、CJS 和类型声明。
- 样式通过 `@demo/ui/styles.css` 明确导入。
- 组件 API 保持窄接口，不为未来想象增加复杂 props。

## 自定义组件库 MCP：40-55 min

MCP Server 暴露三个工具：

- `list_components`：告诉 Codex 有哪些组件。
- `get_component_doc`：告诉 Codex 某个组件怎么用、有哪些 props、有什么约束。
- `search_component_examples`：按场景给示例代码。

现场要强调一点：MCP 不是替代文档，而是把文档变成模型可调用的接口。

## 总结：55-60 min

前端 AI 工程化落地的关键不是让模型变得“更自由”，而是让模型更稳定地使用团队资产。

最终闭环：

- 组件库沉淀标准能力。
- MCP 暴露组件知识。
- Codex 基于 MCP 写代码。
- Review 和测试负责验收。
