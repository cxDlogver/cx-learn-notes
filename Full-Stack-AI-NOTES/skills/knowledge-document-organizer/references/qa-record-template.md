# QA 记录模板只规定必需信息，不预设标准回答的章节

只有用户明确要求记录时，才据此更新 `QA.md` 并在 `QA/` 新建单题文档。以下占位符仅说明需要填写的信息；成稿要用具体陈述句，不能留下占位符。题目原话如需保留，可放在正文，不必强行改写用户原话。

## 1. QA.md 用一条记录连接题目、要点和关联问题

每个问题占一个连续编号的二级标题。题目与回答要点用陈述句，直接表达观点；关联只链接已记录的问题，并写明它们的前置、延伸、对比或分支关系。

```markdown
## <连续编号>. <具体观点的陈述句>

- **回答要点：** <按本题实际内容归纳可复述的观点，并写清重要条件与易漏点>。
- **标准回答：** [完整回答](<./QA/<与标题一致的文件名>.md>)。
- **关联问题：** [另一条已记录的陈述句题目](<./QA/<关联问题文件名>.md>)，<说明关联关系>。
```

没有已记录的关联问题时，可省略“关联问题”一行。出现关联题目后再补双向链接。相关知识体系文档可在要点或标准回答中链接，不强制为每题增加固定字段。

## 2. QA 单题文档按本题的知识结构写成完整回答

单题文档只要求包含陈述句标题、回答要点、完整标准回答和文末参考文献。**正文的章节数、顺序与层级由本题的概念依赖、因果链和场景决定**。二级标题连续编号并写出本节的具体观点；确需三级标题时使用 `### 【具体观点】`。资料链接和引用放在其支持的正文附近，不单设“本地依据”“权威核验”或“关联问题”章节。

```markdown
# <具体观点的陈述句>

**回答要点：**

- <根据本题实际内容列出若干可复述的观点，不规定条数或分类>。

<以下正文按本题的知识关系设置必要章节，逐节解释观点、证据与边界；不套固定小节。>

<在相关论述处链接本地知识文档，并用 [[1]](<已核验的权威来源URL>) 支持外部事实。>

## <连续编号>. 参考文献

[1] <机构或作者>. [<准确题名>](<已核验的权威来源URL>)[EB/OL]. <已核验的日期或版本；没有则省略>。
```

上面的占位符只提示信息位置，**不代表固定的正文大纲**。实际记录要把所有相关本地资料中的有效细节融入论证，再用标准、官方文档或原始论文核对关键事实。相近概念、分支、反例、版本差异和工程场景只在有助于回答本题时展开；若本地资料有偏差，可在相关正文处说明并修正知识文档。

## 3. 记录完成后检查答案与索引一致

- `QA.md` 的题目、要点与单题文档一致；相关问题的链接有效且关系明确。
- 标准回答按本题所需的完整知识体系展开，正文引用与文末参考文献相互对应。
- 只有经用户明确要求记录的问题进入 `QA/`；模板文字不作为真实问题或标准答案写入。
