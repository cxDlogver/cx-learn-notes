# 知识问答与文档维护

本 skill 服务于 `Full-Stack-AI-NOTES`。目标是让回答同时保留本地笔记的细节与权威资料的准确性，并把新增知识接入可查找的知识体系。普通提问可以自动完善知识文档；只有用户明确要求“记录问题”“写入 QA”等，才写 QA 问题文档和 `QA.md`。

## 每次问答

1. 从 [知识体系索引](../../知识体系索引.md) 和 `QA.md` 找到相关主题，再用文件名、标题与正文检索 `Full-Stack-AI-NOTES`。阅读所有与本题实质相关的本地段落、已有 QA 与交叉引用；索引只是入口，不代替原文。必要时继续检索仓库的其他相关资料。排查重复、冲突、遗漏和版本差异。
2. 同时查阅可访问的权威在线资料。优先标准、规范、官方文档、原始论文与官方工程资料；核对具体定义、行为、版本和适用条件。引用直接支持结论的页面，不把本地归纳冒充官方定义。在线核验失败时明确说明未核验的范围，不编造来源或把推测写成定论。
3. 先建立本题的知识框架：前置概念、主流程或因果链、分支与边界、工程场景、常见误区、与已有知识点的关系。回答覆盖用户真正问到的完整体系；复杂题可以拆成多个相互关联的子问题，用户一次问多题时也应处理全部请求。AI 主动出题时从知识依赖、资料缺口或已有 QA 的延伸处选题，避免重复已有题目。回答要有可复述的核心观点和必要细节，避免只给提纲。
4. 在回答中就近链接本地文档和外部来源。指出本地资料哪些内容可沿用、哪些有事实偏差、过时、矛盾或缺口，并给出具体文件和补充建议；没有发现问题也简要说明。区分资料事实、基于资料的分析和工程推论。

## 完善知识文档

- 发现经过核验、与现有主题相关的知识缺口时，可直接补充或修正已有文档；维护原有叙述、示例和有效细节，在合适章节融入新内容，不在末尾机械堆砌。涉及尚有争议或证据不足的结论，先标明不确定性，不作为已核验事实写入。
- 独立的新知识体系在 `Full-Stack-AI-NOTES` 根目录新建 Markdown，与现有知识文档同级。不要为新知识按技术分类再建子目录；`QA/` 只存经用户要求记录的问题，`skills/`、`source/` 与 `assets/` 保持各自用途。无需为了新规范批量改写旧文档。
- 每次新增、重命名或实质更新知识文档，同步维护 [知识体系索引](../../知识体系索引.md) 的主题入口、关联关系与链接。已有主题优先补原文；只有新主题具有独立的概念边界和可持续扩展的框架时才新建文档。
- 新写和实质整理的正文遵循 [文档规范](references/style-guide.md)。仅做局部补充时匹配原文格式，逐步改善结构，不破坏现有阅读路径。引文与参考资料必须真实可追溯。

## 仅在明确要求时记录 QA

- 普通提问、AI 主动提问、回答及知识文档自动完善都不触发 QA 记录。用户明确要求记录时，先检查 `QA.md` 与 `QA/`，避免同题重复。
- `QA/` 中每个问题一个 Markdown 文件。文件名和一级标题以陈述句表达问题所考察的具体观点，不用问号；先列回答要点，再按本题的知识依赖、因果链或场景组织完整标准回答，不固定正文章节。相关本地资料和权威来源在正文就近引用，文末列参考文献。标准回答应覆盖本地资料中的有效细节，以及权威资料揭示的边界、遗漏与更新。多个问题可以共同链接一篇完整知识体系文档，但各有独立 QA 文件。
- 同步更新根目录 `QA.md`：每条记录含陈述句题目、可直接复述的回答要点、指向独立 QA 文件的链接，以及已知相关问题的双向链接。题目、要点和关联说明均使用陈述句，不把疑问句伪装成标题。
- 记录已有回答时以当前可核验资料重新梳理标准回答；保留用户明确要求保留的原话，并标清原话与经核验的修订。

用户明确要求记录时，按 [QA 记录模板](references/qa-record-template.md) 分别填写 `QA.md` 摘要条目和 `QA/` 单题标准回答。模板只规定必需信息，不预设标准回答的小节；将占位符替换为本题的具体陈述句和经核验的内容，不把模板本身当作已记录问题。

## 完成前

确认相关本地资料已阅读、权威来源确实支持关键判断，文档之间的链接有效；新增知识已进入索引，手动记录的 QA 已同时进入独立文件和 `QA.md`。
