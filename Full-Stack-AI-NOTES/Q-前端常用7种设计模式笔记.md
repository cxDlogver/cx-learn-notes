# 前端常用7种设计模式笔记

设计模式是前端开发中解决重复问题的“通用模板”，不直接提供可运行代码，但能指导开发者写出更易维护、可扩展的逻辑。在大型项目（如组件库开发、状态管理、工具函数封装）中，合理运用设计模式可优化代码结构、提升协作效率。本笔记整理前端最常用的7种设计模式，每种模式从核心思想、实际应用场景、完整代码实现三个维度拆解，结合Vue、Axios等常用库举例，附对应知识点问题，助力抽象概念落地到真实开发。

### 工厂模式

#### 核心思想

工厂模式的本质是用一个函数（或类）封装对象的创建逻辑，外界无需关心对象的具体构造细节，只需调用工厂方法即可获取实例。类比工厂生产产品，使用者只需提出需求，工厂直接提供成品，无需关注内部组装过程。

#### 实际应用场景

1. Vue3 的`createApp()`：通过`createApp(App).mount('#app')`创建Vue实例，无需手动`new Vue`，内部封装了实例初始化的全部逻辑，简化开发者使用流程。

2. Axios 的`axios.create()`：基于自定义配置（如`baseURL`、超时时间）创建新的axios实例，可避免全局配置污染，适用于不同接口需要不同请求配置的场景。

3. 组件库中的“弹窗工厂”：批量创建不同类型的弹窗（警告窗、确认窗、输入窗），统一管理弹窗的样式、行为和生命周期，减少重复代码。

#### 完整代码实现：简易Axios工厂

```javascript
// 模拟Axios工厂：根据配置创建请求实例
class AxiosFactory {
  // 静态工厂方法
  static create(config = {}) {
    // 默认配置
    const defaultConfig = {
      baseURL: '',
      timeout: 5000,
      headers: { 'Content-Type': 'application/json' }
    };

    // 合并用户配置与默认配置（用户配置覆盖默认配置）
    const finalConfig = { ...defaultConfig, ...config };

    // 封装请求方法，统一处理请求逻辑
    const request = async (options) => {
      const { url, method = 'GET', data = {} } = options;
      try {
        const response = await fetch(`${finalConfig.baseURL}${url}`, {
          method,
          headers: finalConfig.headers,
          timeout: finalConfig.timeout,
          body: method === 'POST' ? JSON.stringify(data) : null
        });
        return await response.json();
      } catch (err) {
        console.error('请求失败：', err);
        throw err; // 抛出错误，供调用者处理
      }
    };

    // 返回封装后的请求实例，提供get、post便捷方法
    return {
      get: (url, params) => request({ url, params }),
      post: (url, data) => request({ url, method: 'POST', data })
    };
  }
}

// 使用工厂创建不同接口的请求实例
const userApi = AxiosFactory.create({ baseURL: 'https://api.user.com' });
const orderApi = AxiosFactory.create({ baseURL: 'https://api.order.com', timeout: 10000 });

// 调用实例方法（无需关心内部请求实现细节）
userApi.get('/info');
orderApi.post('/create', { goodsId: 123 });
```

### 单例模式

#### 核心思想

单例模式要求一个类在整个系统中只能有一个实例，且提供一个全局访问点。确保无论在何处访问，拿到的都是同一个对象，避免重复创建实例造成的资源浪费，同时保证实例状态的统一性。

#### 实际应用场景

1. 全局状态管理（Vuex/Pinia）：整个应用只有一个Store实例，确保所有组件访问的是同一套状态，避免状态混乱。

2. 弹窗组件（如Vant的Toast、Notify）：多次调用`Toast('提示')`，不会创建多个弹窗DOM，而是复用同一个弹窗并更新内容，提升性能和用户体验。

3. 全局事件总线（EventBus）：整个应用只创建一个事件总线实例，避免创建多个总线导致事件监听混乱、内存泄漏。

#### 完整代码实现：ES6私有属性实现单例

```javascript
class Singleton {
  // 1. 用私有属性（#开头）存储唯一实例，外部无法直接访问，确保实例的唯一性
  static #instance;

  // 2. 私有构造函数：防止外部通过new关键字创建实例，严格限制单例
  constructor() {
    // 若已有实例，直接抛出错误，避免重复创建
    if (Singleton.#instance) {
      throw new Error('单例模式不允许重复创建实例，请通过getInstance()获取');
    }
  }

  // 3. 静态方法：提供全局访问点，确保只创建一个实例
  static getInstance() {
    // 首次调用时创建实例，后续调用直接返回已存在的实例
    if (!Singleton.#instance) {
      Singleton.#instance = new Singleton();
    }
    return Singleton.#instance;
  }

  // 示例：单例的业务方法（模拟实际开发中的业务逻辑）
  doSomething() {
    console.log('单例实例的业务逻辑，全局唯一调用');
  }
}

// 测试：多次调用获取的是同一个实例
const instance1 = Singleton.getInstance();
const instance2 = Singleton.getInstance();
console.log(instance1 === instance2); // true（验证实例唯一性）

// 错误用法：外部无法通过new创建实例，会抛出错误
// const instance3 = new Singleton(); // 抛出错误：单例模式不允许重复创建实例，请通过getInstance()获取
```

### 观察者模式

#### 核心思想

观察者模式定义了对象间的一对多依赖关系：当“目标对象”的状态发生改变时，所有依赖它的“观察者对象”会自动收到通知并执行相应的更新操作。类比订阅报纸，订阅者（观察者）订阅报纸（目标）后，报纸更新时所有订阅者都会收到新报纸。

#### 实际应用场景

1. Vue的响应式原理：数据（目标对象）发生变化时，依赖该数据的DOM元素（观察者）会自动更新，实现“数据驱动视图”。

2. 事件监听（如`addEventListener`）：DOM元素（目标对象）触发`click`、`input`等事件时，所有绑定在该事件上的回调函数（观察者）会依次执行。

3. 组件库的自定义事件：父组件监听子组件的`@change`、`@click`等自定义事件，子组件（目标）触发事件时，父组件（观察者）会收到通知并执行对应逻辑。

#### 完整代码实现：简易EventBus（观察者模式实践）

```javascript
class EventBus {
  // 私有属性：存储事件与对应的观察者（回调函数），结构：{ 事件名: [callback1, callback2, ...] }
  #handlers = {};

  // 1. 订阅事件：为指定事件添加观察者（回调函数）
  $on(eventName, callback) {
    // 校验回调函数类型，确保是可执行函数
    if (typeof callback !== 'function') {
      throw new Error('回调函数必须是function类型');
    }
    // 若事件不存在，初始化空数组存储回调函数
    if (!this.#handlers[eventName]) {
      this.#handlers[eventName] = [];
    }
    // 将回调函数添加到该事件的观察者列表中
    this.#handlers[eventName].push(callback);
  }

  // 2. 触发事件：通知该事件的所有观察者（执行所有回调函数）
  $emit(eventName, ...args) {
    // 若事件无订阅者，直接返回，避免无效执行
    const callbacks = this.#handlers[eventName] || [];
    // 执行所有回调函数，并传递触发时的参数
    callbacks.forEach(callback => callback(...args));
  }

  // 3. 取消订阅：移除指定事件的所有观察者，或清空所有事件的观察者
  $off(eventName) {
    if (eventName) {
      // 移除指定事件的所有订阅者（清空该事件的回调列表）
      this.#handlers[eventName] = [];
    } else {
      // 若未传事件名，清空所有事件的订阅者，重置事件总线
      this.#handlers = {};
    }
  }

  // 4. 一次性订阅：触发一次事件后，自动取消该订阅，避免重复执行
  $once(eventName, callback) {
    // 封装回调函数：执行原回调后，立即取消该事件的订阅
    const wrapper = (...args) => {
      callback(...args); // 执行原回调函数
      this.$off(eventName); // 取消当前事件的订阅
    };
    // 订阅封装后的回调函数
    this.$on(eventName, wrapper);
  }
}

// 使用示例：模拟组件间通信
const bus = new EventBus();

// 订阅事件（观察者1）
bus.$on('userLogin', (username) => {
  console.log(`欢迎 ${username} 登录`);
});

// 一次性订阅事件（观察者2）
bus.$once('showTip', (msg) => {
  console.log('提示：', msg);
});

// 触发事件（目标对象状态变化，通知观察者）
bus.$emit('userLogin', '张三'); // 输出：欢迎 张三 登录
bus.$emit('showTip', '请完善个人资料'); // 输出：提示：请完善个人资料
bus.$emit('showTip', '再次触发'); // 无输出（已取消一次性订阅）

// 取消订阅
bus.$off('userLogin');
bus.$emit('userLogin', '李四'); // 无输出（已取消订阅）
```

### 发布订阅模式

#### 核心思想

发布订阅模式是观察者模式的“升级版”，它通过一个“事件中心”作为中间件，让发布者和订阅者完全解耦。发布者无需知道谁在订阅自己，订阅者也无需知道谁在发布事件，两者均通过事件中心进行通信，发布者向事件中心发布事件，订阅者向事件中心订阅事件，由事件中心统一转发通知。

与观察者模式的核心区别：观察者模式中，目标对象与观察者直接依赖，目标需直接维护观察者列表并通知；发布订阅模式中，发布者和订阅者无直接依赖，通过事件中心间接通信，耦合度更低，更适合复杂系统。

#### 实际应用场景

1. 跨组件通信（如Vue的EventBus、React的Context）：组件间不直接引用，通过事件中心传递消息，降低组件间耦合，适用于多层嵌套、非父子组件的通信场景。

2. 状态管理库（如Redux）：Action（发布者）触发后，Store（事件中心）接收并通知Reducer更新状态，组件（订阅者）订阅状态变化，感知状态更新后重新渲染。

3. 浏览器的`CustomEvent`：自定义事件通过`dispatchEvent`发布，`addEventListener`订阅，浏览器作为事件中心，负责转发事件通知。

#### 完整代码实现：简易发布订阅模式（事件中心）

```javascript
// 事件中心：作为发布者和订阅者的中间件，解耦两者
class EventCenter {
  // 私有属性：存储事件与对应的订阅者（回调函数）
  #eventMap = {};

  // 1. 订阅事件：订阅者向事件中心订阅指定事件
  subscribe(eventName, callback) {
    if (typeof callback !== 'function') {
      throw new Error('回调函数必须是function类型');
    }
    // 若事件不存在，初始化空数组存储订阅者回调
    if (!this.#eventMap[eventName]) {
      this.#eventMap[eventName] = [];
    }
    // 添加订阅者回调
    this.#eventMap[eventName].push(callback);
  }

  // 2. 发布事件：发布者向事件中心发布指定事件，并传递参数
  publish(eventName, ...args) {
    // 若事件无订阅者，直接返回
    const callbacks = this.#eventMap[eventName] || [];
    // 事件中心转发通知，执行所有订阅者回调
    callbacks.forEach(callback => callback(...args));
  }

  // 3. 取消订阅：订阅者取消对指定事件的订阅
  unsubscribe(eventName, callback) {
    // 若未传事件名，清空所有订阅
    if (!eventName) {
      this.#eventMap = {};
      return;
    }
    const callbacks = this.#eventMap[eventName] || [];
    // 若传了回调，只移除指定回调；否则移除该事件所有订阅者
    if (callback) {
      this.#eventMap[eventName] = callbacks.filter(cb => cb !== callback);
    } else {
      this.#eventMap[eventName] = [];
    }
  }
}

// 使用示例：模拟跨模块通信
const eventCenter = new EventCenter();

// 模块A（订阅者）：订阅userChange事件
const moduleA = {
  init() {
    eventCenter.subscribe('userChange', (userInfo) => {
      console.log('模块A收到用户信息更新：', userInfo);
    });
  }
};

// 模块B（订阅者）：订阅userChange事件
const moduleB = {
  init() {
    eventCenter.subscribe('userChange', (userInfo) => {
      console.log('模块B收到用户信息更新：', userInfo);
    });
  }
};

// 模块C（发布者）：发布userChange事件
const moduleC = {
  updateUser(userInfo) {
    // 发布事件，无需知道哪些模块订阅
    eventCenter.publish('userChange', userInfo);
  }
};

// 初始化订阅者
moduleA.init();
moduleB.init();

// 发布事件
moduleC.updateUser({ id: 1, name: '张三' });
// 输出：
// 模块A收到用户信息更新： { id: 1, name: '张三' }
// 模块B收到用户信息更新： { id: 1, name: '张三' }
```

### 原型模式

#### 核心思想

原型模式是基于已有对象（原型）创建新对象，新对象会继承原型的属性和方法，无需重复定义相似对象的属性和方法，减少代码冗余。类比工厂生产玩具，先制作一个“原型玩具”，后续所有玩具都复制原型的样式，再根据需求微调细节，提高生产效率。

在JavaScript中，原型模式是语言的核心特性：每个对象都有`__proto__`属性，指向它的原型对象，原型链就是基于这一机制实现的，通过原型链，对象可以继承原型对象的属性和方法。

#### 实际应用场景

1. `Object.create()`方法：以指定对象为原型，创建新对象，如`const obj = Object.create(prototypeObj)`，新对象会继承`prototypeObj`的所有属性和方法。

2. Vue2的数组方法重写：Vue2为数组的`push`、`pop`、`shift`等方法添加响应式逻辑，新创建的数组会继承这些重写后的方法，确保数组操作能触发视图更新。

3. 组件复用：Vue的组件实例会继承组件选项（如`data`、`methods`、`computed`），本质是原型继承，无需为每个组件实例重复定义组件选项。

#### 完整代码实现：基于原型的对象创建

```javascript
// 1. 定义原型对象（被复制的模板，存储公共属性和方法）
const userPrototype = {
  // 原型方法：所有基于该原型创建的对象都能继承
  greet() {
    console.log(`Hello, 我是 ${this.name}，年龄 ${this.age}`);
  },
  // 原型属性：公共属性，所有实例共享
  role: 'user',
  isActive: true
};

// 2. 基于原型创建新对象（方式1：使用Object.create，推荐）
const user1 = Object.create(userPrototype);
// 为新对象添加自身独有的属性（不影响原型对象）
user1.name = '张三';
user1.age = 20;
user1.greet(); // 输出：Hello, 我是 张三，年龄 20
console.log(user1.role); // 输出：user（继承自原型）
console.log(user1.isActive); // 输出：true（继承自原型）

// 3. 基于原型创建新对象（方式2：手动实现原型链，理解原型继承本质）
function createUser(name, age) {
  const user = {};
  // 设置新对象的原型，让其继承userPrototype
  Object.setPrototypeOf(user, userPrototype);
  // 为新对象添加自身独有的属性
  user.name = name;
  user.age = age;
  return user;
}

const user2 = createUser('李四', 22);
user2.greet(); // 输出：Hello, 我是 李四，年龄 22
console.log(user2.__proto__ === userPrototype); // true（验证原型链关系）
console.log(user2.role); // 输出：user（继承自原型）

// 4. 修改原型对象的属性，所有继承该原型的实例都会受到影响
userPrototype.isActive = false;
console.log(user1.isActive); // 输出：false
console.log(user2.isActive); // 输出：false
```

### 代理模式

#### 核心思想

代理模式为一个对象提供“代理”对象，外界通过代理对象访问原对象，代理对象可以在访问原对象的前后添加额外逻辑（如缓存、权限校验、日志记录、性能监控等），既不改变原对象的功能，又能扩展原对象的行为。类比找房产中介（代理）租房，中介会帮你筛选房源、谈判价格，你无需直接和房东（原对象）打交道，中介就是房东的代理。

#### 实际应用场景

1. 缓存代理：第一次请求数据后缓存结果，重复请求时直接返回缓存，减少网络请求次数，提升页面性能（如城市查询、商品列表查询）。

2. 权限代理：控制敏感操作的访问权限，如未登录用户无法调用“提交订单”“修改个人信息”等接口，代理对象会拦截请求并提示登录。

3. Vue3的响应式代理：通过`Proxy`代理对象，拦截属性的读取、修改操作，实现响应式更新，当属性变化时自动触发视图更新。

4. 日志代理：记录函数的调用参数、返回值、调用时间，方便调试和问题排查，无需修改原函数逻辑。

#### 完整代码实现：缓存代理（API请求优化）

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>缓存代理：API请求优化</title>
</head>
<body>
  <h1>城市查询（缓存代理演示）</h1>
  <input type="text" class="query-input" placeholder="输入省份名查询城市（如：广东省）">
  <script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
  <script>
    // 1. 定义缓存对象：存储已查询的省份对应的城市列表，避免重复请求
    const cache = {};

    // 2. 代理函数：封装API请求，添加缓存逻辑（代理原API请求）
```

### 迭代器模式

#### 核心思想

迭代器模式提供一种统一的遍历接口，让外界可以不关心数据结构的内部实现（如数组、对象、Set、Map、链表等），用相同的方式遍历不同类型的数据结构。类比旅游向导（迭代器）带你游览不同景点（数据结构），你不用知道景点的路线和内部布局，只需跟着向导走，就能遍历所有景点。

在JavaScript中，迭代器模式通过“迭代协议”实现：

1. 可迭代协议：对象必须有`[Symbol.iterator]`方法，该方法返回一个迭代器对象。

2. 迭代器协议：迭代器对象必须有`next()`方法，每次调用`next()`会返回一个包含`done`和`value`的对象，`done`表示是否遍历结束（`true`为结束），`value`表示当前遍历到的值。

#### 实际应用场景

1. `for...of`循环：统一遍历数组、Set、Map、字符串等可迭代对象，无需关心不同数据结构的遍历方式差异。

2. 数组的`forEach`方法：抽象遍历逻辑，用户只需关注每个元素的处理逻辑，无需手动管理遍历索引。

3. 自定义数据结构遍历：如链表、树结构等自定义数据结构，通过实现迭代器协议，实现统一的遍历方式，方便开发者使用。

4. 异步迭代：如`for await...of`，遍历异步数据（如异步请求列表），实现异步数据的统一遍历。

#### 完整代码实现：自定义对象迭代器

```javascript
// 定义一个自定义数据结构（包含数组属性，模拟复杂数据结构）
const customCollection = {
  items: ['前端', 'Java', 'Python', 'UI/UX'], // 待遍历的数据
  length: 4,

  // 1. 实现可迭代协议：添加[Symbol.iterator]方法，返回迭代器对象
  [Symbol.iterator]() {
    let index = 0; // 遍历索引，记录当前遍历位置
    const items = this.items; // 保存this指向，避免闭包中this丢失

    // 2. 实现迭代器协议：返回带有next()方法的迭代器对象
    return {
      next() {
        // 遍历未结束：返回当前值和done=false
        if (index < items.length) {
          return {
            done: false,
            value: items[index++] // 返回当前值后，索引自增，准备下一次遍历
          };
        }
        // 遍历结束：返回done=true，value可选（一般省略）
        return { done: true };
      }
    };
  }

  // 可选：用Generator函数简化迭代器实现（更简洁，自动管理索引）
  // [Symbol.iterator]() {
  //   function* generator() {
  //     for (const item of this.items) {
  //       yield item; // 每次yield返回一个值，自动管理遍历状态
  //     }
  //   }
  //   return generator.call(this);
  // }
};

// 3. 用统一方式遍历自定义数据结构（for...of循环，符合迭代器协议）
for (const item of customCollection) {
  console.log('遍历结果：', item); // 依次输出：前端、Java、Python、UI/UX
}

// 4. 手动调用迭代器（验证迭代器协议的实现）
const iterator = customCollection[Symbol.iterator]();
console.log(iterator.next()); // { done: false, value: '前端' }
console.log(iterator.next()); // { done: false, value: 'Java' }
console.log(iterator.next()); // { done: false, value: 'Python' }
console.log(iterator.next()); // { done: false, value: 'UI/UX' }
console.log(iterator.next()); // { done: true }

// 5. 验证：自定义数据结构可被扩展运算符遍历（扩展运算符支持可迭代对象）
const arr = [...customCollection];
console.log(arr); // 输出：['前端', 'Java', 'Python', 'UI/UX']
```

### 总结

设计模式不是“银弹”，而是解决前端开发问题的“工具箱”，无需刻意追求“用满所有模式”，应根据实际场景选择合适的模式，核心是优化代码结构、降低耦合、提升可维护性和可扩展性。

核心场景匹配：

- 需批量创建相似对象 → 工厂模式

- 需全局唯一实例 → 单例模式

- 需实现事件通知、依赖更新 → 观察者/发布订阅模式

- 需复用对象属性和方法 → 原型模式

- 需控制对象访问、扩展行为 → 代理模式

- 需统一遍历不同数据结构 → 迭代器模式
