## Vue 和 React的核心区别是什么？

> Vue 和 React 的核心区别主要在**定位和设计理念**上。
>
> **Vue 更偏向一个完整框架**，官方提供了比较完善的解决方案，比如路由、状态管理等，上手成本低、开发规范统一，比较适合快速开发和团队协作。
>
> **React 更偏向一个视图库**，主要负责 UI 渲染，其它能力需要开发者自行选择和组合，灵活性更高，但对工程能力要求也更高。
>
> 从使用感受上看，Vue 对初学者更友好，React 更适合大型、长期维护的复杂项目。

## 面试题：介绍一下 Vue 的生命周期

**口述回答模板：**

Vue 的生命周期指的是：**一个组件从创建、挂载、更新到销毁的完整过程**。
 Vue 在这个过程中，在关键阶段暴露了一系列生命周期钩子，让开发者可以在合适的时机执行逻辑，比如初始化数据、发起请求、操作 DOM、清理副作用等。

从整体上看，Vue 的生命周期可以分为四个阶段：**创建、挂载、更新和销毁**。

------

在**创建阶段**，组件实例刚被创建，但 DOM 还没有生成。
 这个阶段的特点是：**数据已经初始化，但还不能访问真实 DOM**。
 通常在这里做一些与 DOM 无关的初始化工作，比如初始化数据结构、读取本地缓存、设置定时器配置等。

------

接下来是**挂载阶段**。
 在这个阶段，Vue 会把模板编译成真实 DOM，并挂载到页面中。
 当组件真正挂载完成后，就可以安全地访问和操作 DOM 了。
 因此，涉及 DOM 读取、第三方库初始化、依赖页面结构的逻辑，通常都放在挂载完成之后执行。

------

第三个阶段是**更新阶段**。
 当组件的响应式数据发生变化时，Vue 会触发重新渲染流程。
 在更新前和更新后，Vue 都提供了对应的生命周期钩子，让我们可以在数据变化前后做一些处理，比如对比新旧数据、在更新后获取最新的 DOM 状态等。

需要注意的是，这个阶段可能会被多次触发，因此不适合在这里做高成本或一次性的逻辑。

------

最后是**销毁阶段**。
 当组件从页面中被移除时，会进入销毁流程。
 在这个阶段，Vue 会解绑事件、停止响应式追踪，并释放资源。
 开发者需要在这里手动清理一些副作用，比如定时器、全局事件监听、订阅关系等，防止内存泄漏。

## 响应式原理

### 二、面试题一：什么是 Vue 的响应式原理？

**口述回答模板：**

Vue 的响应式原理指的是：**当数据层的状态发生变化时，框架能够自动感知这个变化，并驱动视图层进行更新，而不需要开发者手动操作 DOM**。

从整体模型来看，它体现的是一种数据驱动视图的思想，也就是 Model 变化 → View 自动更新。
 Vue 在中间做的事情，是建立数据和视图之间的依赖关系，并在数据变化时，精准通知相关视图进行更新。

------

### 三、面试题二：Vue 响应式的核心思想是什么？

**口述回答模板：**

Vue 响应式的核心思想可以概括为两点：**数据劫持 + 依赖收集与派发更新**。

数据劫持负责“感知变化”，也就是在数据被读取或修改时能够被拦截；
 依赖收集和派发更新负责“通知变化”，也就是知道哪些地方用到了这个数据，并在数据变化时通知它们重新执行。

这套机制保证了 Vue 能做到**精确更新，而不是全量刷新视图**。

------

### 四、面试题三：Vue 2 的响应式原理是如何实现的？

**口述回答模板：**

在 Vue 2 中，响应式是通过 `Object.defineProperty` 来实现的。

Vue 会在初始化阶段，遍历 data 中的每一个属性，为它们定义 getter 和 setter。
 当属性被读取时，会触发 getter，在 getter 中完成**依赖收集**，把当前使用这个数据的 Watcher 记录下来；
 当属性被修改时，会触发 setter，在 setter 中进行**派发更新**，通知所有依赖这个数据的 Watcher 重新执行，从而触发视图更新。

在渲染过程中，模板中用到的数据都会触发 getter，因此 Vue 能自动建立“数据 → Watcher → 视图”的依赖关系。

------

### 五、面试题四：Vue 2 响应式有什么缺陷？为什么？

**口述回答模板：**

Vue 2 响应式的缺陷，根源在于 `Object.defineProperty` 的能力限制。

首先，它只能拦截**已经存在的属性**，如果后续给对象新增或删除属性，是无法触发 getter 和 setter 的；
 其次，对于数组，它无法拦截通过索引直接赋值的行为，比如 `arr[0] = xxx`，因为这相当于新增属性。

因此在 Vue 2 中，需要通过特定 API，比如 `$set`，或者通过数组变异方法，来保证响应式更新。

------

### 六、面试题五：Vue 3 的响应式原理和 Vue 2 有什么不同？

**口述回答模板：**

Vue 3 在思想上和 Vue 2 是一致的，仍然是**数据劫持 + 依赖收集 + 派发更新**，但底层实现发生了变化。

Vue 3 使用的是 `Proxy` 和 `Reflect`，通过代理整个对象来拦截操作。
 由于 Proxy 是基于对象本身进行代理的，它可以天然拦截属性的读取、修改、新增和删除操作，因此彻底解决了 Vue 2 中新增属性和数组索引不响应的问题。

------

### 七、面试题六：Vue 3 的 Proxy 是深度代理吗？

**口述回答模板：**

Vue 3 采用的是**懒代理机制**，而不是一次性递归代理所有嵌套对象。

也就是说，只有当访问某个嵌套对象时，Vue 才会在那一刻对它进行 Proxy 包装。
 这种设计可以显著减少初始化阶段的性能开销，同时保证访问到的对象一定是响应式的。

## Vue模板解析的过程

### 面试题一：Vue 的模板渲染是什么？解决了什么问题？

**口述回答模板：**

Vue 的模板渲染指的是：**将模板语法描述的结构，转换成真实 DOM，并在数据变化时自动更新视图的过程**。
 它的核心目标是让开发者用一种更接近 HTML 的方式来描述界面结构，而不需要手动操作 DOM。

模板本身并不是浏览器能直接执行的代码，Vue 会在内部把模板解析、编译成渲染函数，再由渲染函数生成虚拟 DOM，最终映射为真实 DOM。
 这种方式既保留了声明式开发的可读性，又通过虚拟 DOM 实现了高效更新。

------

### 面试题二：Vue 模板是如何被渲染成页面的？完整流程是怎样的？

**口述回答模板：**

Vue 模板渲染大致可以分为四个步骤。

首先是**模板编译**。
 Vue 会把 template 解析成抽象语法树，也就是 AST，然后将 AST 转换成渲染函数。

第二步是**执行渲染函数生成虚拟 DOM**。
 渲染函数在执行时，会读取响应式数据，这个过程中会触发依赖收集。

第三步是**虚拟 DOM 渲染成真实 DOM**。
 Vue 会把虚拟 DOM 转换成真实 DOM，并挂载到页面上。

最后是**数据变化驱动更新**。
 当响应式数据发生变化时，对应的渲染函数会重新执行，生成新的虚拟 DOM，再通过 Diff 算法最小化更新真实 DOM。

------

### 面试题三：Vue 模板和 render 函数有什么关系？

**口述回答模板：**

Vue 的模板本质上只是 render 函数的一种语法糖。
 不管使用 template 还是 JSX，最终都会被转换成 render 函数来执行。

render 函数是 Vue 渲染系统的最底层接口，它直接返回虚拟 DOM。
 模板的优势在于可读性强、接近 HTML，更适合大多数业务场景；
 render 函数则更灵活，适合高度动态或抽象组件的场景。

所以可以理解为：**Vue 实际只认识 render 函数，模板只是开发阶段的便利写法**。

------

### 面试题四：Vue 模板中数据是如何和视图建立关系的？

**口述回答模板：**

模板中的数据绑定，在渲染阶段会被转换成对响应式数据的访问。
 当渲染函数执行时，只要读取了某个响应式属性，就会触发 getter，从而完成依赖收集。

也就是说，Vue 会自动记录：
 “当前这个渲染函数，依赖了哪些数据”。

当这些数据发生变化时，Vue 就能精准地知道哪些渲染函数需要重新执行，从而更新对应的视图，而不是整个页面重渲染。

------

### 面试题五：为什么 Vue 需要虚拟 DOM？直接操作 DOM 不行吗？

**口述回答模板：**

直接操作 DOM 在复杂应用中成本很高，因为 DOM 操作本身是昂贵的，而且很难精准控制最小更新范围。

Vue 使用虚拟 DOM 的目的不是“更快地生成 DOM”，而是**更可控地更新 DOM**。
 通过虚拟 DOM，Vue 可以先在内存中计算新旧节点的差异，再把最小必要的修改同步到真实 DOM 上。

因此虚拟 DOM 的核心价值在于：
 **用 JavaScript 计算的确定性，换取 DOM 操作的最小化**。

------

### 面试题六：Vue 的模板更新是同步还是异步的？为什么？

**口述回答模板：**

Vue 的模板更新是**异步的**。
 当响应式数据发生变化时，Vue 不会立刻更新 DOM，而是把更新任务放入一个队列中，在同一事件循环内进行合并处理。

这样做的好处是：
 如果在同一个事件循环中多次修改数据，Vue 只会触发一次渲染，从而避免不必要的重复更新，提高性能。

如果开发者需要在 DOM 更新完成后再执行逻辑，可以使用 nextTick 来获取更新后的 DOM 状态。

------

### 面试题七：模板中常见的指令在渲染时起什么作用？

**口述回答模板：**

模板指令本质上是对渲染逻辑的声明式描述。
 比如条件渲染、列表渲染、事件绑定等，都会在编译阶段被转换成渲染函数中的控制逻辑。

这些指令不会在运行时动态解析字符串，而是在编译阶段就被固化进 render 函数中，因此运行时的性能开销是可控的。

### 面试题：Vue 中 key 的作用是什么？为什么 v-for 一定要加 key？

**口述回答模板：**

在 Vue 中，key 的核心作用是：**帮助虚拟 DOM 在 Diff 过程中准确识别节点身份，从而做出正确、最小成本的更新**。

在模板更新时，Vue 会生成新的虚拟 DOM，并与旧的虚拟 DOM 进行 Diff 对比。
 如果没有 key，或者 key 不稳定，Vue 默认会采用“**就地复用**”的策略，也就是按照索引顺序去复用已有节点。

这种策略在简单场景下是成立的，但在**列表发生插入、删除、重排**时，会导致节点身份混乱，从而产生错误的 DOM 复用，比如输入框内容错位、组件状态错乱等问题。

### 【*】面试题：`nexttick`的原理

1. 我修改响应式数据后，Vue 不会立即更新 DOM，而是把组件更新任务放进更新队列，目的是把同一轮里的多次变更合并起来。
2. 第一次有更新任务入队时，Vue 会用 Promise 安排一个微任务，在微任务里触发 flushJobs。
3. 当当前同步代码执行完、调用栈清空后，事件循环开始执行微任务，进入 flush 阶段。
4. flush 阶段里，Vue 先把更新队列里的组件更新任务依次执行，完成 render、diff，并最终 patch DOM。
5. DOM patch 完成后，Vue 再执行 post-flush 队列，也就是 nextTick 注册的回调。
6. 因此 nextTick 能严格保证回调发生在 DOM 更新之后，而不是数据刚改完的同步阶段。
