# 知识体系索引把现有资料连接成可检索的学习路径

本索引是 `Full-Stack-AI-NOTES` 的主知识地图。它组织主题入口、前置关系、主文档、延伸资料以及与源码和附件之间的关联；Skill 和 QA 都应从这里读取知识体系，而不是分别维护一套互相冲突的分类。

索引只负责“定位知识”，不替代具体知识正文。回答具体问题时仍需读取相关 Markdown 全文，并结合权威在线资料核验事实与版本。

## 1. 知识读取遵循索引、正文、证据的顺序

| 场景     | 推荐读取顺序                                                                            |
| -------- | --------------------------------------------------------------------------------------- |
| 系统学习 | `README.md` → `知识体系索引.md` → 主题正文 → `source/` / `resource/`                    |
| 技术问答 | `知识体系索引.md` → `QA.md` → 相关知识正文 → 实现 / 附件 → 外部权威资料                 |
| 知识整理 | `skills/knowledge-document-organizer/SKILL.md` → 本索引 → 目标正文与相邻主题 → 样式规范 |
| 实现验证 | 对应知识正文 → `source/` → 测试和官方 API                                               |
| 附件查阅 | 对应知识正文或本索引 → `resource/`，必要时把长期知识提炼回 Markdown                     |

**知识体系索引是入口，不是摘要数据库。** 找到文档后必须继续阅读原文；需要判断实现时读取 `source/`，需要原始附件时读取 `resource/`。

## 5. 新知识通过关联关系进入现有体系

新增或实质更新知识文档时，在对应主题下加入链接，并检查它依赖哪些旧概念、延伸哪些旧结论、与哪些文档构成对比或冲突。一个问题涉及多条路径时，在回答和文档正文中交叉链接，而不复制整篇内容。

**知识体系索引只允许直接链接 `Full-Stack-AI-NOTES` 目录内部的知识正文、`source/`、`resource/`、`assets/`、Skill 和 QA。不得从本索引直接链接到仓库其他项目目录中的实现文档。**

如果某个知识点需要关联本目录之外的项目实践，按照下面的边界处理：

```text
知识体系索引
    ↓
Full-Stack-AI-NOTES 内部通用知识正文
    ↓
正文中的“项目实践入口”
    ↓
其他项目目录中的具体实现文档
```

通用知识正文必须先脱离具体项目上下文完成定义、框架、机制、边界和通用示例；项目目录只承担真实实现、配置、代码、取舍和验证。已经存在完整项目文档时，通用知识正文优先链接该项目文档，不复制同一套项目目录、配置和实现细节。

独立的新知识文档放在本目录根部；文档图片统一进入 `assets/`；独立代码和 Demo 进入 `source/`；PDF、导出资料等非代码附件进入 `resource/`。任何移动都要同步修正正文链接和本索引。

仅在明确要求记录问题时，才将单题标准回答写入 `QA/` 并同步更新 [QA](./QA.md)。普通问答只读取 QA，不自动产生记录。

本目录之外的课程、源码和项目材料可作为补充证据、实践映射和实现资料按主题检索，但它们不能直接成为本知识体系索引的导航节点。
