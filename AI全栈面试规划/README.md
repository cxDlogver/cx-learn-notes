# AI 全栈开发面试规划

本目录是 2026-09-20 前 AI 全栈开发面试准备工作的唯一进度入口。候选人定位是：**以前端工程能力为长板，能够完成 AI 应用、Agent Runtime 与关键服务端能力的端到端设计和实现。**

规划总投入为 60 小时。9 月 20 日是第一阶段可面试检查点，不是学习终点；第一阶段优先形成能回答、能演示、能经受追问的最小闭环，不追求覆盖所有后端或 AI 基础设施主题。

## 1. 文档职责

- [01-目标规范.md](./01-目标规范.md)：稳定的目标、范围、优先级、时间预算和最终验收标准。
- [02-能力矩阵与验收标准.md](./02-能力矩阵与验收标准.md)：把“掌握”拆成可以观察的证据，并记录各能力的目标等级。
- [03-进度台账.md](./03-进度台账.md)：每天更新的当前状态、证据、薄弱点、复习队列和剩余时间。
- [04-每日复盘与自动提交规范.md](./04-每日复盘与自动提交规范.md)：每天 08:00 自动任务的输入、判断、提交、推送和异常处理规则。
- [05-Demo组合规范.md](./05-Demo组合规范.md)：持续演进的个人知识库 Agent 与动态微型 Demo 的边界和验收场景。
- [每日复盘](./每日复盘/README.md)：按日期保存学习事实、验证结果和下一步建议。
- [demos](./demos/README.md)：主 Demo 与微型 Demo 的统一入口；个人知识库 Agent 已进入架构契约切片。

## 2. 执行原则

学习闭环统一为：现有证据盘点 → 脱稿回答或编码测试 → 暴露缺口 → 定向学习 → Demo 验证 → 间隔复习 → 面试追问。

**<u>文件存在只能证明内容被沉淀过，不能直接证明已经掌握。</u>** 已有知识文档初始最多记为 S1；只有通过解释、代码、运行结果和追问验证，才能升级。

本目录不预先维护僵化的逐日计划。每日任务根据剩余时间、未提交改动、最近验证结果、复习间隔和主 Demo 阻塞点，实时选择下一项工作。

## 3. 更新边界

目标范围或面试定位发生变化时，先修改目标规范，再调整能力矩阵。普通学习进度只更新进度台账和当日复盘，不随意改变目标定义。

主 Demo 固定为个人知识库 Agent；微型 Demo 的主题由复习结果决定。一个微型 Demo 的能力经过验证并适合主链路时，再合并进主 Demo。
