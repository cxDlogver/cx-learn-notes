# AI 全栈面试能力矩阵与验收标准

## 1. 掌握等级

| 等级 | 含义 | 必须存在的证据 |
| --- | --- | --- |
| S0 未覆盖 | 没有形成可靠认知 | 无，或只能说出名词 |
| S1 已沉淀 | 已阅读并形成笔记或代码材料 | 可定位资料；尚未通过脱稿验证 |
| S2 可解释 | 能用自己的话说明边界、流程、场景和反例 | 脱稿回答记录；至少一轮追问 |
| S3 可实现 | 能独立写出最小实现并验证成功与失败路径 | 可运行代码、测试或查询结果 |
| S4 可演示抗追问 | 能放入完整项目，解释取舍、指标、风险和生产化边界 | 主 Demo、故障注入、安全用例、两轮以上追问 |

状态升级必须引用证据路径和日期。遗忘、解释错误或代码无法运行时允许降级；降级不是失败，而是触发复习的信号。

## 3. 验收方法

### 【口述验证】

随机抽题后不看资料作答：先给一句话结论，再用流程或项目展开，最后说明限制和取舍。核心题至少接受两轮追问；如果只能复述定义，不高于 S1。

### 【代码验证】

每个 P0 服务端或 Runtime 机制至少有一个可执行入口和一个失败用例。测试必须断言状态变化、持久化结果或外部副作用，不能只断言 HTTP 200。

### 【演示验证】

主 Demo 从空白数据开始完成一条真实链路，同时展示数据库记录、Run 状态、流式事件、审批、恢复和审计。演示脚本必须包含正常、失败、安全拒绝三类路径。

### 【项目追问】

清华走航车和官网项目的每项主张都要回答：问题是否真实；为什么选择该方案；替代方案是什么；数据或测试如何证明；规模扩大或依赖失败时怎么办。无法给出真实指标时明确说明验证方法，不编造数字。

## 4. 动态调整规则

每日建议按以下顺序选题：截止风险 → P0 未闭环能力 → 主 Demo 阻塞点 → 到期复习项 → 最近改动的追问 → P1 扩展。一次建议最多设置一个主任务、一个复习任务和一个可选微型 Demo，避免并行摊薄 60 小时预算。

出现以下情况时调整范围：连续两次口述失败则回到概念与最小 Demo；连续两次编码失败则缩小场景并补前置服务端知识；主 Demo 某能力已达到 S4 后停止重复堆功能，转向追问和故障验证；剩余时间不足时先砍 P1/P2，不降低 P0 的证据标准。
