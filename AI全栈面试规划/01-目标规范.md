# 面向前端背景的 AI 全栈开发面试目标规范

## 1. 目标与边界

目标是在 2026-09-20 前，用 60 小时建立一套可验证的 AI 全栈面试能力：既能解释 AI 应用与 Agent 的整体框架，也能展示 Agent Runtime、关键服务端机制、React 前端和个人项目经验如何组成一条完整工程链路。

候选人定位不是模型训练研究员，也不是分布式基础设施专家，而是**前端能力突出、能够把 Agent 应用可靠落到服务端并完成全栈交付的 AI 应用工程师**。

第一阶段不追求：训练或微调基础模型；深入 CUDA 与推理引擎；自研向量数据库；复杂 Kubernetes、多地域容灾和大规模微服务治理；同时精通多个 Agent 框架。相关内容只需要知道它们在系统中的位置和边界。

> **9 月 20 日的成功不是“资料都看过”，而是核心主题能脱稿解释、代码可运行、故障可复现、设计取舍能经受追问。**

## 2. 时间与优先级

60 小时只定义领域预算，不提前拆成固定日程。每日投入由进度台账动态分配。

| 领域 | 时间预算 | 第一阶段产出 |
| --- | ---: | --- |
| AI 整体框架与主动回忆 | 8 小时 | 一套统一心智模型；核心概念边界；脱稿回答证据 |
| Agent Runtime 与主 Demo | 28 小时 | 个人知识库 Agent 主链路；中断恢复、状态、数据与安全演示 |
| 服务端关键框架 | 10 小时 | NestJS、PostgreSQL、Redis/BullMQ、鉴权、幂等与可观测性最小闭环 |
| 前端项目、性能与工程化 | 8 小时 | 清华走航车和官网项目回答；React 控制台；性能与监控证据 |
| 模拟面试、复盘与补缺 | 6 小时 | 追问题库、失败项回炉、最终演示与面试表达 |

优先级分为三档：P0 必须达到目标等级；P1 在 P0 闭环后补足；P2 只建立概念边界，不在第一阶段展开实现。任何新增主题都必须说明它替代哪项预算，不能无成本扩张范围。

## 3. AI 整体框架

### 【统一心智模型】

需要能够从一次请求的生命周期解释以下对象，而不是孤立背诵名词：

```text
用户目标
  ↓
应用层：UI、API、身份、业务规则
  ↓
Agent 层：模型、工具、规划/路由、上下文与结果校验
  ↓
Runtime 层：Run/Thread/Step、状态、Checkpoint、中断、恢复、重试、流式事件
  ↓
数据层：业务数据、运行状态、长期记忆、知识库、审计与遥测
  ↓
基础设施：数据库、缓存/队列、对象存储、沙箱、监控与部署
```

必须说清 Model、Agent Loop、Workflow、Agent Runtime、Harness、Tool、MCP、Skill、Context、State、Memory、Knowledge Base、RAG、Eval 与 Observability 的职责边界，并能解释“为什么业务复杂不等于必须使用 Agent”。

### 【现有沉淀与复习入口】

现有资料已经覆盖较完整的概念和框架实现：[企业级 Agent 知识框架](../AI/agent_development_knowledge_framework_2026_cited.md)、[AI Agent 架构学习教程](../AI/AI%20Agent架构学习教程/README.md)、[LangChain、LangGraph 与 Deep Agents 教程](../AI/LangChain-LangGraph-Deep-Agents从零学习教程/README.md)。这些文件作为复习材料，不自动算作掌握证据。

### 【第一阶段验收】

- 在 10 分钟内画出上述分层图，并用“个人知识库 Agent”的一次请求贯穿解释。
- 对任意两个易混概念给出边界、联系、适用场景和反例。
- 回答框架选型时，能说明为什么主 Demo 选择 LangGraph.js，以及哪些能力由 NestJS、数据库、队列或应用代码负责。

## 4. Agent Runtime 核心能力

### 【状态、持久化和恢复】

必须区分业务实体状态、Agent Graph State、Checkpoint、跨线程 Store、知识库数据和审计日志。LangGraph 的 Checkpointer 面向线程内图状态，Store 面向跨线程的应用数据；两者不应被笼统称为“Memory”。[[1]](https://docs.langchain.com/oss/javascript/langgraph/persistence)

中断恢复必须通过实际代码展示：运行到敏感工具前暂停；持久化待审批状态；模拟进程退出；使用同一 `thread_id` 和恢复命令继续；证明已完成副作用不会被重复执行。LangGraph 的动态中断依赖 Checkpointer 和线程标识，生产场景应使用持久化 Checkpointer。[[2]](https://docs.langchain.com/oss/javascript/langgraph/interrupts)

### 【可靠执行】

P0 能力包括：Run/Thread/Step 标识；状态机与终止条件；Checkpoint 与 Resume；HITL；超时、取消、重试和退避；幂等键；工具输入校验；副作用门禁；错误分类；流式事件；执行审计。

P1 能力包括：并行步骤的汇合；任务队列与死信处理；Outbox 思路；状态迁移版本；评测集与回归门禁。P2 只理解分布式调度、多地域状态复制和复杂一致性问题的边界。

### 【第一阶段验收】

- 能展示一次“暂停 → 进程重启 → 审批 → 恢复”的完整运行，并查询恢复前后的持久化状态。
- 对同一副作用重复提交两次，系统只产生一次有效修改，并保存两次请求的审计证据。
- 能解释系统重试、业务重试和人工恢复的区别，以及每种失败由哪一层负责。

## 5. 服务端能力框架

### 【Node.js 与 NestJS】

服务端学习围绕主 Demo 展开，不单独追求框架 API 数量。P0 包括：Node.js 事件循环与异步错误；NestJS Module、Provider、依赖注入和请求生命周期；Controller/Service/Repository 分层；Pipe、Guard、Interceptor、Exception Filter；配置与环境隔离；REST、SSE 和 WebSocket 的边界；单元测试和集成测试。

身份与权限采用 JWT + 默认保护路由 + 细粒度资源授权。NestJS 官方文档展示了通过 Guard 校验 Bearer Token，并支持把认证 Guard 注册为全局默认。[[3]](https://docs.nestjs.com/security/authentication) 面试中需要进一步说明：认证只回答“你是谁”，文件级或工具级授权还要回答“你能操作什么”。

### 【数据、并发与异步任务】

PostgreSQL 负责用户、文档元数据、版本、Agent Run、Checkpoint、审批、幂等记录和审计日志；需要掌握表关系、索引、事务边界、乐观并发控制和常见隔离异常。PostgreSQL 的隔离级别对脏读、不可重复读、幻读和串行化异常提供不同保证，不能用“加事务”代替并发分析。[[4]](https://www.postgresql.org/docs/16/transaction-iso.html)

Redis 的第一阶段职责限定为缓存、限流、短期协调和 BullMQ 作业存储；文档解析、Embedding 和批量索引通过队列执行。NestJS 提供 BullMQ 集成，而 BullMQ 使用 Redis 持久化作业数据。[[5]](https://docs.nestjs.com/techniques/queues)

P0 必须掌握：数据建模与索引；事务；缓存穿透与失效边界；队列生产者/消费者；重试、退避、死信或失败留存；幂等键；乐观锁；连接与任务超时。P1 再学习 Outbox、分布式锁风险和水平扩展。

### 【可观测性与部署】

主链路至少生成 Trace、Metric 和结构化 Log，并能通过 `trace_id` 关联 HTTP 请求、Agent Run、模型调用、检索、工具、队列任务和数据库写入。OpenTelemetry JavaScript 为 Node.js 与浏览器提供遥测 API/SDK；当前文档中 Trace 和 Metric 标为稳定，Log 标为开发中，因此实现时应核对具体包的稳定性。[[6]](https://opentelemetry.io/docs/languages/js/)

部署只要求 Docker Compose 能启动 React 前端、NestJS API、Worker、PostgreSQL/pgvector 和 Redis；P2 的 Kubernetes 与云厂商细节不进入第一阶段实现。

## 6. 知识库与数据存储

个人知识库 Agent 以当前仓库中明确允许的 Markdown 文档为初始语料，必须保留来源路径、文档版本、分块位置和索引时间。检索结果必须引用来源，不能只返回无出处总结。

PostgreSQL 保存业务元数据与运行数据，pgvector 保存向量并执行相似度检索。pgvector 支持在 PostgreSQL 中保存向量，并提供精确与近似最近邻搜索及多种距离度量。[[7]](https://github.com/pgvector/pgvector)

必须区分以下数据：原始知识文档；规范化文档版本；Chunk 与 Embedding；检索结果；Graph State 与 Checkpoint；跨线程用户偏好；业务操作记录；不可变审计日志。每类数据都要回答所有者、主键、生命周期、更新方式和恢复来源。

## 7. 安全与治理

知识文档和用户输入都属于不可信数据。OWASP 将 Prompt Injection 描述为利用自然语言指令与数据边界不清来操纵模型行为的漏洞，并列出间接注入、RAG 污染和 Agent 工具滥用等风险。[[8]](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

P0 控制包括：仓库根路径固定；路径规范化与白名单；拒绝路径穿越和符号链接逃逸；文件类型与大小限制；检索内容标记为数据而非指令；工具最小权限；读写工具分离；修改前生成 diff；写操作必须人工批准；幂等执行；版本记录与回滚；审计日志；敏感信息脱敏；限流和超时。

安全验收至少包含：恶意文档要求泄漏其他文件时被拒绝；无权限用户不能修改文档；越界路径不能读取；审批被拒绝后没有副作用；重复恢复不会重复写入。

## 8. 前端、项目与工程化

### 【React Demo 控制台】

React 前端不是为了展示页面数量，而是暴露 Runtime 状态：会话与 Run 列表；知识文档上传/读取；检索来源；流式步骤；待审批操作；diff 预览；恢复按钮；错误与 Trace 链接。脚手架采用 React + TypeScript，具体构建工具在创建 Demo 时按最小学习成本选择；React 官方也支持从框架或 Vite 等构建工具起步。[[9]](https://react.dev/learn/creating-a-react-app)

### 【已有项目复习】

清华走航车项目重点：WebSocket 鉴权、心跳和指数退避；网络断开与 Token 失效的区分；数据缓冲、`requestAnimationFrame` 与渲染降频；地图/图表状态；规模扩大后的端云协同；性能指标和故障复现。入口为[项目概述](../Project/项目概述.md)和[走航车实时链路代码](../qhzhc-realtime-platform/docs/websocket-jwt-heartbeat-reconnect-complete-flow.md)。

官网项目重点：Nuxt 的 SSR/CSR/SSG/ISR 与 Hydration；SEO 元信息和结构化数据；首屏资源优先级；动画与布局稳定性；Design Token、组件化和工程规范；性能优化前后证据。入口为[官网开发](../Project/官网开发.md)和[性能专项优化](../工程化/性能专项优化.md)。

基础能力复习围绕项目追问展开：JavaScript 事件循环与异步；TypeScript 类型设计；浏览器渲染与缓存；HTTP/TCP/WebSocket/SSE；安全；Vite/Webpack；测试；CI/CD；前端性能监控和 RUM。避免脱离项目重新阅读全部大篇幅资料。

## 9. Demo 组合与产出

主 Demo 固定为持续演进的“个人知识库 Agent”，技术栈为 React + TypeScript、NestJS、LangGraph.js、PostgreSQL/pgvector、Redis/BullMQ 和 Docker Compose。详细范围见 [Demo 组合规范](./05-Demo组合规范.md)。

微型 Demo 不提前固定数量。每日复习发现无法解释或无法验证的机制时，优先创建能在较短时间内运行和断言结果的最小 Demo；通过后再判断是否并入主 Demo。候选主题包括 Checkpoint/Resume、幂等写入、队列重试、事务并发、RAG 引用、路径权限、SSE 流式输出和 Trace 关联。

## 10. 最终验收

### 【核心能力验收】

以下条件必须同时满足：

- AI 分层框架能脱稿讲解，并能回答至少两轮追问。
- 个人知识库 Agent 可从干净环境启动，核心测试通过，架构图与数据模型和代码一致。
- 能现场演示上传、读取、检索引用、分析、修改预览、人工审批、中断恢复、幂等和审计。
- 能现场演示至少一个失败路径和一个安全拒绝路径，而不是只演示成功结果。
- 清华走航车和官网项目都能用“场景—矛盾—方案—证据—取舍”回答，性能数据不虚构。
- 能说明当前实现没有解决什么、生产化还需补哪些能力，以及为什么第一阶段没有实现它们。

### 【证据要求】

有效证据包括：口述录音或逐字稿自测；可运行命令与输出；自动化测试；数据库状态截图或查询结果；故障注入记录；Trace；安全用例；面试追问记录。仅有笔记、代码片段或“看懂了”的自评不能单独证明掌握。
