# Flow Logs

This directory stores local delivery-flow telemetry in git-tracked files.

The default format is newline-delimited JSON:

```json
{"timestamp":"2026-06-24T10:00:00.000Z","event":"phase_start","phase":"design","command":"/delivery:design","agent":"main","workspace":".trae/artifacts/example","case_id":"D-001","result":"STARTED","workflow_version":{"git_commit":"abc123","git_branch":"main","git_dirty":false,"rules_hash":"..."},"data":{}}
```

## Rules

- Append only. Do not rewrite old log lines to make a later run look cleaner.
- Store summaries, classifications, timings, paths, case ids, rule ids, command names and exit codes.
- Every event should include `workflow_version`, generated by `.trae/scripts/append_flow_log.mjs`: git commit, branch, dirty flag and a rules hash.
- Do not store cookies, JWTs, tokens, passwords, raw request bodies, raw response bodies, screenshots, full DOM, full Figma JSON, or user private content.
- Flow logs are observability evidence only. They never close a case, change a Gate result, or replace stage artifacts.
- If a log contains sensitive data, stop and redact the entry before committing.

## Files

- `YYYY-MM-DD.ndjson`: daily structured event logs.
- Use `.trae/scripts/append_flow_log.mjs` to append events.
- Use `--workflow-version <id>` only when you need a human-readable experiment label; git metadata and rules hash are added automatically.
- Use `--dry-run` to inspect a sanitized event without writing a log line.
- Use `.trae/scripts/analyze_flow_logs.mjs` to summarize local logs.
