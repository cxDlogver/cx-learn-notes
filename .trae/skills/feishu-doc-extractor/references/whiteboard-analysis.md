# 白板读取与分析规范

## Evidence Layers

每个 whiteboard token 保存三层证据：

1. 用 `feishu_doc_media` 下载整板缩略图，用于判断布局、分组、流程方向和视觉重点。
2. 用 `feishu_whiteboard action=list_nodes` 将完整节点 JSON 流式保存到 `whiteboards/whiteboard_<NN>_<TOKEN>_nodes.json`，保留所有原字段。
3. 从节点 JSON 找出全部图片节点，逐个下载原图并记录 node id、image token、坐标、尺寸、层级、实际文件和结果。

`whiteboard_manifest.json` 为每个白板记录出现次数、缩略图、节点 JSON、节点图片、分析文件和失败原因。报告生成脚本会写入 `report_anchors` 与 `inline_placeholder_anchors`；两者数量必须等于正文出现次数。不要再写 `overview_explanation_anchors`。

只有缩略图、节点 JSON、全部真实节点图片和独立分析都存在时，白板资源才完成。

## Independent Analysis

将完整分析写入 `<RES>/whiteboards/whiteboard_<NN>_<TOKEN>_analysis.md`。报告正文仅保留 token、缩略图和详细分析链接。

每份分析不是截图索引，必须形成“上下文结论 + 节点证据 + 视觉标注解释 + 需求映射”的闭环。每份分析至少包含：

- `# 白板分析：TOKEN`
- `## 上下文`
- `## 结论摘要`
- `## 节点证据`
- `## 图片节点`
- `## 填充 / 高亮 / 标注分析`
- `## 关联评论`
- `## 需确认点`

各章节的最低分析深度：

- `## 上下文`：记录白板在正文中的章节、相邻标题、表格 / 列表位置、前后文摘要、白板用途和置信度。白板用途必须明确是 Before / After、流程说明、交互说明、字段说明、异常态、配置说明、验收证据或其他类型；不能只写“位于某章节”。
- `## 结论摘要`：承载对业务含义的判断，必须按固定三行输出业务结论、重点标注和需求映射。这里写“白板说明了什么”，不要写节点文件清单。
- `## 节点证据`：承载可复核的节点级事实，只记录节点 JSON 链接、节点范围和节点关系摘要。这里写“依据哪些节点事实判断”，不要混入业务结论。
- `## 图片节点`：逐个图片节点说明 `node_id`、`image_token`、本地图片链接、页面 / 模块 / 状态、可见关键文案、表单项、按钮、表格列、Tab、提示或异常态；多个图片节点之间存在左右对比、上下流程、父子层级或叠加关系时必须说明。
- `## 填充 / 高亮 / 标注分析`：逐个分析 fill、background、border、opacity、shape、radius、箭头、圈选、手绘线、遮罩、色块、图片填充或 `paint.type=highlight` 等非图片标注节点。每个标注都要说明标注对象、视觉位置、被强调内容、业务含义、产品改动映射、证据链和不确定项。
- `## 关联评论`：写入与该 whiteboard token 精确绑定的评论，保留 comment id、解决状态、quote、正文和回复；没有评论时写明“未发现与该白板 token 精确绑定的评论”。
- `## 需确认点`：只记录证据不足或上下文冲突导致无法确认的问题，必须包含缺失证据、候选解释和建议确认对象；证据充分时写“暂无”。

`## 结论摘要` 固定三行的内容要求：

- `**业务结论**`：说明白板在当前段落、表格单元格或列表项中表达的产品变化、业务规则或流程结论。不能只写“见截图”或“展示页面变化”，必须落到具体需求点，例如新增提示、拦截规则、剔除明细、状态变化或操作限制。
- `**重点标注**`：说明填充、高亮、边框、箭头、圈选、遮罩或视觉层级突出的是哪个页面区域、组件、字段、按钮、Tab、异常态或流程节点，以及该标注为什么重要。若无明显视觉标注，也要写明“未发现明显填充/高亮/边框/箭头标注”，并说明依据。
- `**需求映射**`：说明该白板支撑的正文需求点、表格行列、字段、按钮文案、异常态、验收标准或评论结论；若同时支撑多个需求点，写出主次关系。

`## 节点证据` 的内容要求：

- `**节点 JSON**`：链接该白板完整节点 JSON。语义目标是 `[whiteboard_<NN>_<TOKEN>_nodes.json](<RES>/whiteboards/whiteboard_<NN>_<TOKEN>_nodes.json)`；独立分析文件实际位于 `<RES>/whiteboards/` 下，推荐写成 `[whiteboard_<NN>_<TOKEN>_nodes.json](whiteboard_<NN>_<TOKEN>_nodes.json)`。无论采用哪种写法，链接都必须能解析到同一 `<RES>/whiteboards/` 目录下的真实节点 JSON 文件，不得只写文件名或 token。
- `**节点范围**`：概括用于判断的节点类型和数量，例如图片节点、文本节点、形状节点、连接线、section、group、遮罩或高亮节点；不得只写“见 JSON”。
- `**节点关系**`：概括关键父子、分组、叠放、连接、遮罩、左右对比或上下流程关系；若未发现明显关系，也要写明依据。

详细模板：

```markdown
# 白板分析：TOKEN

## 上下文

- 所在章节：
- 所在表格 / 列表：
- 前后文摘要：
- 白板用途：Before / After / 流程说明 / 交互说明 / 字段说明 / 异常态 / 配置说明 / 验收证据 / 其他
- 对应需求点：
- 与正文关系：该白板补充、证明或细化了正文中的哪条产品变化、业务规则或验收标准。
- 置信度：高 / 中 / 低；依据：

## 结论摘要

- **业务结论**：说明白板表达的具体产品变化、业务规则、流程结论或异常态结论，并映射到正文需求点。
- **重点标注**：说明填充、高亮、边框、箭头、圈选、遮罩或视觉层级突出的是哪个页面区域、组件、字段、按钮、Tab、异常态或流程节点，以及该标注为什么重要。
- **需求映射**：说明该白板支撑的正文需求点、表格行列、字段、按钮文案、异常态、验收标准或评论结论。

## 节点证据

- **节点 JSON**：[whiteboard_<NN>_<TOKEN>_nodes.json](whiteboard_<NN>_<TOKEN>_nodes.json)
- **节点范围**：说明参与判断的图片、文本、形状、连接线、section、group、遮罩或高亮节点范围。
- **节点关系**：说明节点之间的父子、分组、叠放、连接、遮罩、左右对比或上下流程关系。

> 该节点证据链接的语义目标为 `<RES>/whiteboards/whiteboard_<NN>_<TOKEN>_nodes.json`；生成实际分析文件时必须写成可解析到真实节点 JSON 的本地 Markdown 链接。

## 图片节点

- `node_id=<id>` / `image_token=<token>` / [节点图片](...)：
  - 对应页面 / 模块 / 状态：
  - 可见关键文案：
  - 可见控件 / 字段 / 表格列 / Tab：
  - 表达的业务含义：
  - 与其他图片节点的关系：

## 填充 / 高亮 / 标注分析

- 标注节点：`node_id=<id>`，type=，样式来源=fill / background / border / opacity / shape / radius / arrow / connector / mask / highlight。
  - 视觉位置：位于哪张截图、哪个页面区域、哪个表格列 / 表单项 / 按钮 / Tab / 提示文案 / 列表行附近。
  - 被强调内容：标注覆盖、框选、指向、衬底或分隔的具体页面对象。
  - 业务含义：该视觉标注传达的信息层级、风险提示、能力入口、差异点、阻断规则或状态变化。
  - 产品改动映射：对应正文需求点、表格行列、场景、字段、按钮文案、异常态或验收标准。
  - 证据链：依据正文上下文、表格单元格、节点 JSON 字段、缩略图、节点图片、评论或 Parser 辅助材料中的哪些证据。
  - 不确定项：无法确认时写明缺失证据和候选解释；能够判断时写“暂无”。

## 关联评论

- comment_id=...，resolved=...，quote=...
  - 评论正文：
  - 回复摘要：
  - 对白板结论的影响：
- 未发现与该白板 token 精确绑定的评论时，写“未发现与该白板 token 精确绑定的评论”。

## 需确认点

- 需确认对象：
- 缺失证据：
- 候选解释：
- 建议确认问题：
- 无需确认时写“暂无”。
```

结合正文前后文、所在表格或列表项、缩略图、节点 JSON、节点图片和评论说明：

- 白板用途、整体业务含义、需求点映射和验收价值。
- 每个图片节点对应的页面、模块、状态、关键文案、异常态、操作入口或结果反馈。
- 节点之间的空间、分组、父子、连接、遮罩、叠放、流程和对比关系。
- fill、background、border、opacity、shape、radius、箭头、圈选或高亮具体覆盖 / 指向的页面对象，以及它表达的产品改动。
- 标注节点与正文描述、评论、表格单元格或验收标准之间的证据链。
- 证据不足时的候选解释、缺失证据、影响范围和需确认问题。

以下内容不构成有效分析，禁止作为单独结论：

- 仅输出节点类型数量、坐标、尺寸或 z-index。
- 仅写“见截图”“展示页面变化”“用于复核布局”“高亮了重点区域”。
- 只描述颜色、透明度、边框样式或箭头方向，不说明对应页面对象和业务含义。
- 图片节点只给本地链接，不解释页面、模块、状态、文案或异常态。
- 对明确可见的色块、半透明遮罩、红线、箭头、圈选或边框标注写“无法判断”，但没有说明缺失证据和候选解释。

节点图片必须在分析文件中逐项链接。标注节点即使没有文字，也必须结合最近图片节点、坐标覆盖范围、透明度、颜色、z-index、父 section、缩略图和正文上下文推断其强调对象；只有截图分辨率不足、节点 JSON 缺字段、缩略图不可读或上下文缺失时，才允许标记无法确认，并必须写出具体原因。

## Comments And Context

记录白板所在章节、相邻标题、表格/列表位置和前后文摘要。`parent_type=WHITEBOARD_BLOCK` 且 `parent_token` 匹配的评论必须写入该分析的 `关联评论`，保留 comment id、解决状态、quote、正文和回复；不得降级为未定位。

正文中的白板由生成脚本原位替换。表格单元格内同样只保留 token、缩略图和详细分析链接，不展开分析正文。
