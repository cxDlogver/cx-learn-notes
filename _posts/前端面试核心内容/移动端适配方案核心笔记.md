# 移动端适配方案核心笔记

## 移动端适配核心目标

移动端适配的核心是解决不同尺寸移动设备（手机、平板等）的显示差异，确保页面在各类设备上都能正常展示，同时满足以下要求：

- 布局稳定：元素位置合理，无错乱、溢出、重叠等问题

- 字体可读：文字大小适中，在不同屏幕上清晰可辨，无需缩放

- 交互合理：按钮、导航等可点击元素尺寸适配，操作便捷

- 高效开发：尽量减少为每个机型单独编写样式，降低维护成本

移动端适配主要从「媒体查询」「相对单位」「弹性布局」三个核心方向展开，以下是具体方案详解。

## 媒体查询适配

媒体查询（Media Query）是响应式适配的基础，核心原理是通过设置不同的屏幕宽度断点，为不同尺寸的设备编写对应的CSS样式，实现布局的动态调整。

### 常见断点设置

根据主流设备尺寸，常用的断点划分如下（可根据项目需求灵活调整）：

```css
/* 小屏手机（如iPhone SE、小屏安卓机） */
@media (max-width: 640px) {}

/* 平板（如iPad mini、iPad） */
@media (min-width: 641px) and (max-width: 768px) {}

/* 中等屏幕（平板Pro、大屏手机） */
@media (min-width: 769px) and (max-width: 1024px) {}

/* 大屏设备（电脑端、平板大屏） */
@media (min-width: 1280px) {}
```

补充说明：前端框架（如Tailwind CSS）中常用的`sm`、`md`、`lg`、`xl`等，本质就是一套预设的断点系统，简化媒体查询的编写。

### 适用场景

- 不同屏幕尺寸下需要切换布局（如移动端单列、平板双列、电脑端多列）

- 控制特定元素在不同设备上的显示/隐藏（如移动端隐藏侧边栏、大屏显示完整导航）

- 调整元素的边距、列数、字号、间距等，适配不同屏幕

### 示例代码

以卡片列表布局为例，实现不同屏幕下的列数自适应：

```css
.card-list {
  display: grid;
  grid-template-columns: 1fr; /* 移动端默认1列 */
  gap: 12px;
}

/* 平板端（768px及以上）显示2列 */
@media (min-width: 768px) {
  .card-list {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* 大屏设备（1200px及以上）显示4列 */
@media (min-width: 1200px) {
  .card-list {
    grid-template-columns: repeat(4, 1fr);
  }
}
```

### 优缺点

- 优点：能精准控制不同设备的样式，最适合“布局变化明显”的场景，适配效果直观

- 缺点：断点数量越多，CSS代码量越大，维护成本越高；容易出现重复样式，冗余度增加

## rem / em 适配

rem和em均为相对单位，核心是通过“相对基准”实现元素尺寸的自适应，避免使用固定像素（px）导致的适配问题，是移动端H5常用的适配方式之一。

### rem 适配

rem（Root EM）的基准是「根元素（html标签）的字体大小」，页面中所有使用rem单位的元素，都会跟随html的font-size自动缩放。

### 核心原理

通过JavaScript动态计算并设置html的font-size，让rem单位与屏幕宽度绑定，实现页面整体按比例缩放。通常以某一标准设计稿（如375px宽度）为基准，计算缩放比例。

### 示例代码

基础样式设置：

```css
/* 默认html字体大小（可作为基准） */
html {
  font-size: 16px;
}

/* 使用rem单位设置元素样式 */
.title {
  font-size: 1.5rem; /* 等价于16px * 1.5 = 24px */
  padding: 1rem;     /* 等价于16px */
  margin-bottom: 0.5rem; /* 等价于8px */
}
```

JavaScript动态设置rem基准（适配不同屏幕）：

```javascript
// 基准设计稿宽度（通常为375px，移动端常用设计稿尺寸）
const baseWidth = 375;
// 计算当前屏幕宽度与基准宽度的缩放比例
const scale = window.innerWidth / baseWidth;
// 动态设置html的font-size（基准16px，按比例缩放）
document.documentElement.style.fontSize = `${16 * scale}px`;

// 监听屏幕 resize 事件，屏幕变化时重新计算
window.addEventListener('resize', () => {
  const scale = window.innerWidth / baseWidth;
  document.documentElement.style.fontSize = `${16 * scale}px`;
});
```

### em 适配

em的基准是「当前元素的字体大小」，若当前元素未设置font-size，则继承父元素的font-size，嵌套使用时会出现“叠加计算”的情况。

### 示例代码

```css
/* 父元素设置字体大小，作为子元素em的基准 */
.parent {
  font-size: 20px;
}

/* 子元素em基于父元素的font-size计算 */
.child {
  font-size: 1.2em; /* 等价于20px * 1.2 = 24px */
  padding: 1em;     /* 等价于24px（基于自身font-size） */
  margin: 0.8em;    /* 等价于24px * 0.8 = 19.2px */
}
```

### 适用场景与一般实践

- rem：适合页面级适配，用于整体UI（如字号、边距、宽高）的按比例缩放，常用于移动端H5项目

- em：适合组件内部的局部缩放（如按钮内部文字与内边距的比例），嵌套较少的场景

- 一般实践：页面级适配优先使用rem，保证整体一致性；组件内部局部缩放可使用em，灵活调整内部比例

### 优缺点

- 优点：一套比例体系，适配统一，能快速实现页面整体缩放；无需为不同设备单独编写样式

- 缺点：需要额外通过JavaScript维护根元素font-size；过度缩放时（如大屏设备），文字可能过大或过小，影响可读性；em嵌套时计算复杂，容易出错

## vw / vh 适配

vw（Viewport Width）和vh（Viewport Height）是基于「视口尺寸」的相对单位，无需JavaScript辅助，天然跟随视口大小变化，适配逻辑更简洁。

### 单位含义

- `1vw`：等于视口宽度的1%（如视口宽度375px，1vw = 3.75px）

- `1vh`：等于视口高度的1%（如视口高度667px，1vh = 6.67px）

### 示例代码

```css
/* 轮播图全屏宽度，高度为视口高度的50% */
.banner {
  width: 100vw;
  height: 50vh;
  object-fit: cover;
}

/* 标题字体大小跟随视口宽度变化 */
.title {
  font-size: 4vw; /* 视口宽度越大，字体越大 */
  font-weight: 600;
}

/* 按钮宽高跟随视口变化 */
.btn {
  width: 20vw;
  height: 8vh;
  font-size: 3vw;
}
```

### 适用场景

- 与视口强相关的尺寸（如全屏轮播、首屏banner、弹窗全屏布局）

- 需要跟随视口大小动态变化的元素（如自适应字体、自适应按钮）

- 无需复杂适配逻辑，追求简洁高效的场景

### 优缺点

- 优点：无需JavaScript辅助，天然适配视口；代码简洁，开发效率高；适配逻辑直观

- 缺点：字体完全使用vw时，在极端尺寸设备上（如小屏手机、大屏平板）容易过大或过小，影响可读性；vh在移动端会受地址栏、工具栏遮挡影响，不同浏览器表现不一致，稳定性较差

### 改进写法（结合clamp()）

为解决vw单位字体波动过大的问题，可结合`clamp()`函数设置字体的最小、最大和理想值，兼顾适配性和可读性。

```css
/* clamp(最小值, 理想值, 最大值) */
.title {
  font-size: clamp(16px, 4vw, 24px);
}

/* 解释：
  1. 当视口较小时，字体最小为16px，避免过小
  2. 当视口适中时，字体为4vw，跟随视口缩放
  3. 当视口较大时，字体最大为24px，避免过大
*/
```

补充：clamp()函数在现代浏览器中支持度较高，是当前移动端适配中优化vw字体的常用方案。

## Flex 适配

Flex（弹性布局）是移动端最常用的布局方式之一，核心是通过「弹性容器」和「弹性子项」的关系，实现元素的自适应排列，尤其适合一维布局（横向或纵向）。

### 核心语法与含义

通过给父容器设置`display: flex`，使其成为弹性容器，子元素自动成为弹性子项，常用核心属性如下：

- `flex: 1`：是`flex-grow: 1`、`flex-shrink: 1`、`flex-basis: 0`的简写，含义是：子项自动拉伸或收缩，平分弹性容器的剩余空间

- `flex-direction`：设置布局方向（row横向、column纵向）

- `justify-content`：设置子项在主轴上的对齐方式（如center居中、space-between两端对齐）

- `align-items`：设置子项在交叉轴上的对齐方式（如center垂直居中）

### 示例代码

以移动端底部导航栏为例，实现等分布局：

```css
/* 弹性容器（底部导航栏） */
.nav {
  display: flex;
  height: 50px;
  border-top: 1px solid #eee;
}

/* 弹性子项（导航项），平分剩余空间 */
.nav-item {
  flex: 1; /* 所有导航项平分导航栏宽度 */
  text-align: center;
  line-height: 50px;
  font-size: 14px;
  color: #333;
}

/* 激活状态 */
.nav-item.active {
  color: #007aff;
}
```

### 适用场景

- 横向排列的元素（如导航栏、标签栏、按钮组）

- 等分布局（如底部导航、卡片内等宽元素）

- 元素按内容伸缩（如输入框+按钮组合）

- 垂直居中、水平居中的布局需求

### 优缺点

- 优点：语法简洁，适配性强，适合移动端一维布局；对齐能力强，轻松实现居中、等分布局；编写响应式布局时更便捷

- 缺点：处理复杂二维布局（如多列多行且有固定间距的卡片流）时，不如Grid布局直观、高效

## Grid 适配

Grid（网格布局）是一种二维布局方式，核心是通过「网格容器」和「网格项」的关系，实现多列多行的布局，尤其适合卡片流、宫格、后台列表等规则的二维布局，适配性极强。

### 核心经典写法

移动端Grid适配中，最常用、最经典的写法是：`grid-template-columns: repeat(auto-fit, minmax(最小宽度, 1fr))`，无需媒体查询，即可实现卡片的自动适配。

### 语法解析

- `repeat(...)`：重复生成网格列，简化多列写法

- `auto-fit`：自动根据网格容器的宽度，塞入尽可能多的列，剩余空间自动拉伸网格项

- `minmax(最小宽度, 1fr)`：每列的最小宽度为设定值，最大宽度为1fr（平分剩余空间）

### 示例代码

以商品卡片列表为例，实现自适应列数：

```css
/* 网格容器（卡片列表） */
.goods-list {
  display: grid;
  /* 每列最小150px，自动适配列数，列间距16px */
  grid-template-columns: repeat(auto-fit, minmax(150px, 1fr));
  gap: 16px; /* 网格项之间的间距 */
  padding: 12px;
}

/* 网格项（商品卡片） */
.goods-card {
  height: 200px;
  background: #f5f5f5;
  border-radius: 8px;
  padding: 8px;
}
```

效果：屏幕较小时（如手机），一行显示1~2列；屏幕较大时（如平板），自动显示3~4列，无需编写媒体查询。

### auto-fit 与 auto-fill 的区别

两者均用于自动生成网格列，核心区别在于对“剩余空间”的处理：

- `auto-fit`：尽量拉伸已有网格项，填满网格容器的剩余空间，不会留下空白轨道

- `auto-fill`：会根据容器宽度，生成尽可能多的列（包括空白轨道），即使没有足够的网格项，也会保留空白空间

实际开发中，做响应式卡片列表、宫格布局时，优先使用`auto-fit`，适配效果更自然。

### 适用场景

- 商品卡片列表、图片列表等需要自适应列数的场景

- 宫格布局（如首页功能入口、设置页面）

- 后台管理系统的列表布局、多列表单布局

- 需要固定间距、规则排列的二维布局

### 优缺点

- 优点：适配性极强，无需媒体查询即可实现多列自适应；语法简洁，适合复杂二维布局；间距控制更精准

- 缺点：浏览器兼容性略低于Flex布局（现代浏览器均支持，低版本浏览器需兼容处理）；简单一维布局不如Flex简洁

## 核心总结

- 移动端适配的核心是“统一比例、灵活调整”，优先选择简单、可维护性高的方案，避免过度复杂的适配逻辑。

- 媒体查询适合布局变化明显的场景，rem/vw适合整体缩放，Flex适合一维布局，Grid适合二维布局，实际开发中可组合使用（如Flex+Grid、vw+clamp()）。

- 适配优先级：先保证布局稳定和可读性，再追求开发效率；优先使用相对单位和弹性布局，减少固定像素的使用。
