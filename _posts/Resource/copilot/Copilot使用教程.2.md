# GitHub Copilot 从 0 到 1 部署与使用教程

**摘要：**  
这是一篇面向中文初学者的 GitHub Copilot 从 0 到 1 部署与使用教程。你将了解 Copilot 是什么、适合谁、如何完成账号与权限准备、如何在 VS Code / JetBrains / Visual Studio 中安装登录、如何使用 Copilot CLI，以及如何在 GitHub 网站、代码补全、解释、测试、修 Bug、重构、写文档等场景中真正落地。本文强调“先能用，再用好”，界面、套餐能力和组织策略如有变动，请以官方文档和当前产品界面为准。

---

## 1. 什么是 GitHub Copilot？能做什么？

GitHub Copilot 是 GitHub 提供的 AI 编程助手，可在编辑器、IDE、命令行和 GitHub 网站内为开发者提供帮助。

### 它能做什么
- **代码补全**
  - 根据当前文件、注释、函数名、相邻代码自动给出建议
  - 可补全单行、函数、样板代码甚至一段实现逻辑
- **对话式问答**
  - 解释代码含义
  - 帮你理解陌生仓库
  - 回答“这段报错为什么出现”
- **生成与修改代码**
  - 生成测试
  - 修复常见 Bug
  - 重构重复逻辑
  - 补充文档注释
- **命令行辅助**
  - 在终端中解释命令、生成命令、结合仓库上下文做开发辅助
- **GitHub 网站内协作**
  - 在仓库、文件、Pull Request 场景中辅助理解代码与变更
  - 在某些计划或配置下，可进一步参与代码修改建议甚至协助创建 PR

### 一句话理解
它不是“替你写完所有代码”的工具，而是一个**高频、上下文感知、可交互的开发助手**。  
你仍然负责判断需求、审核输出、运行测试和最终交付。

## 2. 适用人群与使用前准备

### 适用人群
- 刚开始接触编程或刚接触 GitHub 的新手
- 需要快速上手新语言、新框架的开发者
- 需要提高日常编码、调试、写测试效率的工程师
- 维护老项目、需要快速理解陌生代码的团队成员
- 技术文档、脚本、自动化任务较多的研发团队

### 使用前准备
建议先准备好以下内容：

1. **GitHub 账号**
2. **可用的 Copilot 权限**
   - Copilot Free 或付费计划
   - 如果你通过公司/组织使用，则还需要组织为你开通权限
3. **开发工具**
   - VS Code / JetBrains IDE / Visual Studio
4. **稳定网络**
5. **基础开发环境**
   - 例如 Git、Node.js、Python、Java 等，按你的项目需要准备
6. **最小认知准备**
   - 会打开项目
   - 会运行基本命令
   - 知道如何查看报错与测试结果

## 3. 账号、订阅/权限、组织策略说明

这是很多新手第一次使用时最容易卡住的地方。

### 3.1 个人用户如何获得 Copilot
GitHub Copilot 可通过以下方式使用：
- **Copilot Free**
- **付费计划**（不同计划的功能与额度可能不同）

也就是说，不一定非要先购买最高级套餐才能开始体验；但不同计划的能力、模型、配额、企业集成能力会有差异。

### 3.2 个人版与组织版的区别
可简单理解为：

#### 个人版
适合个人开发者、学习者、小型独立使用场景。
- 账号自己开通
- 权限由个人账号控制
- 更适合个人学习和日常编码提效

#### 组织版 / 企业管理场景
适合公司、团队、企业统一采购与管理。
- 由组织或企业管理员统一分配权限
- 组织可以控制 Copilot 是否可用
- 组织可以设置策略、功能范围与合规边界
- 某些能力是否开放，可能取决于组织策略而不是你个人意愿

### 3.3 为什么“我明明有账号，却用不了”
常见原因：
- 你没有可用的 Copilot 资格
- 你的组织未给你分配权限
- 组织管理员关闭了某些 Copilot 功能
- 你在 IDE 中登录了错误的 GitHub 账号
- 企业网络策略拦截了相关服务

### 3.4 实操建议
开始前先确认这三件事：
- **你登录的是哪个 GitHub 账号**
- **该账号是否有 Copilot 权限**
- **若为公司账号，组织是否允许使用相关功能**

## 4. 在 VS Code 中安装与登录

VS Code 是多数初学者最容易开始的方式。

### 安装步骤
1. 打开 VS Code
2. 进入扩展商店
3. 搜索：
   - `GitHub Copilot`
   - 如需聊天能力，也可安装与 Copilot Chat 相关的官方扩展（以当前扩展市场显示为准）
4. 点击安装

### 登录步骤
1. 安装完成后，通常会看到登录提示
2. 选择 **Sign in to GitHub**
3. 浏览器会跳转到 GitHub 授权页
4. 完成授权后回到 VS Code
5. 若状态正常，Copilot 会开始提供建议或聊天能力

### 首次验证是否成功
打开一个代码文件，输入类似注释：

```python
# 写一个函数，返回列表中的最大值
```

如果几秒内出现灰色建议文本，说明已基本正常。

### 常见建议
- 如果没有弹出登录，尝试：
  - 命令面板搜索 `Copilot`
  - 查找登录相关命令
- 如果登录后仍无建议：
  - 重新加载窗口
  - 检查扩展是否被禁用
  - 检查当前语言是否支持建议
  - 检查当前账号是否确实拥有权限

## 5. 在 JetBrains 中安装与登录

JetBrains 系 IDE（如 IntelliJ IDEA、PyCharm、WebStorm、GoLand 等）也可使用 GitHub Copilot。

### 安装步骤
1. 打开 JetBrains IDE
2. 进入 **Plugins**
3. 在 Marketplace 中搜索 **GitHub Copilot**
4. 安装插件
5. **重启 IDE**

### 登录步骤
根据官方常见流程，可按以下方式操作：
1. 打开顶部菜单 **Tools**
2. 进入 **GitHub Copilot**
3. 选择 **Login to GitHub**
4. IDE 会给出一个设备码或登录提示
5. 浏览器打开认证页面
6. 输入设备码并完成 GitHub 授权

> JetBrains 的具体菜单名称、位置和弹窗样式可能因 IDE 版本不同而略有差异，请以官方文档和实际界面为准。

### 首次验证
新建或打开一个代码文件，写出清晰注释，例如：

```java
// 实现一个方法：判断字符串是否为回文
```

若出现建议，说明插件工作正常。

## 6. 在 Visual Studio 中安装与登录

如果你所在公司统一安装开发环境，优先联系管理员确认：
- 当前 Visual Studio 版本是否支持
- 组织是否允许使用 Copilot
- 是否需要企业账号登录

## 7. Copilot CLI：安装、认证与基础使用

如果你经常在终端里开发，Copilot CLI 很值得上手。

## 7.1 安装方式

### 方式一：npm 安装
> 使用 npm 安装时，**Node.js 需要 22+**

```bash
npm install -g @github/copilot
```

### 方式二：Homebrew
```bash
brew install copilot-cli
```

### 方式三：WinGet
```powershell
winget install GitHub.Copilot
```

### 方式四：安装脚本
```bash
curl -fsSL https://gh.io/copilot-install | bash
```

---

## 7.2 首次启动与登录

安装完成后，先运行：

```bash
copilot
```

如果尚未登录，按提示输入：

```text
/login
```

然后根据终端与浏览器提示完成认证。

> 最稳妥的首次使用方式就是：**先运行 `copilot`，如被提示，再执行 `/login`。**

---

## 7.3 基础使用方式

### 在项目目录中启动
建议进入项目目录后再启动：

```bash
cd your-project
copilot
```

这样它更容易理解当前仓库上下文。

### 常用能力
- **`@file`**：把文件内容带入上下文  
  例如：
  ```text
  请解释 @src/app.py 这个文件的核心逻辑
  ```

- **计划模式 / Plan mode**
  - 在动手改代码前，先让它输出计划
  - 适合“先评估再执行”的工作方式

- **受信任目录 / trusted directories**
  - Copilot CLI 支持受信任目录机制
  - 建议只在你确认安全、熟悉的项目目录中授予更高权限

- **`/cwd`（部分界面或使用习惯中也会提到 `/cd`，以实际界面为准）**
  - 查看或切换当前工作目录
  - 适合确认当前分析的是哪个项目

- **`!` 执行本地 shell 命令**
  - 例如在交互中执行命令
  - 适合快速查看文件、运行测试、检查状态

- **`--continue`**
  - 继续之前的会话或上下文，适合中断后续接

### 一个简单示例
```bash
copilot
```

进入后可尝试：

```text
请先阅读当前仓库结构，告诉我入口文件在哪里，并给出一个修改计划
```

再进一步：

```text
@package.json @src/main.ts 请解释启动流程
```

## 7.4 让 CLI 更懂你的仓库

Copilot CLI 支持仓库级指令文件，有助于稳定输出风格和约束。

### 仓库级通用说明
```text
.github/copilot-instructions.md
```

适合写：
- 项目技术栈
- 代码风格要求
- 测试运行方式
- 禁止修改的目录
- 提交前检查项

### 路径级说明
```text
.github/instructions/**/*.instructions.md
```

适合按目录细分规则，例如：
- 前端目录一套规范
- 后端目录一套规范
- 文档目录一套规范

### 代理说明文件
```text
AGENTS.md
```

适合描述：
- 仓库内协作规则
- 任务分工说明
- 常见工作流约束

### 建议
如果你在团队中使用 CLI，强烈建议把这些说明文件纳入版本控制，这样每个成员得到的 Copilot 行为更一致。

## 8. GitHub 网站内的 Copilot：Chat、代码理解、PR 场景

很多人以为 Copilot 只能在 IDE 里用，其实 GitHub 网站里的价值也很高。

### 8.1 仓库与文件理解
在 GitHub 网站查看代码时，Copilot 可帮助你：
- 总结文件作用
- 解释某段代码在做什么
- 帮你快速定位关键入口
- 帮助理解大型仓库结构

适合新手第一次接手项目时使用。

### 8.2 Chat 场景
在网页端，你可以直接围绕仓库内容提问，例如：
- 这个项目的主入口在哪里？
- 用户登录流程涉及哪些文件？
- 为什么这个模块容易报错？
- 最近这个 PR 改动的重点是什么？

### 8.3 Pull Request 场景
在 PR 中，Copilot 的典型帮助包括：
- 总结变更内容
- 解释修改影响
- 辅助审阅代码
- 帮助发现潜在风险点

在某些计划或配置下，它还可以更进一步参与代码修改流程，甚至协助打开 PR；但这取决于当前产品能力、套餐与组织策略，需以官方能力范围为准。

## 9. 常见使用姿势：真正能提效的 6 类场景

下面不是“理论功能清单”，而是最值得新手先掌握的使用姿势。

### 9.1 补全代码
适合：
- 写 CRUD
- 写接口调用
- 写数据转换
- 写样板代码

高效写法：
```python
# 读取 CSV 文件，按城市分组并统计人数，返回字典
```

比起只写函数名，**清晰注释更容易得到可用结果**。

---

### 9.2 解释代码
适合：
- 接手旧项目
- 看不懂报错栈
- 看不懂陌生函数

示例提示词：
```text
请用初学者能理解的方式解释这段代码，每一步都说明目的，并指出潜在风险。
```

---

### 9.3 生成测试
适合：
- 给老函数补单元测试
- 快速覆盖边界情况
- 学习测试写法

示例提示词：
```text
为这个函数生成单元测试，覆盖正常输入、空输入、异常输入和边界条件。
```

---

### 9.4 修 Bug
适合：
- 已有报错信息
- 已能复现问题
- 知道期望行为

高效输入模板：
```text
问题：接口返回 500
复现步骤：提交空邮箱时触发
期望结果：返回 400，并提示邮箱不能为空
请先分析原因，再给出最小修改方案
```

---

### 9.5 重构
适合：
- 重复代码太多
- 函数太长
- 命名混乱
- 逻辑耦合严重

示例提示词：
```text
请重构这段代码，目标是拆分职责、减少重复、保持原有行为不变，并说明每一步改动原因。
```

---

### 9.6 写文档
适合：
- README
- API 使用说明
- 代码注释
- 部署指南
- 交接文档

示例提示词：
```text
根据当前模块代码，生成一段面向新同事的中文说明，包含功能、输入、输出、依赖和注意事项。
```

## 10. 高质量提示词写法与示例

Copilot 的效果很大程度取决于你怎么问。

## 10.1 好提示词的结构
建议包含以下 5 个元素：

1. **目标**
2. **上下文**
3. **约束**
4. **输出格式**
5. **验收标准**

### 模板
```text
目标：我要做什么
上下文：当前项目/语言/文件/报错信息
约束：不要改接口、保持兼容、只改最小范围
输出格式：直接给代码 / 先给方案再改 / 用表格总结
验收标准：测试通过、包含边界处理、给出风险说明
```

---

## 10.2 从“模糊提问”到“高质量提问”

### 不够好
```text
帮我修一下这个问题
```

### 更好
```text
这是一个 Python Flask 接口。当前问题是用户提交空邮箱时返回 500。
请先分析可能原因，再给出最小改动的修复方案，并补一组单元测试。
不要修改接口路径和返回 JSON 字段名。
```

---

## 10.3 适合直接复制的提示词示例

### 示例 1：解释代码
```text
请解释这个文件的作用、主要函数、调用关系，并用适合初学者的语言说明。
```

### 示例 2：生成测试
```text
请为选中的函数生成单元测试，覆盖成功路径、空值、异常值和边界条件。
```

### 示例 3：修 Bug
```text
下面是报错信息和复现步骤。请先定位根因，再给出最小修改方案，并说明为什么这么改。
```

### 示例 4：重构
```text
请把这段过长函数拆成多个小函数，保持外部行为不变，并给出重构前后职责对比。
```

### 示例 5：写文档
```text
请基于当前代码生成一段中文 README 说明，包含用途、启动方式、配置项和常见问题。
```

## 11. 团队落地建议与安全边界

Copilot 用得好，关键不只是“装上”，而是“设好边界”。

## 11.1 团队落地建议
### 建议一：先从低风险场景开始
优先用于：
- 测试生成
- 文档编写
- 代码解释
- 样板代码
- 小范围重构

不要一上来就让它改核心交易逻辑或安全关键模块。

### 建议二：建立统一提示模板
例如团队统一要求：
- 先给方案再改代码
- 修改时说明影响范围
- 必须补测试
- 不要擅自改公共接口

### 建议三：把仓库说明文件配起来
建议逐步完善：
- `.github/copilot-instructions.md`
- `.github/instructions/**/*.instructions.md`
- `AGENTS.md`

### 建议四：保留人工审核
AI 生成的内容必须经过：
- 代码评审
- 测试验证
- 安全检查
- 业务确认

---

## 11.2 安全边界
以下边界建议长期坚持：

- **不要直接信任 AI 输出**
- **不要把密钥、Token、证书、生产口令直接贴给 Copilot**
- **不要让 AI 替代权限审批和代码审核**
- **不要在未确认的情况下执行它建议的高风险命令**
- **对数据库、支付、安全、权限控制等核心逻辑保持人工主导**
- **组织环境下，遵守企业管理员设置的策略与合规要求**

一句话：**Copilot 是助手，不是审批人，也不是最终责任人。**

## 12. 常见问题与排障

## 12.1 登录成功了，但没有补全
排查顺序：
1. 确认当前账号有 Copilot 权限
2. 确认扩展/插件已启用
3. 确认当前文件类型受支持
4. 尝试重新加载 IDE
5. 检查网络连接与代理设置
6. 如果是组织账号，确认组织未禁用相关能力

---

## 12.2 一直弹登录，登录后又失效
常见原因：
- 登录了错误账号
- 本地缓存状态异常
- 企业 SSO/组织授权未完成
- 网络或代理导致认证回调失败

处理建议：
- 退出后重新登录
- 清理 IDE 中的 GitHub 登录状态
- 用浏览器确认 GitHub 当前登录账号
- 若为公司账号，联系管理员确认策略

---

## 12.3 JetBrains / VS Code 安装了但没有 Chat
可能原因：
- 相关扩展或插件未安装完整
- 当前计划不包含某些能力
- 组织策略限制
- 版本过旧

建议：
- 更新 IDE
- 更新插件
- 查看官方功能说明页
- 与管理员确认授权范围

---

## 12.4 Copilot CLI 启动后不能用
检查：
- 是否已正确安装
- 是否运行了 `copilot`
- 是否按提示执行了 `/login`
- 是否在项目目录中启动
- 是否当前目录未被允许或未设为可信环境
- 是否网络阻断了认证或请求

---

## 12.5 CLI 用 npm 安装失败
优先确认：
- Node.js 是否为 **22+**
- 全局 npm 安装路径是否正常
- 是否被公司代理限制

可切换其他安装方式：
- `brew install copilot-cli`
- `winget install GitHub.Copilot`
- `curl -fsSL https://gh.io/copilot-install | bash`

---

## 12.6 Copilot 给出的代码不靠谱怎么办
这是正常现象，不代表工具失效。

改进方法：
- 给更多上下文
- 说明输入输出
- 明确不要改动的边界
- 指定“先分析再给代码”
- 把相关文件带入上下文，如 `@file`
- 用测试来约束输出质量

## 13. 实战演练：从安装到完成第一个任务

下面用一个最小实战，把“能装、能登、能用”串起来。

### 任务目标
在 VS Code 中安装 GitHub Copilot，并用它完成一个简单 Python 函数及测试。

---

## 13.1 第一步：安装并登录 VS Code 插件
1. 打开 VS Code
2. 安装 `GitHub Copilot`
3. 按提示登录 GitHub
4. 确认当前账号具备 Copilot 权限

---

## 13.2 第二步：创建一个示例文件
创建 `math_utils.py`：

```python
def add(a, b):
    pass
```

---

## 13.3 第三步：让 Copilot 帮你补全函数
把光标放在函数里，输入注释：

```python
def add(a, b):
    # 返回两个数字之和，如果输入不是数字则抛出 TypeError
```

此时观察是否出现建议。接受后，可能得到类似实现：

```python
def add(a, b):
    # 返回两个数字之和，如果输入不是数字则抛出 TypeError
    if not isinstance(a, (int, float)) or not isinstance(b, (int, float)):
        raise TypeError("a and b must be numbers")
    return a + b
```

> 不要直接结束，先自己读一遍：逻辑对不对？异常是否合理？

---

## 13.4 第四步：让 Copilot 生成测试
创建 `test_math_utils.py`，然后在 Chat 或编辑器中输入：

```text
请为 add 函数生成 pytest 单元测试，覆盖正常情况和非数字输入的异常情况。
```

可能得到类似内容：

```python
import pytest
from math_utils import add

def test_add_normal():
    assert add(1, 2) == 3

def test_add_float():
    assert add(1.5, 2.5) == 4.0

def test_add_invalid_type():
    with pytest.raises(TypeError):
        add("1", 2)
```

---

## 13.5 第五步：运行测试并回到 Copilot 修正
如果你的环境已安装 pytest，可运行：

```bash
pytest
```

若报错，把报错贴给 Copilot：

```text
下面是 pytest 报错，请分析原因并给出最小修复方案，不要改测试目标。
```

这一步非常关键：  
**Copilot 最有价值的不是“一次写对”，而是“帮你快速迭代到正确”。**

---

## 13.6 第六步：再做一次文档化
继续让它生成简单说明：

```text
请为这个文件补充中文文档注释，并生成一段 README 示例说明如何运行测试。
```

你就完成了一个完整闭环：
- 安装
- 登录
- 写代码
- 写测试
- 跑测试
- 修问题
- 写文档

这已经是一个合格的“第一个 Copilot 任务”。
