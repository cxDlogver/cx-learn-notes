# 面向对象编程思想

## 0 目标

### 掌握原型继承的基本概念

理解 JavaScript 中原型和原型链的核心关联，明确原型继承的底层逻辑，掌握原型相关的核心属性与方法，能清晰描述原型链的查找规则。

1. 核心概念：每个 JavaScript 对象都有内部属性`[[Prototype]]`（可通过`Object.getPrototypeOf()`访问），该属性指向另一个对象即**原型**；原型对象也有自己的原型，以此形成的链式结构即为**原型链**，原型链的最终终点为`null`。
2. 关键区分：构造函数的`prototype`属性是其创建实例的原型，实例的`[[Prototype]]`指向构造函数的`prototype`，二者不可混淆。
3. 核心规则：访问对象属性 / 方法时，若自身无该成员，会沿原型链向上查找，直至找到目标成员或到达`null`。

```js
// 原型与原型链基础示例
function Person(name) {
  this.name = name;
}
// 构造函数的prototype挂载共享方法
Person.prototype.sayName = function() {
  console.log(this.name);
};
const p1 = new Person('Tom');
p1.sayName(); // Tom：p1自身无sayName，沿原型链找到Person.prototype.sayName

// 验证原型链关系
console.log(Object.getPrototypeOf(p1) === Person.prototype); // true
console.log(Object.getPrototypeOf(Person.prototype) === Object.prototype); // true
console.log(Object.getPrototypeOf(Object.prototype) === null); // true：原型链终点
```

### 掌握面向对象编程（OOP）思想

了解面向对象编程的核心三大特性 ——**封装**、**继承**、**多态**，并掌握其在 JavaScript 中的基础实现方式，建立面向对象的编程思维。

1. 封装：将数据（属性）和操作数据的方法封装在一个对象 / 构造函数中，隐藏内部实现细节，仅对外暴露访问接口，减少全局变量污染。
2. 继承：让一个对象 / 类拥有另一个对象 / 类的属性和方法，实现代码复用，JavaScript 中基于原型链实现原生继承。
3. 多态：同一方法在不同对象上有不同的实现形式，即**方法重写**，JavaScript 中通过原型链的属性遮蔽特性实现。

```js
// OOP三大特性基础实现
// 1. 封装：构造函数封装属性和方法
function Animal(name) {
  this.name = name; // 封装属性
  this.eat = function() { // 封装实例方法
    console.log(`${this.name}在进食`);
  };
}
// 2. 继承：原型链实现继承
function Dog(name) {
  Animal.call(this, name);
}
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;
// 3. 多态：方法重写
Dog.prototype.eat = function() {
  console.log(`${this.name}在吃骨头`);
};

const animal = new Animal('小动物');
const dog = new Dog('旺财');
animal.eat(); // 小动物在进食
dog.eat(); // 旺财在吃骨头：重写后实现多态
```

### 了解原型实现继承的方式

能够通过**原型链**实现 JavaScript 对象的基础继承，掌握原型链继承的核心代码编写，理解其运行逻辑，能独立实现简单的继承结构。

1. 核心实现：将子类的原型对象指向父类的实例，即`Child.prototype = new Parent()`，让子类实例沿原型链访问父类的属性和方法。
2. 关键注意：需保证子类原型的`constructor`属性指向自身，避免原型链混乱。

```js
// 原型链实现继承的基础写法
// 父类
function Parent(age) {
  this.age = age;
  this.hobbies = ['reading'];
}
Parent.prototype.sayAge = function() {
  console.log(this.age);
};
// 子类
function Child(name, age) {
  this.name = name;
  Parent.call(this, age); // 初始化父类属性
}
// 核心：原型链继承父类方法
Child.prototype = new Parent();
// 修正constructor指向
Child.prototype.constructor = Child;

// 创建子类实例
const c1 = new Child('Jerry', 18);
c1.sayAge(); // 18：继承父类原型方法
console.log(c1.name); // Jerry：子类自身属性
console.log(c1.hobbies); // ['reading']：继承父类实例属性
```

2. `call`/`apply`原理：改变函数执行时的`this`指向，将函数作为目标对象的临时方法调用，执行后删除该方法并返回结果。
3. `class`与原型的区别：`class`是原型继承的语法糖，简化了代码编写，其底层仍通过构造函数、`prototype`、原型链实现，与原生原型方式的核心逻辑一致，仅语法形式不同。

```js
// 高频考点1：手写call方法
Function.prototype.myCall = function(context) {
  // 处理context为null/undefined的情况，默认指向window
  context = context || window;
  // 将当前函数（this）作为context的临时方法
  const fn = Symbol('fn'); // 避免属性名冲突
  context[fn] = this;
  // 获取传入的参数，排除第一个context参数
  const args = [...arguments].slice(1);
  // 执行函数并获取结果
  const result = context[fn](...args);
  // 删除临时方法，避免污染context
  delete context[fn];
  // 返回函数执行结果
  return result;
};

// 测试myCall
function fn(a, b) {
  console.log(this.name, a + b);
}
fn.myCall({name: 'Tom'}, 1, 2); // Tom 3

// 高频考点2：class与原型的等价实现
// class写法
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    console.log(`${this.name}发出声音`);
  }
}
// 等价的原生原型写法
function AnimalProto(name) {
  this.name = name;
}
AnimalProto.prototype.speak = function() {
  console.log(`${this.name}发出声音`);
};
```

### OOP 实践应用

能够将面向对象编程思想灵活运用到实际项目开发中，解决真实业务问题，实现代码的高复用、高可维护和高扩展性。

1. 业务封装：将项目中的通用模块封装为类，如弹窗类、请求类、工具类，通过实例化实现多处复用，修改时仅需维护类的内部逻辑。
2. 继承扩展：基于基础类实现子类扩展，如基础弹窗类派生出确认弹窗类、提示弹窗类，继承基础方法并扩展专属功能。
3. 多态适配：针对不同业务场景实现同一方法的不同逻辑，如表单验证类的`validate`方法，对不同表单项（输入框、下拉框）实现不同的验证规则。

```js
// 项目实战：封装基础请求类并通过继承扩展
// 基础请求类：封装通用的请求逻辑
class Request {
  constructor(baseUrl) {
    this.baseUrl = baseUrl;
  }
  // 通用请求方法
  async request(url, options) {
    const res = await fetch(`${this.baseUrl}${url}`, options);
    return res.json();
  }
  // GET请求封装
  get(url, params) {
    const query = new URLSearchParams(params).toString();
    return this.request(`${url}?${query}`, { method: 'GET' });
  }
}

// 子类：业务请求类，继承并扩展
class ApiRequest extends Request {
  constructor() {
    super('https://api.example.com'); // 继承父类构造函数
  }
  // 扩展专属业务方法：用户相关请求
  getUserInfo(id) {
    return this.get(`/user/${id}`);
  }
  // 扩展专属业务方法：商品相关请求
  getGoodsList(params) {
    return this.get('/goods', params);
  }
}

// 实例化使用
const api = new ApiRequest();
api.getUserInfo(1).then(res => console.log(res));
api.getGoodsList({ page: 1, size: 10 }).then(res => console.log(res));
```

### 经典面试真题

#### 解释 JavaScript 中的原型继承概念

**答案**：原型继承是 JavaScript 实现面向对象继承的原生方式，基于**原型链**实现，核心逻辑为对象可以从其他对象继承属性和方法。每个 JavaScript 对象都有内部属性`[[Prototype]]`（原型），该属性引用另一个对象，当访问对象的属性 / 方法时，若自身无该成员，会沿原型链向上查找，直至找到目标成员或到达原型链终点`null`；构造函数的`prototype`属性会成为其所有实例的原型，因此挂载在`prototype`上的属性和方法会被所有实例共享，这是原型继承实现代码复用的核心。

```js
// 原型继承核心示例
function Person(name) {
  this.name = name;
}
// 原型上的方法被所有实例共享
Person.prototype.greet = function() {
  console.log(`Hello, I'm ${this.name}`);
};
const john = new Person('John');
const lily = new Person('Lily');
john.greet(); // Hello, I'm John
lily.greet(); // Hello, I'm Lily
// 两个实例共享同一个greet方法
console.log(john.greet === lily.greet); // true
```

#### 解释 JavaScript 中 class 和 prototype 的区别

**答案**：`class`和`prototype`并非对立的概念，`class`是 ES6 引入的语法糖，其底层完全基于**原型（prototype）** 机制实现，二者的核心目标都是实现 JavaScript 的面向对象编程，仅语法形式和使用方式不同。

1. **prototype**：是 JavaScript 实现继承和对象复用的**原生底层机制**，通过构造函数的`prototype`属性、实例的`[[Prototype]]`、原型链实现继承，需要手动编写代码关联原型、修正`constructor`指向，语法相对繁琐，但能直观体现 JavaScript 的原生 OOP 特性。
2. **class**：是原型继承的**语法糖**，提供了更简洁、更符合传统基于类的 OOP 语言的语法形式，自动完成原型创建、`constructor`绑定、原型链关联等操作，无需手动处理底层细节，可读性和可维护性更高，但其运行逻辑与原生原型方式完全一致。

```js
// class实现继承
class Animal {
  constructor(name) {
    this.name = name;
  }
  speak() {
    return `${this.name} makes a sound.`;
  }
}
class Dog extends Animal {
  speak() {
    return `${this.name} barks.`;
  }
}
const dog1 = new Dog('Rex');
console.log(dog1.speak()); // Rex barks.

// 等价的prototype原生实现
function AnimalProto(name) {
  this.name = name;
}
AnimalProto.prototype.speak = function() {
  return `${this.name} makes a sound.`;
};
function DogProto(name) {
  AnimalProto.call(this, name);
}
// 关联原型链实现方法继承
DogProto.prototype = Object.create(AnimalProto.prototype);
// 修正constructor指向
DogProto.prototype.constructor = DogProto;
// 方法重写
DogProto.prototype.speak = function() {
  return `${this.name} barks.`;
};
const dog2 = new DogProto('Rex');
console.log(dog2.speak()); // Rex barks.
```

#### 手写 call、apply、bind

**答案**：`call`、`apply`、`bind`的核心作用都是**改变函数执行时的 this 指向**，区别在于参数传递方式和执行时机：`call`接收多个参数，`apply`接收数组参数，二者立即执行函数；`bind`接收多个参数，返回一个绑定了 this 的新函数，需手动调用执行。三者的实现均基于**将函数作为目标对象的临时方法**的核心原理。

```js
// 1. 手写call
Function.prototype.myCall = function(context) {
  context = context || window;
  const fn = Symbol('fn');
  context[fn] = this;
  const args = [...arguments].slice(1);
  const result = context[fn](...args);
  delete context[fn];
  return result;
};

// 2. 手写apply
Function.prototype.myApply = function(context) {
  context = context || window;
  const fn = Symbol('fn');
  context[fn] = this;
  let result;
  // apply接收数组参数
  if (arguments[1]) {
    result = context[fn](...arguments[1]);
  } else {
    result = context[fn]();
  }
  delete context[fn];
  return result;
};

// 3. 手写bind（返回函数，支持柯里化）
Function.prototype.myBind = function(context) {
  const _this = this;
  const args = [...arguments].slice(1);
  // 返回新函数，支持传入剩余参数
  return function Fn() {
    // 处理新函数被new调用的情况，this指向实例
    if (this instanceof Fn) {
      return new _this(...args, ...arguments);
    }
    return _this.myApply(context, [...args, ...arguments]);
  };
};

// 测试
function fn(a, b) {
  console.log(this.name, a + b);
}
const obj = { name: 'Tom' };
fn.myCall(obj, 1, 2); // Tom 3
fn.myApply(obj, [1, 2]); // Tom 3
const bindFn = fn.myBind(obj, 1);
bindFn(2); // Tom 3
```

面向对象编程（Object-Oriented Programming，简称OOP）是一种编程思想，其核心是将现实世界中的事物抽象为对象，程序的编写和操作均基于对象执行。在JavaScript中，OOP通过`class`（类）和`object`（对象）来封装数据与行为，使程序更易于复用、扩展和维护，同时降低代码的耦合度。

### 面向对象编程（OOP）定义

OOP的核心思想是“万物皆对象”，即将现实中的实体（如人、动物、工具等）抽象为程序中的对象。

对象是对现实事物的抽象概述，面向对象编程的核心就是将程序封装成一个个对象，程序的运行过程本质上是一系列对象之间相互协作、传递消息的过程。每个对象都包含描述自身状态的属性和执行动作的方法，这是对象的核心特征。JavaScript中的OOP并非严格意义上的面向对象（无真正的类继承，基于原型链实现），但通过ES6引入的`class`语法糖，使其更符合传统OOP的编程习惯。

### 类与对象

类与对象是JS面向对象的基础核心概念，二者紧密关联但本质不同。

类（Class）是对象的模板或蓝图，是定义对象属性和方法的抽象结构，用于描述对象“应该有什么”和“能做什么”。在JS中，通过`class`关键字定义类，类内部通常包含构造函数`constructor`，用于初始化对象的属性。

```javascript
// 定义类
class Person {
  // 构造函数，初始化实例属性
  constructor(name, age) {
    this.name = name; // 实例属性
    this.age = age;   // 实例属性
  }

  // 实例方法，属于对象的行为
  sayHello() {
    console.log(`Hello, I am ${this.name}`);
  }
}
```

对象（Object）是类的具体实例，是根据类的模板创建出来的实体，占用内存空间，具备类中定义的所有属性和方法。在JS中，通过`new`关键字配合类名，即可创建类的实例（对象）。

```javascript
// 创建对象（类的实例）
const p1 = new Person('Alice', 20);
p1.sayHello(); // 调用实例方法，输出：Hello, I am Alice
```

类与对象的核心关系：对象由类实例化而来，一个类可以创建多个不同的对象，所有对象共享类中定义的方法，但拥有各自独立的属性值。

### OOP三大特性

#### 封装

封装是OOP的核心特性之一，指将对象的属性和方法打包在类中，隐藏内部实现细节，仅暴露对外的操作接口，禁止外部直接访问或修改内部数据，确保数据安全。

JS中实现封装的主要方式的是使用私有属性（ES2022引入，语法为`#属性名`），私有属性仅能在类内部访问，外部无法直接操作；同时可通过`getter/setter`方法（访问器）提供对外的读写接口，还可在接口中添加校验逻辑，控制属性的读写权限。

```javascript
class Person {
  // 定义私有属性，仅类内部可访问
  #name;

  // 构造函数初始化私有属性
  constructor(name) {
    this.#name = name;
  }

  // 现代写法：属性式getter，获取私有属性值
  get name() {
    return this.#name;
  }

  // 现代写法：属性式setter，设置私有属性值，添加校验逻辑
  set name(value) {
    // 校验：仅当传入的值非空时，才修改私有属性
    if (value.length > 0) {
      this.#name = value;
    }
  }

  // 类内部访问私有属性的方法
  sayHello() {
    console.log(`Hi, I'm ${this.#name}`);
  }
}

// 使用示例
const p = new Person("Tom");
p.name = "Jerry"; // 调用setter，修改私有属性
console.log(p.name); // 调用getter，获取私有属性，输出：Jerry
p.#name = "Mike"; // 报错：私有属性无法外部直接访问
```

封装的核心好处：保护数据安全，防止外部随意修改属性；通过访问器控制属性读写权限；降低外部与类内部的耦合度，外部无需关心内部实现，仅需调用暴露的接口；便于调试，可在访问器中添加调试信息。

#### 继承

继承是OOP的重要特性，指子类可以继承父类的属性和方法，同时子类可根据需求扩展自身的属性和方法，实现代码复用，减少冗余代码。

JS中通过`extends`关键字实现类的继承，子类使用`super()`方法调用父类的构造函数，继承父类的实例属性；若子类需要重写父类的方法，直接在子类中定义同名方法即可。

```javascript
// 父类
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  sayHello() {
    console.log(`Hello, I am ${this.name}, ${this.age} years old`);
  }
}

// 子类继承父类
class Student extends Person {
  // 子类构造函数，调用父类构造函数继承属性
  constructor(name, age, studentId) {
    super(name, age); // 必须先调用super()，再定义子类自身属性
    this.studentId = studentId; // 子类扩展的属性
  }

  // 子类扩展的方法
  study() {
    console.log(`${this.name} is studying, studentId: ${this.studentId}`);
  }

  // 子类重写父类的sayHello方法
  sayHello() {
    console.log(`Hello, I am student ${this.name}, studentId: ${this.studentId}`);
  }
}

// 使用示例
const s1 = new Student('Bob', 18, '2024001');
s1.sayHello(); // 调用重写后的方法，输出：Hello, I am student Bob, studentId: 2024001
s1.study(); // 调用子类扩展方法，输出：Bob is studying, studentId: 2024001
console.log(s1.age); // 继承父类的属性，输出：18
```

#### 多态

多态是OOP的特性之一，指不同类的对象可以以统一的方式调用同名方法，且根据对象的具体类型，执行不同的方法逻辑。

JS中没有传统面向对象语言（如Java）中的多态语法（如接口、重载），其多态主要通过“鸭子类型”实现——即不关注对象的具体类型，只关注对象是否具备对应的方法，只要对象有同名方法，就可以统一调用，执行各自的逻辑。

```javascript
// 定义不同的类，均包含say方法
class Dog {
  say() {
    console.log('Woof! Woof!');
  }
}

class Cat {
  say() {
    console.log('Meow! Meow!');
  }
}

class Bird {
  say() {
    console.log('Chirp! Chirp!');
  }
}

// 统一调用方法的函数（体现多态）
function animalSay(animal) {
  animal.say(); // 不关注animal的具体类型，只要有say方法即可调用
}

// 使用示例
const dog = new Dog();
const cat = new Cat();
const bird = new Bird();

animalSay(dog); // 输出：Woof! Woof!
animalSay(cat); // 输出：Meow! Meow!
animalSay(bird); // 输出：Chirp! Chirp!
```

### JS对象的分类

根据创建主体和用途，JS中的对象可分为三类，各类对象的作用和示例如下：

内建对象：由JS语言本身提供，无需手动创建即可直接使用，用于完成基础的编程需求，常见的有`Object`、`String`、`Array`、`Number`、`Date`等。例如`let arr = new Array(1,2,3)`，`arr`就是内建对象`Array`的实例。

宿主对象：由运行环境（如浏览器）提供，用于与运行环境交互，常见的有浏览器提供的`BOM`（浏览器对象模型，如`window`、`location`）和`DOM`（文档对象模型，如`document`、`div`元素对象）。例如`window.alert('hello')`，`window`就是宿主对象。

自定义对象：由开发人员根据业务需求，通过`class`、`function`或字面量方式创建的对象，用于实现具体的业务逻辑。例如前面定义的`Person`类创建的`p1`对象，就是自定义对象。

### 类的属性和方法

JS中类的属性和方法，根据归属可分为实例属性/方法和静态属性/方法，二者的归属、用途和使用方式均不同。

#### 实例属性与方法

实例属性与方法属于类的实例（对象），每个对象都拥有独立的实例属性，共享实例方法（方法本身不重复创建，对象通过原型链访问）。实例属性通常在`constructor`构造函数中定义，使用`this.属性名`语法；实例方法直接在类体中定义，无需加`static`关键字。

```javascript
class Dog {
  // 实例属性：在constructor中定义，属于每个Dog对象
  constructor(name) {
    this.name = name;
  }

  // 实例方法：直接定义在类体中，属于每个Dog对象
  bark() {
    console.log(`${this.name} says woof!`);
  }
}

// 使用示例
const dog1 = new Dog('Buddy');
const dog2 = new Dog('Max');

console.log(dog1.name); // 输出：Buddy（dog1的实例属性）
console.log(dog2.name); // 输出：Max（dog2的实例属性，与dog1独立）
dog1.bark(); // 输出：Buddy says woof!
dog2.bark(); // 输出：Max says woof!
```

#### 静态属性与方法

静态属性与方法属于类本身，不属于任何实例对象，不能通过对象调用，只能通过类名直接调用；静态属性和方法通常用于定义类级别的工具属性或工具方法，所有实例共享这一份静态内容。

JS中通过`static`关键字定义静态属性和方法，语法为`static 属性名 = 值`、`static 方法名() {}`。

```javascript
class Tool {
  // 静态属性：属于Tool类，不属于实例
  static version = '1.0.0';

  // 静态方法：属于Tool类，不属于实例
  static logInfo() {
    console.log(`Tool Version: ${Tool.version}`);
  }
}

// 使用示例
console.log(Tool.version); // 正确：通过类名调用静态属性，输出：1.0.0
Tool.logInfo(); // 正确：通过类名调用静态方法，输出：Tool Version: 1.0.0

const tool1 = new Tool();
console.log(tool1.version); // 错误：无法通过对象调用静态属性，输出undefined
tool1.logInfo(); // 错误：无法通过对象调用静态方法，报错
```

#### 方法定义位置

对象中方法的定义位置不同。

1. **原型方法（`method() {}`）**

```js
class MyClass {
  method() {
    console.log('原型方法');
  }
}
```

- 定义位置：类的原型上（`MyClass.prototype.method`）
- 不是在构造函数中定义的
- 所有实例共享
- 正常调用（如 `obj.protoMethod()`），`this` 指向实例

```js
const obj = new MyClass();
obj.protoMethod(); // this === obj 

const f = obj.funcExpr;
f(); // this === undefined（在严格模式下） this === window （非严格模式下）
```

2. **实例方法（字段定义：`method = function() {}` 或 `method = () => {}`）**

```js
class MyClass {
  method1 = function() {
    console.log('函数表达式');
  }
}
```

- 定义位置：构造函数内部

  > 因为 JavaScript 会把这些“字段初始化器”转化为构造函数里的赋值语句

- 每个实例一份，每次实例化的时候都会定义一次。

- `method2`（箭头函数）自动绑定 `this`，而 `method1` 不会

- `this`和原型方法一样。

```js
class MyClass {
  method2 = () => {
    console.log('箭头函数');
  }
}
// 等价于
class MyClass {
    constructor (){
        this.method2 = () = >{
            console.log('箭头函数');
        }
    }
}
```

- 定义位置：构造函数内部
- 每个实例一份，每次实例化的时候都会定义一次。
- `method2`（箭头函数）自动绑定 `this`，
- `this`根据外作用域决定，也就是`constructor`， `this === 实例对象`，因此无论怎么调用，`this` 都不会变

```js
const obj = new MyClass();
const f = obj.arrowFunc;
f(); // this === obj（永远是实例）
```

**3. 静态方法（`static method() {}`）**

```js
class MyClass {
  static method() {
    console.log('静态方法');
  }
}
```

- 定义位置：类本身（`MyClass.method`），而不是实例或构造函数里，只定义一次。
- 不是在构造函数中定义的
- 只能通过类调用，不能通过实例调用，`MyClass.staticMethod()`，此时 `this === MyClass`

| -------------- | ---------------------------- |

| 箭头函数       | 定义时绑定 `this`，永不改变  |

### 对象和函数的核心关联

在JS中，对象和函数是相互关联、不可分割的，二者的关系决定了原型机制的基础。

JS中所有对象都有一个内部隐藏属性`[[Prototype]]`（通常通过`__proto__`访问，注意`__proto__`并非标准语法，但浏览器普遍支持），这个属性指向另一个对象，被指向的这个对象就是当前对象的“原型”。当访问对象的某个属性时，如果对象本身没有定义该属性，JS引擎会自动去它的原型对象上查找；如果原型对象上也没有该属性，就继续去原型的原型上查找，这个层层查找的机制就是“原型链查找”。原型本身也是对象，因此也拥有自己的`[[Prototype]]`，这样就形成了一条链式结构，直到最顶层的原型指向`null`，原型链终止。

最基础的原型链关系可通过以下代码验证：

```javascript
// 定义类（本质是构造函数的语法糖）
class Person {}
// 创建实例对象
const p = new Person();
// 实例对象的__proto__ 指向其构造函数的prototype
console.log(p.__proto__ === Person.prototype); // true
```

#### Object和Function的特殊关系

`Object`和`Function`是JS中两个特殊的构造器，而<span style="color:#409eff">构造器本身也是一个实例对象</span>，这种双重身份是理解原型链顶层结构的关键。

> 由于构造器本身也是一个对象，任何一个构造器既有 prototype， 也有 [[Prototype]]及 `__proto__`， 两者指向不一定相同。

```javascript
// Object 是由 Function 构造出来的，因此Object的__proto__指向Function.prototype
console.log(Object.__proto__ === Function.prototype); // true

// Function 是由自身构造出来的（自举特性），因此Function的__proto__指向自身的prototype
console.log(Function.__proto__ === Function.prototype); // true

// 函数对象的原型最终继承自 Object.prototype，形成完整原型链
console.log(Function.prototype.__proto__ === Object.prototype); // true

// 根据上面的关系推导，Object的__proto__（Function.prototype）的__proto__指向Object.prototype
console.log(Object.__proto__.__proto__ === Object.prototype); // true

// Object.prototype是所有对象的顶层原型，其__proto__指向null，原型链终止
console.log(Object.prototype.__proto__ === null); // true
```

对上述关系的进一步解读：

1. `Object`是普通对象的构造器，负责创建普通对象，但`Object`本身是一个函数，因此它是`Function`的实例，其`__proto__`指向`Function.prototype`。
2. `Function`是所有函数的构造器，负责创建所有函数对象，同时`Function`本身也是一个函数，具备自举特性，即自己构造自己，因此其`__proto__`指向自身的`prototype`。
3. `Function.prototype`是所有函数对象的原型，包括`Object`和`Function`自身；而`Object.prototype`是所有对象的顶层原型，所有对象的原型链最终都会指向它，再由它指向`null`终止。
4. 函数本身也是对象，因此函数对象的原型链也会指向`Object.prototype`，最终终止于`null`。

JS中通过`typeof`运算符区分函数对象和普通对象，其内部本质是检测对象是否具备`[[Call]]`内部方法——具备`[[Call]]`方法的是函数对象，`typeof`返回`"function"`；不具备的是普通对象，`typeof`返回`"object"`。

```javascript
// 普通对象：无[[Call]]方法，typeof返回object
console.log(typeof {}); // "object"

// 函数对象：有[[Call]]方法，typeof返回function
console.log(typeof function(){}); // "function"
console.log(typeof Object); // "function"（Object是构造器，属于函数对象）
console.log(typeof Function); // "function"（Function是构造器，属于函数对象）
```

补充核心要点：在JS中，判断一个对象是不是某个构造器的实例，只看一件事——该构造器的`prototype`属性是否出现在该对象的原型链上，这也是后面`instanceof`运算符的核心原理。

### 构造函数和普通函数的区别

构造函数和普通函数的核心区别在于是否具备`[[Construct]]`内部方法，这也决定了二者能否通过`new`关键字调用，进而创建实例对象。

核心区别解析：

1. 构造函数：除了具备函数对象必备的`[[Call]]`方法（可直接调用），还具备`[[Construct]]`内部方法，因此可以通过`new`关键字调用，用于创建实例对象。
2. 普通函数：具备`[[Call]]`方法（可直接调用），但不具备`[[Construct]]`内部方法，因此不能通过`new`关键字调用，强行调用会报错。

#### 不同函数类型的特性区分

JS中不同方式创建的函数，其是否具备`[[Call]]`、`[[Construct]]`方法，以及能否通过`new`调用的情况不同，具体可分为以下几类（去掉表格，用文字详细说明）：

- 普通函数（`function f(){}`）：具备`[[Call]]`方法，具备`[[Construct]]`方法，可通过`new`关键字调用，能创建实例对象。

- 类（`class`）：类本身不能直接调用（无`[[Call]]`方法），但具备`[[Construct]]`方法，可通过`new`关键字调用，能创建实例对象，本质是构造函数的语法糖。

- 箭头函数（`() => {}`）：具备`[[Call]]`方法，不具备`[[Construct]]`方法，不能通过`new`关键字调用，强行调用会报错。

- 方法简写（`{ foo(){} }`）：具备`[[Call]]`方法，不具备`[[Construct]]`方法，不能通过`new`关键字调用，强行调用会报错。

- `Function.prototype.bind`返回的函数：具备`[[Call]]`方法，不具备`[[Construct]]`方法，不能通过`new`关键字调用，强行调用会报错。

- Generator函数（`function* f(){}`）：具备`[[Call]]`方法，不具备`[[Construct]]`方法，不能通过`new`关键字调用，强行调用会报错。

- Async函数（`async function f(){}`）：具备`[[Call]]`方法，不具备`[[Construct]]`方法，不能通过`new`关键字调用，强行调用会报错。

代码示例验证：

```javascript
// 普通函数（构造函数）：可通过new调用
function Foo() {
  this.x = 1;
}
const f = new Foo();   // OK，创建实例对象f
console.log(f.x); // 1

// 箭头函数：不能通过new调用
const bar = () => {};
new bar();             // TypeError: bar is not a constructor（报错）

// 类：可通过new调用，不能直接调用
class Person {}
const p = new Person(); // OK
Person(); // TypeError: Class constructor Person cannot be invoked without 'new'（报错）
```

#### constructor属性的作用

`constructor`属性返回自身构造器，是区分构造器函数和普通函数的核心标准，同时也是实例对象追溯其构造函数的重要依据，其核心特性如下：

1. 构造器函数（包括普通函数、类）在创建时，会自动获得一个`prototype`属性，该属性指向一个原型对象；这个原型对象上默认会有一个`constructor`属性，指向构造器函数本身。
2. 实例对象通过原型链可以访问到原型对象上的`constructor`属性，进而追溯到自身的构造函数。
3. 普通函数（不具备`[[Construct]]`的函数，如箭头函数、方法简写等）没有`prototype`属性，也没有`constructor`属性，但它们依然是实例对象，因此具备`__proto__`属性，可通过原型链追溯到顶层原型。

代码示例验证：

```javascript
// Object的constructor指向Function（Object是Function的实例）
console.log(Object.constructor === Function); // true

// 数组实例的constructor指向Array（数组是Array的实例）
console.log([].constructor === Array); // true

// Array的constructor指向Function（Array是Function的实例）
console.log(Array.constructor === Function); // true

// Function的constructor指向自身（Function自举特性）
console.log(Function.constructor === Function); // true

// Object的constructor 等同于 Object.__proto__.constructor（均指向Function）
console.log(Object.constructor === Object.__proto__.constructor); // true
```

#### 构造函数的核心总结

1. 构造函数的本质是具备`[[Construct]]`方法的函数，可通过`new`关键字调用，用于创建实例对象。
2. 类（`class`）是构造函数的语法糖，本质上还是函数，具备构造函数的所有特性（可通过`new`调用，有`prototype`和`constructor`属性）。
3. `Function`是所有函数的构造器，它本身也是函数，具备自举特性（自己构造自己），核心关系链如下：

Function（构造所有函数）→ class / 普通函数（本质是Function的实例）→ 实例对象（由构造函数/class生成）

### new关键字的原理

理解了原型、构造函数和对象的关系后，就能清晰掌握`new`关键字的底层原理——`new`的核心作用是通过构造函数创建实例对象，并建立实例对象与构造函数原型之间的关联（即原型链的基础）。

当我们使用`new`关键字调用构造函数创建实例时，JS引擎内部大致会执行以下4个步骤，每一步都与原型机制紧密相关：

第一步：创建一个空对象。这个空对象就是即将生成的实例对象，后续会为其添加属性和方法。

模拟代码：`let obj = {};`

第二步：将这个空对象的原型（`[[Prototype]]`，即`__proto__`）指向构造函数的`prototype`属性。这一步是核心，它建立了实例对象与构造函数原型之间的关联，为后续原型链查找奠定基础。

模拟代码：`obj.__proto__ = Person.prototype;`

第三步：执行构造函数，并将构造函数内部的`this`绑定到刚创建的空对象上。这样一来，构造函数内部通过`this`定义的属性和方法，都会被添加到实例对象上。

模拟代码：`let result = Person.call(obj, "Alice");`（通过call方法绑定this）

第四步：判断构造函数的返回值，并最终返回实例对象。这里有两种情况：

1. 如果构造函数返回的是一个对象（包括数组、函数、普通对象等，`null`除外），则直接返回该对象，此时`new`关键字创建的空对象会被丢弃；
2. 如果构造函数返回的不是对象（如基本数据类型、无返回值），则返回刚创建的空对象（即绑定了`this`的实例对象）。

模拟代码：`return (typeof result === "object" && result !== null) ? result : obj;`

```javascript
// 手写myNew，模拟new关键字原理
// 参数：Constructor（构造函数），...args（构造函数的参数，剩余参数接收）
function myNew(Constructor, ...args) {
  // 1. 创建空对象，并将其原型指向构造函数的prototype（替代obj.__proto__ = Constructor.prototype）
  let obj = Object.create(Constructor.prototype);
  
  // 2. 执行构造函数，将this绑定到新创建的obj上，传入参数args
  let result = Constructor.apply(obj, args);
  
  // 3. 判断返回值，返回对应的对象
  return (typeof result === "object" && result !== null) ? result : obj;
}
```

### instanceof运算符的原理

`instanceof`运算符是JS中用于判断实例对象与构造函数之间关系的核心运算符，其底层原理完全基于原型链——判断构造函数的`prototype`属性是否出现在实例对象的原型链上的任何位置。

核心语法：`left instanceof right`，其中`left`是实例对象，`right`是构造函数（或类）。

运算规则：如果`right.prototype`出现在`left`的原型链上（即`left.__proto__`、`left.__proto__.__proto__`... 中存在等于`right.prototype`的对象），则返回`true`，表示`left`是`right`的实例；否则返回`false`。

补充说明：`instanceof`的判断与构造函数本身无关，只与构造函数的`prototype`属性和实例对象的原型链有关；如果修改了`prototype`属性的指向，会改变`instanceof`的判断结果。

#### 手写myInstanceof函数（模拟instanceof原理）

根据`instanceof`的底层原理，我们可以手写一个`myInstanceof`函数，模拟其判断逻辑，核心是遍历实例对象的原型链，判断是否能找到构造函数的`prototype`。

```javascript
// 手写myInstanceof，模拟instanceof原理
// 参数：left（实例对象），right（构造函数/类）
function myInstanceof(left, right) {
  // 1. 获取实例对象的原型（使用Object.getPrototypeOf方法，比__proto__更标准）
  let proto = Object.getPrototypeOf(left);
  // 2. 获取构造函数的prototype对象
  let prototype = right.prototype; 
 
  // 3. 遍历原型链，判断是否能找到构造函数的prototype
  while (true) {
    // 原型链终止于null，若遍历到null仍未找到，返回false
    if (!proto) return false;
    // 若当前原型等于构造函数的prototype，返回true
    if (proto === prototype) return true;
    // 若未找到，继续遍历上一层原型（proto的原型）
    proto = Object.getPrototypeOf(proto);
  }
}
```

### 原型与原型链核心总结

1. 原型：每个对象都有`[[Prototype]]`（`__proto__`），指向其原型对象，原型对象可共享属性和方法，实现代码复用。
2. 原型链：由对象的`[[Prototype]]`层层串联形成的链式结构，顶层为`Object.prototype`，最终指向`null`，是属性查找和继承的核心机制。
3. 核心关联：`Object`和`Function`是原型链的顶层核心，`Function`构造所有函数，`Object.prototype`是所有对象的顶层原型，二者相互关联。
4. 关键工具：`new`关键字用于创建实例并建立原型关联，`instanceof`用于判断原型链关系，二者均基于原型机制实现。

## 3.JS创建对象的多种方式及优缺点

在JavaScript中，对象是核心数据类型之一，创建对象的方式有多种，不同方式适用于不同场景，各有优劣。

### 工厂模式

工厂模式是创建对象的基础方式，核心思路是通过一个普通函数（工厂函数）封装对象的创建过程，函数内部创建空对象、添加属性和方法，最终返回该对象，实现批量创建相似对象。

```javascript
// 工厂模式创建对象（JavaScript代码）
function createPerson(name, age) {
  // 1. 创建空对象
  let obj = {};
  // 2. 给对象添加属性和方法
  obj.name = name;
  obj.age = age;
  obj.sayHello = function() {
    console.log(`Hello, I'm ${this.name}, ${this.age} years old`);
  };
  // 3. 返回创建的对象
  return obj;
}

// 批量创建实例对象
const person1 = createPerson('Alice', 20);
const person2 = createPerson('Bob', 18);

person1.sayHello(); // Hello, I'm Alice, 20 years old
person2.sayHello(); // Hello, I'm Bob, 18 years old
```

优点：实现简单，逻辑清晰，可快速批量创建结构相似的对象，减少代码冗余。

缺点：对象无法识别具体类型，所有通过工厂函数创建的实例，其原型都指向`Object.prototype`，无法区分是“Person”实例还是普通`Object`实例，无法利用原型实现方法共享。

### 构造函数模式

构造函数模式基于构造函数的特性创建对象，核心思路是定义一个构造函数，通过`new`关键字调用构造函数，自动创建对象、绑定`this`、建立原型关联，无需手动创建和返回对象，解决工厂模式对象无法识别类型的问题。

```javascript
// 构造函数模式创建对象（JavaScript代码）
function Person(name, age) {
  // 无需手动创建空对象，new关键字会自动创建
  // this绑定到新创建的对象上，给对象添加属性
  this.name = name;
  this.age = age;
  // 给对象添加方法
  this.sayHello = function() {
    console.log(`Hello, I'm ${this.name}, ${this.age} years old`);
  };
}

// 通过new关键字调用构造函数，创建实例对象
const person1 = new Person('Alice', 20);
const person2 = new Person('Bob', 18);

person1.sayHello(); // Hello, I'm Alice, 20 years old
person2.sayHello(); // Hello, I'm Bob, 18 years old

// 可识别对象具体类型
console.log(person1 instanceof Person); // true（确认是Person实例）
console.log(person1 instanceof Object); // true（所有对象都是Object实例）
```

优点：实例可识别为具体的类型（如Person实例），通过`instanceof`可精准判断对象归属，逻辑更贴合面向对象思想，无需手动管理对象的创建和返回。

缺点：每次通过`new`创建实例时，构造函数内部的方法都会被重新创建一次，即每个实例都拥有独立的方法副本（如person1.sayHello和person2.sayHello是两个不同的函数对象），造成内存浪费，无法实现方法共享。

#### 构造函数模式优化

针对构造函数模式“方法重复创建”的缺点，优化思路是将需要共享的方法提取到构造函数外部，通过全局函数定义方法，再在构造函数内部引用该方法，实现方法共享，减少内存浪费。

```javascript
// 构造函数模式优化（JavaScript代码）
// 1. 提取共享方法，定义为全局函数
function sayHello() {
  console.log(`Hello, I'm ${this.name}, ${this.age} years old`);
}

// 2. 构造函数内部引用全局方法
function Person(name, age) {
  this.name = name;
  this.age = age;
  // 所有实例共享同一个sayHello方法，无需重复创建
  this.sayHello = sayHello;
}

// 创建实例对象
const person1 = new Person('Alice', 20);
const person2 = new Person('Bob', 18);

person1.sayHello(); // Hello, I'm Alice, 20 years old
person2.sayHello(); // Hello, I'm Bob, 18 years old

// 验证方法共享（两个实例的sayHello指向同一个函数对象）
console.log(person1.sayHello === person2.sayHello); // true
```

优化核心：将共享方法定义在构造函数外部，所有实例引用同一个全局方法，解决了每次创建实例时方法重复创建的问题，节省内存。

缺点：全局函数在一定程度上违背了面向对象的封装性原则。

### 原型模式

原型模式基于原型机制创建对象，核心思路是利用构造函数的`prototype`属性，将需要共享的属性和方法定义在原型对象上，所有通过该构造函数创建的实例，都会通过原型链共享原型上的属性和方法，彻底解决方法重复创建的问题。

```javascript
// 原型模式创建对象（JavaScript代码）
function Person() {}

// 将属性和方法定义在构造函数的prototype（原型对象）上
Person.prototype.name = 'Unknown';
Person.prototype.age = 0;
Person.prototype.sayHello = function() {
  console.log(`Hello, I'm ${this.name}, ${this.age} years old`);
};

// 创建实例对象（实例本身无属性和方法，通过原型链访问原型上的内容）
const person1 = new Person();
const person2 = new Person();

// 访问原型上的方法和属性
person1.sayHello(); // Hello, I'm Unknown, 0 years old
person2.sayHello(); // Hello, I'm Unknown, 0 years old

// 验证方法共享（所有实例共享原型上的sayHello方法）
console.log(person1.sayHello === person2.sayHello); // true
```

优点：所有实例共享原型上的属性和方法，方法不会被重复创建，极大节省内存，符合代码复用的原则。

缺点：1.  所有实例共享原型上的属性和方法，若修改一个实例的原型属性，会影响所有其他实例（因为原型属性是共享的）；2.  无法在创建实例时初始化参数（构造函数为空，无法传递参数给原型属性赋值），灵活性较差。

### 组合模式

针对原型模式“无法初始化参数”的缺点，优化思路是结合构造函数和原型模式的特点：在构造函数内部定义实例私有属性（可初始化参数），在原型对象上定义共享方法，实现“私有属性+共享方法”的结构，同时让封装逻辑更清晰。

针对上一步优化“丢失`constructor`属性”的缺点，进一步优化思路是：在重写原型对象时，手动指定`constructor`属性的值为对应的构造函数，确保实例能通过`constructor`追溯到其构造函数，同时保留“私有属性+共享方法”的优势

组合模式是应用最广泛的创建对象方式，核心思路是“构造函数+原型模式”的完美结合：通过构造函数定义实例私有属性（实现参数初始化、属性独立），通过原型对象定义共享方法和属性（实现方法共享、节省内存），兼顾灵活性和复用性，解决了前面几种模式的核心缺点。

```javascript
// 组合模式创建对象（JavaScript代码）
function Person(name, age) {
  // 1. 构造函数：定义实例私有属性，可通过参数初始化
  this.name = name;
  this.age = age;
  this.friends = ['Tom', 'Jerry']; // 私有属性，每个实例独立拥有
}

// 2. 原型模式：定义共享方法，所有实例共享
Person.prototype = {
  constructor: Person, // 手动绑定constructor，避免丢失
  sayHello: function() {
    console.log(`Hello, I'm ${this.name}, ${this.age} years old`);
  },
  showFriends: function() {
    console.log(`My friends are: ${this.friends}`);
  }
};

// 创建实例对象
const person1 = new Person('Alice', 20);
const person2 = new Person('Bob', 18);

// 验证：私有属性独立（修改一个实例的friends，不影响另一个）
person1.friends.push('Mike');
person1.showFriends(); // My friends are: Tom,Jerry,Mike
person2.showFriends(); // My friends are: Tom,Jerry

// 验证：方法共享，constructor正常
console.log(person1.sayHello === person2.sayHello); // true
console.log(person1.constructor === Person); // true
```

优点：兼顾灵活性和复用性，该共享的方法（原型上）共享，该私有的属性（构造函数内）私有，解决了前面几种模式的缺点，是开发中最常用、最推荐的创建对象方式。

缺点：构造函数和原型的定义是分离的，没有完全封装在同一个地方，开发者需要分别维护构造函数（私有属性）和原型（共享方法），对代码封装性有更高要求的场景不够友好。

### 动态原型模式

动态原型模式是组合模式的进一步优化，核心思路是将原型方法的定义封装在构造函数内部，通过判断条件（方法是否存在）动态初始化原型，确保原型方法只被创建一次，同时实现构造函数和原型的“统一封装”，解决组合模式封装性不足的问题。

注意：使用动态原型模式时，<span style="color:#FAAD14">不能用对象字面量重写原型，否则会破坏实例与原型的关联，导致方法无法访问</span>。

```javascript
// 动态原型模式创建对象（JavaScript代码）
function Person(name, age) {
  // 1. 构造函数：定义实例私有属性，初始化参数
  this.name = name;
  this.age = age;

  // 2. 动态初始化原型：判断sayHello方法是否存在，不存在则添加到原型
  // 仅在第一次创建实例时执行（第一次new时，原型上无sayHello方法）
  if (typeof this.sayHello !== 'function') {
    Person.prototype.sayHello = function() {
      console.log(`Hello, I'm ${this.name}, ${this.age} years old`);
    };
  }
}

// 创建实例对象
const person1 = new Person('Alice', 20);
const person2 = new Person('Bob', 18);

// 验证：方法共享，封装在构造函数内部
person1.sayHello(); // Hello, I'm Alice, 20 years old
person2.sayHello(); // Hello, I'm Bob, 18 years old
console.log(person1.sayHello === person2.sayHello); // true
```

错误示例（用对象字面量重写原型，导致报错）：

```javascript
function Person(name) {
  this.name = name;
  // 错误：用对象字面量重写原型，破坏实例与原型的关联
  if (typeof this.getName !== 'function') {
    Person.prototype = {
      constructor: Person,
      getName: function() {
        console.log(this.name);
      }
    };
  }
}

// 第一次创建实例：person1的原型指向原原型（无getName方法）
var person1 = new Person('heyi');
// 第二次创建实例：Person.prototype被重写，person2的原型指向新原型（有getName方法）
var person2 = new Person('heyi2');

person1.getName(); // 报错：person1.getName is not a function（原原型无该方法）
person2.getName(); // 正常执行：heyi2
```

错误原因：第一次执行`new Person('heyi')`时，`new`的执行过程为：1. 新建空对象；2. 将对象的原型指向`Person.prototype`（原原型，无`getName`方法）；3. 执行构造函数，用对象字面量重写`Person.prototype`（指向新原型）；4. 返回空对象（person1）。此时person1的原型依然是原原型，而新原型被person2继承，因此person1无法访问`getName`方法。

正确示例（用对象字面量重写原型的兼容写法）：

```javascript
function Person(name) {
  this.name = name;
  if (typeof this.getName !== "function") {
    // 重写原型，并手动绑定constructor
    Person.prototype = {
      constructor: Person,
      getName: function () {
        console.log(this.name);
      }
    };
    // 重新调用构造函数，让当前实例的原型指向新原型
    return new Person(name);
  }
}

var person1 = new Person('heyi');
var person2 = new Person('heyi2');

person1.getName(); // heyi（正常执行）
person2.getName(); // heyi2（正常执行）
```

优点：将构造函数（私有属性）和原型（共享方法）封装在同一个函数内部，代码封装性更好，同时保留组合模式的所有优势，原型方法仅被创建一次，节省内存。

缺点：逻辑稍复杂，需要注意避免用对象字面量重写原型，否则会破坏实例与原型的关联，导致方法无法访问。

知识点对应问题：组合模式的核心优势和缺点是什么？动态原型模式是为了解决什么问题？使用动态原型模式时的关键注意事项是什么？用对象字面量重写原型会导致什么问题，如何解决？

### 构造函数与原型上方法的区别

#### 1. 函数里的“方法”默认放哪？

如果在构造函数内部通过`this.方法名 = function() {}`的方式定义方法，该方法会成为实例的自有属性，每次`new`创建实例时，都会创建一份新的函数对象，不在原型上，无法被实例共享。

```javascript
function Fn() {
  // 构造函数内部定义的方法，是实例自有属性
  this.say = function () {
    console.log('Hello');
  };
}
const a = new Fn();
const b = new Fn();

// 两个实例的say方法是不同的函数对象，不共享
console.log(a.say === b.say); // false
// say是a的自有属性，不在原型上
console.log(Fn.prototype.say); // undefined
```

#### 2. 什么会在原型对象上？

只有显式将方法或属性定义在`构造函数.prototype`上，或者通过ES6 class的方法语法（不加`static`关键字）定义的方法，才会放在原型对象上，所有实例通过原型链共享该方法或属性。

```javascript
// 方式1：显式定义在构造函数的prototype上
function Fn() {}
Fn.prototype.say = function () {
  console.log('Hello');
};
const a = new Fn();
console.log(a.say === Fn.prototype.say); // true（实例共享原型上的方法）

// 方式2：ES6 class的方法语法（不加static，默认在原型上）
class Fn {
  say() {
    console.log('Hello');
  }
}
const a = new Fn();
console.log(a.say === Fn.prototype.say); // true
```

知识点对应问题：构造函数内部定义的方法和原型上定义的方法，核心区别是什么？ES6 class中，不加`static`的方法会放在哪里？

### 核心总结

1. 工厂模式：简单易实现，但无法识别对象类型，无方法共享；
2. 构造函数模式：可识别对象类型，但方法重复创建，浪费内存；
3. 原型模式：方法共享，节省内存，但无法初始化参数，属性共享易冲突；
4. 组合模式：私有属性+共享方法，兼顾灵活与复用，是开发中最常用的方式；
5. 动态原型模式：组合模式的优化，统一封装构造函数和原型，需注意避免重写原型的陷阱。

选择创建对象的方式时，优先考虑组合模式和动态原型模式，根据场景需求灵活选择，核心是兼顾代码复用、内存占用和封装性。

## 4.JS继承的多种方式及优缺点

在JavaScript中，继承是面向对象编程的核心特性之一，用于实现代码复用、建立类与类之间的层级关系。与创建对象的多种方式对应，JS的继承方式也有多种，不同方式基于原型、构造函数等底层机制实现，各有优劣。

### 原型链继承

原型链继承是JS中最基本的继承方式，核心思路是通过让子类的原型对象等于父类的实例，使子类实例能通过原型链访问到父类的属性和方法，从而实现继承。其本质是利用原型链的查找机制，将父类的实例作为子类的原型，搭建子类与父类之间的继承关联。

```javascript
// 原型链继承（JavaScript代码）
// 父类：Person
function Person(name) {
  this.name = name;
  this.friends = ['Tom', 'Jerry']; // 引用类型属性
}

// 父类原型上的方法
Person.prototype.sayHello = function() {
  console.log(`Hello, I'm ${this.name}`);
};

// 子类：Student
function Student(age) {
  this.age = age; // 子类自身属性
}

// 核心：让子类的原型等于父类的实例，建立原型链继承
Student.prototype = new Person('Alice');

// 子类实例
const student1 = new Student(18);
const student2 = new Student(20);

// 访问父类的属性和方法
student1.sayHello(); // Hello, I'm Alice（访问父类原型方法）
console.log(student1.name); // Alice（访问父类实例属性）
console.log(student1.age); // 18（访问子类自身属性）
```

原型链继承存在明显的问题，最突出的是引用类型的属性被所有子类实例共享，修改一个实例的引用类型属性，会影响所有其他子类实例，示例如下：

```javascript
// 修改student1的friends属性（引用类型）
student1.friends.push('Mike');

// 查看两个实例的friends属性，均发生变化（共享属性被修改）
console.log(student1.friends); // ['Tom', 'Jerry', 'Mike']
console.log(student2.friends); // ['Tom', 'Jerry', 'Mike']
```

优点：1.  实现简单，逻辑清晰，仅需将子类原型指向父类实例，即可实现继承；2.  子类实例可以继承父类的原型上的属性和方法，也可以继承父类的实例属性；3.  实例之间不会共享父类构造函数中定义的基本数据类型属性（仅共享原型上的属性和引用类型实例属性）。

缺点：1.  构造函数会被调用两次，一次是在创建子类原型（new Person('Alice')）的时候，一次是在子类构造函数内部（若子类构造函数中调用父类构造函数），这可能导致某些父类属性被重复创建；2.  **引用类型的属性会被所有子类实例共享，修改一个实例的引用类型属性，会影响所有其他实例**；3.  无法在创建子类实例时，向父类构造函数传递参数，灵活性较差。

知识点对应问题：原型链继承的核心思路是什么？原型链继承最突出的问题是什么？为什么原型链继承中引用类型属性会被所有子类实例共享？

### 借用构造函数（经典继承）

借用构造函数（又称经典继承），核心思路是通过在子类构造函数中调用父类构造函数来实现继承。利用`call`或`apply`方法，将父类构造函数内部的`this`绑定到子类实例上，使子类实例能继承父类构造函数中定义的实例属性和方法，从根源上解决原型链继承中引用类型属性共享的问题。

```javascript
// 借用构造函数实现继承（解决引用类型共享问题）（JavaScript代码）
function Parent () {
    this.names = ['heyi', 'heyi2']; // 引用类型属性
}

function Child () {
    // 核心：通过call方法，将父类构造函数的this绑定到子类实例
    Parent.call(this);
}

var child1 = new Child();
child1.names.push('test'); // 修改child1的引用类型属性
console.log(child1.names); // ["heyi", "heyi2", "test"]

var child2 = new Child();
console.log(child2.names); // ["heyi", "heyi2"]（未受影响，引用类型属性不共享）
```

借用构造函数支持在子类构造函数中向父类构造函数传递参数，灵活性大幅提升，示例如下：

```javascript
// 借用构造函数（支持传递参数）（JavaScript代码）
function Parent (name) {
    this.name = name; // 父类实例属性
}

function Child (name) {
    // 调用父类构造函数，并传递参数，绑定this到子类实例
    Parent.call(this, name);
}

var child1 = new Child('heyi');
console.log(child1.name); // heyi（继承父类属性并初始化）

var child2 = new Child('heyi2');
console.log(child2.name); // heyi2（不同实例属性独立）
```

优点：1.  彻底解决了原型链继承中子类实例共享引用类型属性的问题，每个子类实例的引用类型属性都是独立的；2.  可以在子类构造函数中向父类构造函数传递参数，灵活初始化父类属性；3.  实现逻辑简单，仅需通过`call`或`apply`方法绑定`this`即可。

缺点：1.  方法需在父类构造函数中定义，无法实现函数复用，每次创建子类实例时，父类构造函数中的方法都会被重新创建一遍，造成内存浪费；2.  只能继承父类的实例属性和方法，无法继承父类原型上的属性和方法，失去了原型链继承的核心优势（方法共享）。

知识点对应问题：借用构造函数的核心思路是什么？如何实现子类向父类构造函数传递参数？借用构造函数相比原型链继承，解决了什么问题，又存在哪些不足？

### 组合继承

组合继承结合了原型链继承和借用构造函数的优点，核心思路是“借用构造函数继承属性，原型链继承方法”。通过`call`或`apply`方法调用父类构造函数，让子类实例继承父类的实例属性（保证属性独立）；通过设置子类原型与父类原型的关联，让子类实例继承父类原型上的方法（实现方法共享），兼顾了属性独立和方法复用的需求。

```javascript
// 组合继承（结合原型链和借用构造函数）（JavaScript代码）
function Parent (name) {
    this.name = name; // 父类实例属性（基本类型）
    this.colors = ['red', 'blue', 'green']; // 父类实例属性（引用类型）
}

// 父类原型上的方法（实现方法共享）
Parent.prototype.getName = function () {
    console.log(this.name);
}

function Child (name, age) {
    // 1. 借用构造函数：继承父类实例属性，保证属性独立，支持传递参数
    Parent.call(this, name);
    // 子类自身实例属性
    this.age = age;
}

// 2. 原型链继承：让子类原型关联父类原型，继承父类原型上的方法
// 推荐方式：不调用父类构造函数，避免构造函数重复执行
Child.prototype.__proto__ = Parent.prototype;

// 创建子类实例
var child1 = new Child('Heyi', '18');
child1.colors.push('black'); // 修改child1的引用类型属性

console.log(child1.name); // Heyi（继承父类实例属性）
console.log(child1.age); // 18（子类自身属性）
console.log(child1.colors); // ["red", "blue", "green", "black"]

var child2 = new Child('daisy', '20');
console.log(child2.name); // daisy（属性独立）
console.log(child2.age); // 20（子类自身属性）
console.log(child2.colors); // ["red", "blue", "green"]（引用类型属性不共享）

// 访问父类原型上的方法（方法共享）
child1.getName(); // Heyi
child2.getName(); // daisy
```

优点：1.  兼顾了原型链继承和借用构造函数的优势，既可以继承父类原型上的属性和方法（实现方法共享），也可以继承父类的实例属性（保证属性独立）；2.  解决了原型链继承中引用类型属性共享的问题，也解决了借用构造函数无法实现方法复用的问题；3.  支持在子类构造函数中向父类构造函数传递参数，灵活性高；4.  实例之间不会共享引用类型属性，方法共享且不浪费内存。

缺点：1.  相比ES6`class`语法，需要手动处理子类原型与父类原型的关联（如`Child.prototype.__proto__ = Parent.prototype`），语法稍显繁琐；2.  若使用旧版组合继承方式（`Child.prototype = new Parent()`），会导致父类构造函数被调用两次（一次在创建子类原型时，一次在子类构造函数内部），可能造成内存浪费；3.  无法直接继承父类原型上的不可枚举属性，需额外处理。

知识点对应问题：组合继承的核心思路是什么？组合继承如何结合原型链继承和借用构造函数的优势？组合继承的主要缺点有哪些，如何避免父类构造函数被重复调用？

### 原型式继承(了解)

原型式继承是一种简洁的继承方式，核心思路是通过克隆一个已有对象来实现继承，无需创建单独的构造函数。可以使用JS原生方法`Object.create()`实现更简洁的原型式继承，`Object.create()`会创建一个新对象，并将新对象的原型指向传入的参数对象（即被克隆的对象）。

```javascript
// 原型式继承（JavaScript代码）
// 被克隆的对象（作为新对象的原型）
const person = {
  name: 'Unknown',
  friends: ['Tom', 'Jerry'], // 引用类型属性
  sayHello: function() {
    console.log(`Hello, I'm ${this.name}`);
  }
};

// 使用Object.create()实现原型式继承，克隆person对象
const person1 = Object.create(person);
const person2 = Object.create(person);

// 访问继承的属性和方法
person1.sayHello(); // Hello, I'm Unknown
person2.sayHello(); // Hello, I'm Unknown

// 修改person1的自身属性（不影响原型）
person1.name = 'Alice';
console.log(person1.name); // Alice
console.log(person2.name); // Unknown（原型上的属性未被修改）
```

原型式继承的核心问题与原型链继承类似，包含引用类型的属性值始终会被所有克隆对象共享，修改一个对象的引用类型属性，会影响所有相关对象，示例如下：

```javascript
// 修改person1的friends属性（引用类型，原型上的属性）
person1.friends.push('Mike');

// 查看两个对象的friends属性，均发生变化（共享属性被修改）
console.log(person1.friends); // ['Tom', 'Jerry', 'Mike']
console.log(person2.friends); // ['Tom', 'Jerry', 'Mike']
```

优点：对于不需要单独创建构造函数，但仍然需要在对象间共享信息的场合非常有用，实现简洁，无需定义复杂的类结构。

缺点：1.  包含引用类型的属性值始终会被所有克隆对象共享，修改一个对象的引用类型属性，会影响所有相关对象，与原型链继承存在相同的引用类型共享问题；2.  无法实现函数复用，每个需要新增方法的对象，都需要单独定义方法，会造成内存浪费；3.  无法在克隆对象时，向原型对象传递参数，灵活性不足。

知识点对应问题：原型式继承的核心思路是什么？`Object.create()`方法在原型式继承中的作用是什么？原型式继承的主要缺点有哪些？

### 寄生式继承（了解）

寄生式继承是在原型式继承的基础上进行优化的继承方式，核心思路是使用工厂函数封装原型式继承的过程，在工厂函数内部克隆对象、增强对象（添加新的属性和方法），然后返回增强后的对象，实现对象的继承与扩展。

```javascript
// 寄生式继承（JavaScript代码）
// 工厂函数：封装原型式继承，增强对象并返回
function createPerson(original) {
  // 1. 原型式继承：克隆传入的对象
  const clone = Object.create(original);
  // 2. 增强对象：添加新的属性和方法
  clone.sayAge = function(age) {
    console.log(`I'm ${age} years old`);
  };
  // 3. 返回增强后的对象
  return clone;
}

// 被克隆的原型对象
const person = {
  name: 'Unknown',
  sayHello: function() {
    console.log(`Hello, I'm ${this.name}`);
  }
};

// 使用寄生式继承创建对象
const person1 = createPerson(person);
const person2 = createPerson(person);

// 访问继承的方法和增强的方法
person1.sayHello(); // Hello, I'm Unknown（继承的方法）
person1.sayAge(18); // I'm 18 years old（增强的方法）
person2.sayHello(); // Hello, I'm Unknown（继承的方法）
person2.sayAge(20); // I'm 20 years old（增强的方法）
```

优点：可以在不影响原对象（被克隆对象）的情况下，为克隆对象添加新的函数或属性，用于增强对象功能，灵活性较高；继承逻辑封装在工厂函数内部，代码复用性有所提升。

缺点：跟借用构造函数模式一样，每次通过工厂函数创建对象时，都会重新创建一遍增强方法（如sayAge），无法实现函数复用，会造成内存浪费；同时继承了原型式继承的缺点，引用类型属性会被所有克隆对象共享。

知识点对应问题：寄生式继承的核心思路是什么？寄生式继承相比原型式继承的优化点是什么？寄生式继承的主要缺点是什么？

### 继承中的数据类型相关问题

#### 1. 对象可以修改原型链上的基本数据类型吗？

分两种情况，核心区别在于“修改自身”还是“直接修改原型对象”：

情况一：“改自己”会发生遮蔽（shadowing）。如果原型上有一个基本类型属性（如`a = 1`），在实例上执行`obj.a = 2`，不会修改原型上的`a`，只是给`obj`自己新增或覆盖了一个同名属性，将原型上的那个属性“遮住”，后续访问`obj.a`时，会优先访问实例自身的属性，而非原型上的属性。

情况二：“直接改原型对象”可以修改。如果拿到原型对象本体（如`Ctor.prototype`）直接修改，比如`Person.prototype.name = 'Bob'`，那就是在修改原型本身，所有沿着这条原型链查到该属性的对象，读取结果都会发生变化，因为它们共享这个原型对象。

结论：实例通常改不到原型上的基本类型值，只会在自己身上生成同名属性；但直接修改原型对象本体，会影响所有依赖该原型的实例。

#### 2. 创建对象时引用数据类型会放在原型上吗？

默认不会“自动放到原型上”，引用数据类型的存放位置，完全取决于开发者的代码编写方式：

如果在构造函数里写`this.arr = []`，那么`arr`是每个实例各自拥有的属性，存储在实例对象上，每个实例的`arr`都是独立的，修改一个实例的`arr`不会影响其他实例。

如果在原型上写`Ctor.prototype.arr = []`，那么`arr`是所有实例共享的属性，存储在原型对象上，所有实例通过原型链访问到的是同一个数组，修改一个实例的`arr`（如`push`操作），会影响所有其他实例。

总结：引用类型可以放在原型上，但那是开发者手动编写的结果；一旦放上去就会变成共享状态，最常见的坑就是“修改一个实例的引用类型属性，所有实例都会发生变化”。

#### 3. 继承对基本数据类型和引用数据类型如何继承？修改父类会影响子类实例吗？

可以将“继承”拆分为两类来看，分别对应不同的数据类型继承规则：原型继承（共享）和构造函数初始化（独享）。

A. 原型继承（通过`Child.prototype = Object.create(Parent.prototype)`等方式实现）

继承的核心是“查找能力”：子类实例能沿原型链找到父类原型上的属性和方法，其继承规则如下：

- 基本类型属性在父类原型上：<span style="color:#FAAD14">子类实例能正常读取该属性；子类实例赋值同名属性时，只会发生遮蔽，不会修改父类原型上的属性</span>；如果直接修改`Parent.prototype.x`（父类原型上的基本类型属性），会影响所有能查到该属性的实例（包含子类实例）。

- 引用类型属性如果放在父类原型上（不推荐）：子类实例访问到的是同一个引用（所有实例共享同一个数组、对象等）；任意一个实例对该引用类型属性做“原地修改”（如`push`、`obj.k = ...`），都会影响所有实例（包含子类实例）。

B. 构造函数初始化（通过`Parent.call(this)`、`super()`等方式实现）

继承的核心是“实例属性初始化”：父类在构造函数里通过`this.x = 1`、`this.obj = {}`定义的属性，都会变成子类实例的自有属性，其继承规则如下：

- 基本类型属性：每个子类实例各自拥有一份，修改一个实例的基本类型属性，不会影响其他实例。

- 引用类型属性：每个子类实例也各自拥有一份，因为每次调用构造函数，都会创建一个新的对象或数组，修改一个实例的引用类型属性，不会影响其他实例（除非将同一个外部对象塞给所有实例）。

补充结论：修改父类是否会影响子类实例，关键看修改的是父类原型上的属性，还是父类构造函数里的实例属性；修改父类原型上的属性，会影响所有子类实例；修改父类构造函数里的实例属性，只会影响当前实例，不会影响其他子类实例。

知识点对应问题：对象修改原型链上的基本数据类型有哪两种情况？创建对象时，引用数据类型放在原型上和放在实例上有什么区别？原型继承和构造函数初始化，对基本数据类型和引用数据类型的继承规则有什么不同？

### 核心总结

1. 原型链继承：最基本的继承方式，实现简单，但存在引用类型共享、构造函数调用两次、无法传递参数等缺点；
2. 原型式继承：基于对象克隆实现，无需创建构造函数，适合简单的对象共享场景，但引用类型共享、无法函数复用；
3. 寄生式继承：原型式继承的增强版，通过工厂函数增强对象，但依然无法实现函数复用，继承了原型式继承的缺点；
4. class语法继承：最佳实现方式，原型链+构造函数继承的语法糖，解决了之前所有继承方式的缺点，语法简洁、封装性好，是开发中首选。

选择继承方式时，优先使用ES6`class`语法，兼顾可读性、封装性和复用性；如需兼容旧版浏览器，可通过Babel转换class语法；理解各种继承方式的底层原理（原型、构造函数）。

## 5.JS class语法糖详解

- class 创建对象的本质，不同方法挂载的位置？
- class 静态方法和实例方法的区别？
- class 继承的本质， 两条链的描述？

ES6引入的`class`语法，并非JavaScript新增的面向对象编程机制，其本质是**语法糖**——底层依然依赖JavaScript原生的“构造函数+原型+继承链+属性定义”这套核心机制，只是对原有语法进行了封装和简化，让代码更简洁、可读性更强，更符合传统面向对象编程的语法习惯，降低了原型链和构造函数的使用门槛。

class语法糖的核心作用，是自动帮开发者完成“构造函数创建、原型对象绑定、方法挂载、继承链搭建”等繁琐操作，无需手动编写原型关联、构造函数调用等底层代码，但其底层运行逻辑与手动编写构造函数+原型的方式完全一致。下面将从底层实现步骤、各核心特性、关键区别等方面，详细拆解class语法糖。

### class语法糖的底层实现核心步骤

class语法糖的底层实现可拆解为6个核心步骤，每一步都对应原生构造函数+原型的操作，理解这些步骤，就能彻底掌握class与原生语法的关联。

#### 1. 创建构造函数对象

任何一个`class`定义，本质上都会创建一个可通过`new`调用的构造函数（构造器），这是class语法糖的基础。

- 若class中未显式定义`constructor`方法，会自动生成一个空的构造器，在无继承（不使用`extends`）时，空构造器等价于`function 类名() {}`；在有继承时，空构造器会默认包含`super(...args)`，用于调用父类构造函数。

- 若显式定义`constructor(...) { ... }`，则该方法会直接作为这个构造函数的函数体，负责实例属性的初始化。

```javascript
// class定义（底层会创建构造函数对象）
class A {}

// 等价于原生构造函数（无继承时的空构造器）
function A() {}

// 显式定义constructor的class
class B {
  constructor(name) {
    this.name = name; // 构造函数体，初始化实例属性
  }
}

// 等价于原生构造函数
function B(name) {
  this.name = name;
}

// 验证：class创建的类本质是构造函数
console.log(typeof A); // function
console.log(typeof B); // function
console.log(A.prototype.constructor === A); // true
console.log(B.prototype.constructor === B); // true
```

#### 2. 创建并绑定原型对象

<span style="color:#409eff">class会自动创建一个原型对象（`类名.prototype`），并自动将该原型对象的`constructor`属性指向当前类（构造函数）</span>，无需手动绑定，避免了原生语法中“重写原型后丢失constructor”的问题。

这一步对应原生语法中“手动创建原型对象并绑定constructor”的操作，class将其自动化，减少开发者的手动操作和出错概率。

```javascript
// class自动创建并绑定原型对象
class A {
  constructor(name) {
    this.name = name;
  }
}

// 1. 自动生成A.prototype原型对象
console.log(A.prototype); // {constructor: ƒ, ...}
// 2. 自动绑定constructor，指向类A（构造函数）
console.log(A.prototype.constructor === A); // true

// 对比原生语法（需手动处理）
function B(name) {
  this.name = name;
}
// 若手动重写原型，需手动绑定constructor
B.prototype = {
  constructor: B, // 手动绑定，否则会丢失
  sayName() {}
};
```

#### 3. 实例方法/访问器挂载到原型对象

class中定义的普通实例方法（不含`static`关键字）、get访问器、set访问器，都会被自动挂载到`类名.prototype`上，供所有实例通过原型链共享，无需手动编写`类名.prototype.方法名 = 函数`的代码。注意不同方法定义的位置不同。

注意：class挂载的实例方法/访问器，默认是**不可枚举**的，这与原生语法中“手动挂载原型方法（默认可枚举）”的行为不同，更符合封装的思想。

```javascript
// class中定义实例方法、get/set访问器
class A {
  constructor(name) {
    this.name = name;
  }

  // 实例方法：自动挂载到A.prototype
  sayName() {
    console.log(`My name is ${this.name}`);
  }

  // get访问器：自动挂载到A.prototype
  get fullName() {
    return `Mr. ${this.name}`;
  }

  // set访问器：自动挂载到A.prototype
  set fullName(value) {
    this.name = value.slice(3); // 截取前缀，重新赋值name
  }
}

// 创建实例，通过原型链访问方法和访问器
const a = new A('Tom');
a.sayName(); // My name is Tom（访问原型上的实例方法）
console.log(a.fullName); // Mr. Tom（访问get访问器）
a.fullName = 'Mr. Jerry'; // 调用set访问器
console.log(a.name); // Jerry

// 验证：方法挂载在A.prototype上，且不可枚举
console.log(A.prototype.sayName); // ƒ sayName() {...}
console.log(A.prototype.hasOwnProperty('fullName')); // true
// 验证不可枚举：for...in循环不会遍历到原型上的方法（除非手动设置enumerable: true）
for (let key in a) {
  console.log(key); // 只输出name，不会输出sayName、fullName
}
```

#### 4. 静态方法/访问器挂载到类本身

class中使用`static`关键字定义的静态方法、静态访问器，不会挂载到原型对象（`类名.prototype`）上，而是直接挂载到**类本身**（即构造函数对象上），只能通过“类名.方法名”调用，无法通过实例调用（实例无法通过原型链访问到类本身的属性/方法）。

```javascript
// class中定义静态方法、静态访问器
class A {
  // 静态方法：自动挂载到类A本身
  static sayHello() {
    console.log('Hello, class static method');
  }

  // 静态get访问器：挂载到类A本身
  static get staticProp() {
    return 'static property';
  }

  // 静态set访问器：挂载到类A本身
  static set staticProp(value) {
    console.log(`Set static property: ${value}`);
  }
}

// 调用静态方法和访问器（只能通过类名调用）
A.sayHello(); // Hello, class static method
console.log(A.staticProp); // static property
A.staticProp = 'new static value'; // Set static property: new static value

// 实例无法调用静态方法/访问器（静态成员不在原型上）
const a = new A();
console.log(a.sayHello); // undefined（实例无该方法）
console.log(a.staticProp); // undefined（实例无该属性）

// 验证：静态方法挂载在类本身
console.log(A.sayHello); // ƒ sayHello() {...}
console.log(A.hasOwnProperty('sayHello')); // true
```

#### 5. extends继承：搭建两条继承链

class通过`extends`关键字实现继承，底层会自动搭建**两条继承链**（实例继承链、构造器继承链），这是class继承与原生原型链继承的核心区别之一，也是其简化继承逻辑的关键，无需手动关联子类原型与父类原型。

extends继承的底层操作的两条链：

1. 实例方法继承链：`子类.prototype.__proto__ = 父类.prototype`，确保子类实例能通过原型链找到父类的实例方法和访问器；
2. 静态方法继承链：`子类.__proto__ = 父类`，确保子类（构造函数对象）能继承父类的静态方法和静态访问器。

同时，子类构造器中必须先调用`super()`，才能使用`this`——因为`super()`会调用父类构造函数，完成父类对`this`的初始化绑定，否则`this`会处于未初始化状态，报错。

```javascript
// class extends继承（自动搭建两条继承链）
class Parent {
  // 父类实例方法（挂载到Parent.prototype）
  parentMethod() {
    console.log('Parent instance method');
  }

  // 父类静态方法（挂载到Parent本身）
  static parentStaticMethod() {
    console.log('Parent static method');
  }
}

// 子类继承父类
class Child extends Parent {
  constructor() {
    // 必须先调用super()，才能使用this（初始化父类this）
    super();
    this.childProp = 'child property';
  }

  // 子类实例方法（挂载到Child.prototype）
  childMethod() {
    console.log('Child instance method');
  }
}

// 验证1：实例继承链（子类实例能访问父类实例方法）
const child = new Child();
child.childMethod(); // Child instance method
child.parentMethod(); // Parent instance method（通过原型链继承）
// 验证实例链底层：Child.prototype.__proto__ === Parent.prototype
console.log(Object.getPrototypeOf(Child.prototype) === Parent.prototype); // true

// 验证2：构造器继承链（子类能访问父类静态方法）
Child.parentStaticMethod(); // Parent static method（继承父类静态方法）
// 验证构造器链底层：Child.__proto__ === Parent
console.log(Object.getPrototypeOf(Child) === Parent); // true

// 错误示例：子类构造器未调用super()，使用this报错
class ErrorChild extends Parent {
  constructor() {
    this.errorProp = 'error'; // 报错：Must call super constructor in derived class before accessing 'this'
  }
}
```

#### 6. 处理class字段（实例字段/静态字段）

class中直接定义的字段（如`x = 1`），称为实例字段，其底层并非挂载到原型对象（`类名.prototype`）上，而是在“每次`new`创建实例时”，自动在构造函数中为实例初始化该字段——这意味着，每个实例的字段都是独立的，不会被所有实例共享，避免了“原型上引用类型字段被共享”的坑。

若字段前加上`static`关键字（如`static y = 1`），则为静态字段，底层会挂载到类本身（构造函数对象上），与静态方法一样，只能通过类名访问，实例无法访问。

```javascript
// class字段（实例字段+静态字段）
class A {
  // 实例字段：每次new时，为实例初始化该字段（每个实例独立）
  x = 1;
  obj = {}; // 引用类型实例字段，每个实例一份，不共享

  // 静态字段：挂载到类A本身，只能通过类名访问
  static y = 10;
}

// 创建两个实例，验证实例字段独立
const a1 = new A();
const a2 = new A();

// 修改a1的实例字段，不影响a2
a1.x = 2;
a1.obj.name = 'Tom';

console.log(a1.x); // 2
console.log(a2.x); // 1（未受影响）
console.log(a1.obj); // {name: 'Tom'}
console.log(a2.obj); // {}（未受影响，独立存在）

// 访问静态字段（只能通过类名）
console.log(A.y); // 10
console.log(a1.y); // undefined（实例无法访问静态字段）

// 对比：原型上的引用类型字段（会共享，不推荐）
class B {
  constructor() {}
}
B.prototype.shareObj = {}; // 挂载到原型上，所有实例共享
const b1 = new B();
const b2 = new B();
b1.shareObj.name = 'Jerry';
console.log(b2.shareObj); // {name: 'Jerry'}（被共享修改）
```

### 构造器的prototype与__proto__区别

理解class语法糖，必须区分“构造器本身的原型（__proto__）”和“构造器的prototype属性”——两者指向不同，作用也完全不同，这是避免原型链混淆的核心要点。

#### 1. Constructor.prototype 指向什么？

`Constructor.prototype`（构造器的prototype属性）指向一个普通对象，这个对象会成为“通过`new Constructor()`创建的所有实例”的`[[Prototype]]`（即`__proto__`），也是实例原型链的核心。

简单来说：`Object.getPrototypeOf(实例) === Constructor.prototype`，开发者放在`Constructor.prototype`上的方法/属性，会被所有实例通过原型链共享。class中的实例方法、get/set访问器，本质就是挂载到这个对象上。

#### 2. Constructor.__proto__ 指向什么？

`Constructor.__proto__`（标准写法：`Object.getPrototypeOf(Constructor)`）指向“构造器本身作为函数对象的原型”，属于“函数对象的原型链”，与实例无关。

对大多数普通函数/类（无继承）来说，`Object.getPrototypeOf(Constructor) === Function.prototype`——这意味着，构造器本身作为一个函数对象，会沿着“Constructor -> Function.prototype -> Object.prototype -> null”的链，继承`call`、`apply`、`bind`等函数的原生能力（这些能力都来自`Function.prototype`）。

#### 3. 继承时（class Child extends Parent）的额外改变

当使用`extends`实现继承时，class会额外修改上述两个指向，搭建两条继承链（对应前文的第5步）：

- 实例链（供实例使用）：`Object.getPrototypeOf(Child.prototype) === Parent.prototype`，确保实例能继承父类的实例方法；

- 构造器链（供构造器本身使用）：`Object.getPrototypeOf(Child) === Parent`，确保子类构造器能继承父类的静态方法/静态属性。

```javascript
// 区分Constructor.prototype与Constructor.__proto__
class A {}
class B extends A {}

// 1. 普通类（无继承）的指向
console.log(Object.getPrototypeOf(A.prototype)); // Object.prototype（实例原型链的下一级）
console.log(Object.getPrototypeOf(A)); // Function.prototype（A作为函数对象的原型）

// 2. 继承类的指向（两条链）
// 实例链：B.prototype的原型是A.prototype（供实例继承）
console.log(Object.getPrototypeOf(B.prototype) === A.prototype); // true
// 构造器链：B的原型是A（供B继承静态方法）
console.log(Object.getPrototypeOf(B) === A); // true

// 3. 实例的原型指向
const a = new A();
console.log(Object.getPrototypeOf(a) === A.prototype); // true（实例的原型是构造器的prototype）
```

#### 一句话记忆（核心区分）

- `Constructor.prototype`：给**实例**用的（实例的原型，挂载实例方法，供所有实例共享）；

- `Constructor.__proto__`：给**构造器本身**用的（构造器作为函数对象的原型，挂载静态方法，供构造器继承）。

### class基本语法及底层转换

ES6引入的`class`语法，是JS继承的最佳实现方式，本质上是原型链继承和构造函数继承的语法糖，简化了继承的实现逻辑，同时解决了之前多种继承方式的缺点，具备更好的可读性和封装性。`class`语法的底层依然基于原型和构造函数实现，我们可以通过查看其Babel转换后的代码，理解其底层原理。

#### class基本语法实现继承

```javascript
// class基本语法实现继承（JavaScript代码）
// 父类
class Person {
  // 父类构造函数，初始化属性
  constructor(name) {
    this.name = name;
  }

  // 父类原型上的方法（不加static，默认在原型上）
  sayHello() {
    console.log(`Hello, I'm ${this.name}`);
  }
}

// 子类：通过extends关键字继承父类
class Student extends Person {
  // 子类构造函数
  constructor(name, age) {
    // 调用父类构造函数，初始化父类属性（相当于Parent.call(this)）
    super(name);
    // 子类自身属性
    this.age = age;
  }

  // 子类原型上的方法
  sayAge() {
    console.log(`I'm ${this.age} years old`);
  }
}

// 创建子类实例
const student1 = new Student('Alice', 18);
const student2 = new Student('Bob', 20);

// 访问父类属性和方法、子类属性和方法
student1.sayHello(); // Hello, I'm Alice（父类方法）
student1.sayAge(); // I'm 18 years old（子类方法）
console.log(student1.name); // Alice（父类属性）
console.log(student1.age); // 18（子类属性）

// 验证：引用类型属性独立（若父类有引用类型属性，子类实例各自独立）
Person.prototype.friends = ['Tom', 'Jerry'];
student1.friends.push('Mike');
console.log(student1.friends); // ['Tom', 'Jerry', 'Mike']
console.log(student2.friends); // ['Tom', 'Jerry', 'Mike']（原型上的引用类型仍共享，需避免在原型上定义引用类型）
```

### 核心总结

1. class是JS面向对象编程的语法糖，底层完全依赖“构造函数+原型+继承链”，不新增任何原生机制，仅简化代码编写和阅读体验；
2. class会自动完成“构造函数创建、原型对象绑定、方法挂载、继承链搭建”等操作，避免了原生语法的繁琐和易错点（如丢失constructor、原型链关联错误）；
3. 实例方法挂载在`类名.prototype`上，供所有实例共享；静态方法/字段挂载在类本身，仅能通过类名访问；实例字段在每次`new`时初始化，每个实例独立；
4. `extends`继承的核心是两条链：实例链负责实例方法继承，构造器链负责静态方法继承，`super()`是子类初始化`this`的关键；
5. 区分`Constructor.prototype`（实例用）和`Constructor.__proto__`（构造器用），是理解class原型链和继承的核心，避免混淆实例和构造器的原型关系。

掌握class语法糖的底层实现，既能享受其简洁性，也能在遇到原型链相关问题时，快速定位本质，结合原生语法解决问题——class是开发中首选的面向对象编程方式，但其底层逻辑仍需以原型和构造函数为基础。
