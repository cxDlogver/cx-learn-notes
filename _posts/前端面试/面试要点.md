## async 和 defer的区别
- 默认js 会阻塞 HTML 和 CSS渲染
- async 会异步进行  defer 时在HTML 解析完成以后执行
- 全部 defer 脚本执行完之后，才触发 DOMContentLoaded
- defer 本身不会阻塞 HTML 解析，所以比普通 script 更友好。
但它和 CSS 渲染不是完全没关系。因为 defer 脚本在 DOM 解析完成后执行，如果脚本依赖样式计算或布局信息，浏览器通常需要等 CSSOM 构建完成后再执行相关逻辑，所以 CSS 加载可能间接影响 defer 脚本的执行时机和页面首次渲染体验。

## 动态规范和贪心算法的区别
 动态规划：
解决问题时，分解成子问题并通过保存子问题的解来避免重复计算。
通常使用递归和记忆化技术来实现。
适用于最优解问题，如最短路径、最大子数组和背包问题。
时间复杂度通常较高，但可以通过保存中间结果来提高效率。
2. 贪心算法：
每一步选择局部最优解，最终通过局部最优解得到全局最优解。
不考虑全局最优解的可能性，贪心选择会在每个阶段做出局部最优的决策。
通常应用于特定类型的问题，如活动选择、哈夫曼编码等。

## response.json() 实现了什么功能， 为什么要使用？
- 解析HTTP响应体的JSON数据, 返回一个promise对象， 得到JS对象。 JSON.parse()

fetch() 返回的是一个 Promise<Response>，其中 response 是浏览器提供的 Response 对象，包含 HTTP 响应的状态码、响应头和响应体。

在处理响应时，通常会先看 response.ok，它表示当前状态码是否在 200 到 299 之间，如果不是，说明这次 HTTP 请求虽然完成了，但结果是失败的，比如 404 或 500。

然后再根据返回内容类型去解析响应体。对于接口最常见的 JSON 数据，一般会调用 response.json()。它的作用是把 response.body 这个 ReadableStream 读取出来，并解析成 JavaScript 对象。因为响应体本质上是流，所以不能直接使用，必须通过 json()、text()、blob() 等方法进行解析。

另外 response.json() 返回的也是 Promise，因为读取和解析本身是异步过程，而且响应流通常只能消费一次。

## new Object() 和 Object.create(null) 创建的对象有什么本质区别？为什么在某些场景（如做 Map 字典）推荐使用后者？
- 区别: new Object() (或 {}) 创建的对象原型指向 Object.prototype，拥有 toString, hasOwnProperty 等方法。Object.create(null) 创建的对象没有原型，是纯粹的字典。
- 场景: 用作 Map/Hash 字典时推荐 Object.create(null)。原因：避免键名与原型链方法冲突（如用户输入 key 为 "toString" 时会覆盖原生方法，导致遍历或判断出错）。

## 后端接口没开发好时，怎么测试

## 设置验证码的作用是什么
设置验证码的作用是做真人校验，防止脚本、爬虫或恶意程序批量操作接口，从而减少暴力破解、恶意注册、短信轰炸和刷活动等风险。
 1. 防止恶意机器人攻击
比如注册账号、登录暴力破解、刷票、刷评论、刷秒杀等操作。
图形验证码通过“人类识别难度小，机器识别难度大”的设计，阻止自动脚本重复访问系统。
✅ 2. 提高系统安全性
验证码可以防止黑客批量尝试用户名密码组合，保护用户数据。
在登录、注册、找回密码等敏感操作中设置验证码，可提升系统抗攻击能力。
✅ 3. 降低服务器压力
防止恶意爬虫刷请求、导致服务器资源被浪费甚至崩溃。
有效识别出非正常用户行为，减少服务器资源的无效消耗。
✅ 4. 防止恶意提交表单
如留言板、论坛、注册页，如果没有验证码，攻击者可以通过脚本大量灌水、发垃圾广告。
验证码类型 特点
图形验证码 常见，用户识别字符
滑动验证码 用户拖动滑块或拼图验证
点选验证码 点击指定图片/位置验证
数学题验证码 要用户输入算式结果
音频验证码 为视障用户设计，用听的识别
