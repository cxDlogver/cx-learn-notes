## 1. 验收模型与判定原则

每项用例按 `Given 场景 → When 单一动作 → Then 功能 F / Visual 视觉 V / But 反向 N` 写明可观察结果。`Given` 固定账号、计划类型与方向、业务日期、计划时区、规则版本、浏览器/视口、网络和权限。参数变体分别记录结果，不将多个边界值平均。用例状态为 `PASS / FAIL / BLOCKED / NOT_RUN`；未实现属于 `NOT_RUN`，外部依赖阻断必须写明复测条件。功能、视觉、反向三项及必需证据均满足，才可标 `PASS`；视觉 `N/A` 仅适用于无界面 API 场景。

### 1.1 三类断言

| 类型 | 判定问题 | 最小证明 |
| --- | --- | --- |
| `F` 功能 | 用户与 API 得到的状态、数值、导航和持久化结果是否正确？ | UI 可见结果 + 脱敏 API；唯一性、权限和统计再核对测试库 |
| `V` 视觉 | 文案、状态、视觉令牌、层级、响应式、可读性及可访问性是否正确？ | 页面截图 + DOM/无障碍树 + 规则审查结果；无页面时标 `N/A` |
| `N` 反向 | 越权、重复记录、错误统计、假成功、错误提醒或私人数据泄漏是否没有发生？ | 有观察窗口的 API 拒绝、DB 计数、事件/队列日志或浏览器网络记录；单张截图不足以证明缺席 |

### 1.2 Web 视觉与视口门槛

iOS 393×852 画板仅作颜色、排版、组件状态和信息层级参考。Web 不使用 iOS 的 4 pt/3% 或其他逐像素差异阈值。浅色与深色均验文案、状态语义、视觉令牌、足够对比度、焦点、键盘、屏幕阅读器和 200% 缩放。页面布局不得宽于可用视口，禁止横向溢出、遮挡和屏幕外不可达控件；长表单、日历详情和历史列表允许纵向滚动，固定导航与提交按钮不得遮住内容。参考视口至少含 360×800、390×844、768×1024、1280×800、1440×900 CSS px，并在发布时记录实际设备像素比、浏览器 UI 占用和可用内容视口。

桌面 Chrome、Edge、Safari、Firefox 与手机 Safari、Chrome 的当前和上一稳定大版本均在正式支持矩阵中；执行时冻结确切浏览器、版本、操作系统、能力检测结果、色彩模式和视口。缺少 Web Push 或相机能力时，仅允许相关能力在明确记录条件后标 `N/A`，不得用该理由跳过计划、打卡或隐私验收。

### 1.3 证据代码与结果契约

| 代码 | 文件/内容 | 适用场景 |
| --- | --- | --- |
| `S` | `screen-before.png`、`screen-after.png`、必要时整页截图 | 所有 UI 场景；记录浏览器与视口 |
| `H` | `dom.html`、`accessibility.json`：DOM 与可访问性树 | UI、键盘、焦点、视觉和隐私断言 |
| `V` | `visual-result.json`：参考令牌、布局规则、溢出/遮挡、对比度、人工复核 | 所有视觉断言；不写逐像素通过率 |
| `A` | `api.json`：脱敏请求/响应、状态码、requestId、幂等键摘要 | API、权限、统计、会话 |
| `D` | `db-assertions.json`：测试库只读断言与计数 | 唯一性、规则版本、权限、删除 |
| `L` | `browser-log.jsonl`、`server-log.jsonl`：网络、Worker、异常和审计事件 | 错误、重试、并发与后台任务 |
| `N` | `push-evidence.json`：权限、订阅、Worker 受理、展示、点击与失效 | 计划提醒、社交通知、Web Push |
| `F` | `artifact-manifest.json`：照片/ZIP/下载清单和 SHA-256 | 媒体、导出、删除 |
| `T` | `timeline.json`：冻结时钟、业务日期、浏览器 A/B、网络切换与操作顺序 | 跨日、时区、并发、30 天删除 |

每个变体保存 `evidence/<runId>/<caseId>/<variant>/result.json`。结果需包含用例/变体 ID、来源引用、PRD/技术方案/本矩阵的 SHA-256、Web 构建 commit、环境、浏览器版本/OS/视口/色彩模式、计划时区、服务端时间、fixture、F/V/N 的预期/实际/状态/证据路径、评审者与理由。证据路径为相对路径，清单记录文件 SHA-256；缺文件或哈希不符不能判 `PASS`。敏感内容在采集前脱敏。

### 1.4 测试种子与可控环境

- 用户 A（主人）、B（好友）、C（陌生人）、D（被屏蔽者）；同一 A 的桌面浏览器 A1、手机浏览器 A2、第二桌面标签 A3。所有账户与媒体使用隔离测试数据。
- 计划 F（周一/三/五固定日期）、FD（每日）、W（每周目标 3 天）、O（一次性到期）；均准备“要做/不要做”、暂停/归档、历史规则版本及一个数值项样本。
- 固定 `serverNowUtc`、计划 IANA 时区、业务日期、周一 00:00、截止日界线、浏览器时区；不能只改页面显示时间来模拟服务端结果。
- 短信、Web Push 供应端、对象存储与 Worker 可使用可审计桩；发布门槛再在受控真实浏览器和拟发布环境抽验。禁止使用生产账号、真实私人照片和真实手机号作固定测试数据。
- 浏览器 A/B 的独立 Cookie、权限、缓存和窗口状态必须保存；不将 iOS 客户端作为本矩阵的前置依赖。

## 15. 证据判定和 Web 发布门槛

1. 每次执行记录稳定 ID、变体、构建和源文档摘要、浏览器及操作系统版本、实际视口、主题、账号数据集、时区、业务日期、三类断言、证据路径与校验和。截图 S、HTML/可访问性树 H、录屏 V、API A、数据库 D、日志 L、文件 F、网络 N、时钟 T 按各行证据列采集；证据路径必须指向可复查的文件或记录。
2. `PASS` 表示该实例所有适用的 F/V/N 断言通过，且证据完整；`FAIL` 记录具体差异；`BLOCKED` 记录阻断原因；`NOT_RUN` 不能代替验收。纯 API/Worker 场景的 V 可为 `N_A`，但必须说明原因。人工或 AI 辅助判定均保留复核人、时间与依据；有争议时由产品、设计和测试按 PRD 与本矩阵共同裁决。
3. 136 个稳定用例 ID 均须有执行结果。`WEB-UI-01` 至少覆盖第 13 节 16 个页面键，因此最低执行实例数为 151；其他参数化场景按浏览器、主题、视口和数据状态增加实例。所有发布阻断实例必须 `PASS`，不能以 `BLOCKED` 或 `NOT_RUN` 放行。
4. 正式浏览器范围：发布时桌面 Chrome、Edge、Safari、Firefox 与手机 Safari、Chrome 的当前及上一稳定大版本，采用其支持的操作系统。核心流程和安全断言逐浏览器执行；响应式基线与浅/深色按矩阵执行。更旧版本提示升级，不承诺同等兼容。
5. Web Push 在受控支持浏览器中，权限请求、订阅、服务端发送、接收展示、点击跳转、取消订阅、失效清理均为必过链路。不同系统中关闭页面后的稳定到达率只记录观察，不作为发布阻断。权限拒绝、浏览器不支持时，站内消息和今日页仍须通过。
6. Web 独立发布验收只检查 Web UI、共享 API 与同账号多浏览器的数据/已读一致性。iOS 客户端联测另行验收；共用账号和云端数据仍是产品要求。任何 Web 自身的越权、隐私泄漏、数据丢失、核心业务失败、严重响应式遮挡或受控 Push 链路失败均阻断发布。
