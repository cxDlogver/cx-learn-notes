# OPS-03 删除与墓碑流程

## 在线行为

1. 计划删除在 API 事务内标记不可读、撤销分享并写同步删除事件。Worker 等上传签名失效，先删除照片对象，再删除媒体行和计划级联数据。对象删除失败会保留数据库追踪行并重试。
2. 账号注销请求在 API 事务内将账号置为 `deletion_pending`、撤销会话与分享、关闭推送，将已有导出文件设为立即过期，建立 30 天到期作业。普通 API 和登录从此拒绝该账号。
3. 30 天内，用户可向原手机号申请 `cancel_deletion` 用途验证码。校验成功后恢复账号并建立新会话；已撤销的逐计划分享保持撤销。到期后不能撤销。
4. 到期 Worker 标记照片待删，并等照片、导出 ZIP 对象清理完成，再删除计划、关系、令牌和用户行。墓碑以手机号检索摘要为键记录完成时间；日志不输出手机号、摘要、照片路径或验证码。

## 备份恢复门槛

删除墓碑必须独立于数据库业务备份保存。恢复业务备份时，先阻断 API 流量，使用与原环境相同的 `PHONE_LOOKUP_KEY` 和墓碑签名密钥：

1. 在源环境设置 `DATABASE_URL`、`TOMBSTONE_FILE`、`TOMBSTONE_SIGNING_KEY`，运行 `pnpm deletion:tombstones:export`，将生成文件作为受控备份保存；每次业务备份后及删除完成后都应更新独立墓碑文件。导出拒绝覆盖已有文件，应使用新的文件名。
2. 将业务备份恢复到隔离环境，设置 `DATABASE_URL`、`TOMBSTONE_FILE`、`TOMBSTONE_SIGNING_KEY`，运行 `pnpm deletion:tombstones:apply`。签名不符则停止。脚本把备份中复活的账号立即置为注销待清理、撤销会话和分享，并建立到期作业。
3. 保持 API 关闭，运行 Worker 至清理完成，再执行 `pnpm deletion:tombstones:check`。只有检查通过后才能开放 API。对象存储需同时指向已验证的恢复目标，Worker 才能删除恢复的照片和 ZIP。

墓碑回放以手机号检索摘要和账号创建时间共同判定：只隔离在该墓碑完成前创建的旧账号；用户在永久删除后使用同一手机号重新注册的新账号不在该墓碑清理范围内。

墓碑当前保留期为完成后 365 天。发布前要把业务与对象备份保留周期、墓碑独立保存周期对齐；任何可恢复的业务备份都必须有覆盖该备份之后删除事件的墓碑文件。恢复演练属于 OPS-05 和独立验收阶段。
