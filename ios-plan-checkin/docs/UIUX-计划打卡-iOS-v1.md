## 0. 一页看懂方案

### 产品气质

像一本安静、可信的个人执行记录簿。重点放在「今天要处理什么」「我实际记录了什么」「过去怎样」，不使用排名、勋章、夸张鼓励、虚假的连续天数或大面积渐变。成功可以被看见，失败、跳过、未记录也能被平静、准确地表达。

### 核心路径

```text
首次使用：登录 → 今日空态 → 创建计划 → 保存 → 返回今日
日常使用：今日 → 选择结果 → 确认（可选备注/照片/数值）→ 原卡片显示结果
复盘：日历选日期 / 计划详情 → 看历史 → 补记或修正
监督：朋友建立关系 → 在具体计划上授权 → 预览可见内容 → 确认分享
```

### 四个底部入口

| 入口 | 用户的问题 | 首屏第一重点 |
| --- | --- | --- |
| 今日 | 今天有什么需要处理？ | 待处理固定日计划、可自选的周目标、未完的一次性任务 |
| 日历 | 某天实际发生了什么？ | 月历状态与所选日期记录 |
| 计划 | 我有哪些计划？ | 运行中计划和分组，便于管理与进入详情 |
| 朋友 | 谁能看我分享的哪项计划？ | 好友与逐计划授权关系 |

### 设计原则及具体落点

1. **先结果，后附加内容。** 打卡主流程只需选结果并提交；备注、照片和数值收在同一确认页的可选区。
2. **状态写成字。** 「失败」「跳过」「未记录」始终有文字，不用颜色或图标代替语义。
3. **不制造欠账。** 周目标只展示本周进度；未指定的空白日没有待办、失败或未记录。
4. **先解释再授权。** 分享前明确展示历史状态和文字备注会被看见，照片与数值不会被看见。
5. **让操作有回声。** 提交后今日卡片留在原位；离线时显示本机保存状态，冲突时说明最终保留版本。
6. **不把失败人格化。** 用「本次未做到」「本周未达标」，不用「你又失败了」等评价性表达。

## 1. 设计范围与业务边界

### 1.1 设计覆盖

账号入口与首次使用、计划创建与编辑、今日、打卡、全局日历、计划列表与详情、统计、补记与修正、分组、提醒、朋友与分享、个人设置、导出与删除账号，以及离线/同步/权限/错误状态。

### 1.2 三种时间规则

| 类型 | 创建时的用户语言 | 今日呈现 | 结果判断 |
| --- | --- | --- | --- |
| 固定日期循环 | 「每周二、四」；「每天」是七天全选快捷项 | 只在选中日成为待处理项 | 选中日可成功/失败/跳过；过期未操作为未记录 |
| 每周目标 N 天 | 「一周任选 3 天」 | 始终可见本周进度，今日可主动记录 | 空白日没有未记录；周结束后判定达标与否 |
| 一次性任务 | 「9 月 30 日前提交」 | 截止前显示待完成，逾期仍显示 | 待完成/逾期/按时完成/迟完成/失败/取消 |

「要做 / 不要做」是方向，不是时间规则。一次性任务只允许「要做」。所有结果均由本人主动选择；系统只派生待处理、未记录、逾期、周达标等状态。

### 1.3 设计时不得跨越的边界

- 固定日期循环的非选中日不出现打卡或补记操作。
- 已有有效记录的同一计划、同一自然日再次进入时打开「修改」，不会再新增一条。
- 过去日期可补记，未来日期不可提前打卡；计划生效前也不可补记。
- 计划修改不重算历史；周中改变周目标、暂停/恢复等形成的部分周不计入周达标率和连续达标周数。
- 分享只发生在「计划 × 好友」上；好友关系本身不开放任何计划。
- 照片、数值、其他计划和个人统计绝不进入好友视图。
- 计划所属时区定义业务日期。设备时区改变后，历史记录仍停留在原日期。

## 2. 用户心智、信息架构与导航

### 2.1 心智模型

```text
计划 = 我要坚持什么
规则 = 哪些日子需要记录 / 一周怎样算达标
记录 = 我主动申报的实际结果
回顾 = 按日期或按计划查看这些结果
```

界面刻意把「应该执行」和「已经做了」分开：规则说明写在标题下方；结果状态作为独立标签。避免用一个勾号同时表达计划安排和完成结果。

### 2.2 页面树

```text
App
├─ 今日（默认）
│  ├─ 打卡确认 / 修改记录
│  ├─ 一次性任务结果确认
│  └─ 计划详情
├─ 日历
│  ├─ 日期详情 → 补记 / 修改 → 计划详情
│  └─ 分组筛选
├─ 计划
│  ├─ 分组管理
│  ├─ 创建计划 → 规则设置 → 可选设置 → 保存
│  ├─ 计划详情 → 日历 / 历史 / 统计
│  └─ 计划设置 → 编辑 / 暂停 / 恢复 / 归档 / 删除 / 分享
├─ 朋友
│  ├─ 搜索用户名 / 申请 / 请求处理
│  ├─ 好友详情 → 我分享给他 / 他分享给我
│  ├─ 获授权计划只读详情 → Emoji / 鼓励留言
│  └─ 分享预览 / 授权 / 撤销 / 删除好友 / 屏蔽
└─ 个人入口（今日右上角）
   ├─ 个人资料
   ├─ 通知设置
   ├─ 隐私设置
   ├─ 账号设置 / 退出
   ├─ 数据导出
   └─ 删除账号
```

### 2.3 导航约定

- 底部栏固定四项：今日、日历、计划、朋友。使用系统样式图标配文字，始终显示文字；不把创建按钮放在底栏中央。
- 「今日」右上角为个人入口；「计划」右上角为新建。今日空态和计划空态也提供新建按钮。
- 二级页面使用标准导航返回，重要提交页使用清晰的「取消」「保存」。返回已修改但未保存的表单时提示保留或放弃。
- 模态用于短决策：结果选择、分享确认、破坏性操作。长期浏览页面使用正常导航层级，避免连续叠加弹层。
- 深链接进入提醒时，先校验登录和权限，再落到对应计划及业务日期；记录已经改变时显示最新状态。

## 3. 视觉设计系统

### 3.1 视觉方向

白底或系统分组背景、温和中性色、少量深绿色作为行动色。卡片依靠排版、留白和细边界组织信息，不靠阴影堆层级。状态色保持克制，文本比色彩更重要。插画不承担功能说明；首版空态优先使用文字、简明线性图标和明确操作。

### 3.2 设计令牌（建议值，最终用系统动态颜色映射）

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 页面背景 | `#F7F7F4` | `#101310` | 大面积底色 |
| 内容表面 | `#FFFFFF` | `#1B211C` | 卡片、输入区域 |
| 主文字 | `#172018` | `#F3F5F0` | 标题、正文 |
| 次文字 | `#5B665D` | `#AEB8AD` | 规则、辅助信息 |
| 分隔线 | `#E2E6DF` | `#354037` | 分区边界 |
| 主行动 | `#236A49` | `#78C69A` | 主按钮、选中态 |
| 成功 | `#236A49` | `#78C69A` | 成功标签与图标 |
| 失败 | `#A34039` | `#F09A92` | 用户明确失败 |
| 跳过 | `#6A608D` | `#BEB2DF` | 主动跳过 |
| 未记录 | `#626C72` | `#B7C0C4` | 过去应记录却无记录 |
| 警示/逾期 | `#9B5C1E` | `#E8AE70` | 逾期、部分周提示 |

状态标签采用「文字 + 图形 + 颜色」三重表达，例如 `✓ 成功`、`× 失败`、`— 跳过`、`○ 未记录`。未记录与失败色相分离，但任何状态都不能只靠色彩辨认。深浅模式分别检查正文、辅助文字与按钮对比度；如设计令牌未达标，以可读性为准调整。

### 3.3 字体与排版

- 使用 iOS 系统中文字体与 SF 数字。页面大标题 28–34 pt；区块标题 20–22 pt；卡片标题 17–19 pt；正文 15–17 pt；说明 13–15 pt。具体字号使用系统文本样式映射，而非写死。
- 数字进度如 `2 / 3` 使用等宽数字，旁边始终写「本周已记录 2 天，目标 3 天」。不把数字孤立呈现。
- 8 pt 间距基准：页面左右 16–20 pt；卡片内 16 pt；卡片间 12 pt；主要区块间 24–32 pt。卡片圆角 12–16 pt，按钮圆角 10–12 pt。
- 不使用高密度仪表盘。一个屏幕只强化一个主问题：今日处理、日历回顾、计划管理或朋友授权。

### 3.4 控件与触控

- 主按钮高度建议 50–56 pt；所有可点区域至少 44 × 44 pt；点击整行的列表项应有明确按压反馈。
- 日期用系统日期选择器；星期用七个独立切换按钮，VoiceOver 可读出「周二，已选中」。每周目标用步进器或 1–7 的选择器，不允许无效值。
- 危险操作只用文字加警示色，不用模糊图标承载。删除计划与删除账号需要二次确认；归档作为保留历史的近邻选项。
- 动画只服务状态变化：记录提交后原卡片文字与标签更新，时长约 150–250 ms；减少动态效果开启时取消非必要位移。

## 4. 页面规格

### 4.1 登录与首次使用

**目标**：解释价值并进入核心闭环。入口说明只写「安排计划、记录结果、回看历程」，不承诺系统自动验证完成。**已确认：首版采用手机号登录。**登录页上半部是一句价值说明，下半部依次为国家/地区区号、手机号输入框、「获取验证码」、隐私说明和服务条款入口。手机号只用于登录与账号恢复，不作为好友搜索信息；好友仍仅按唯一用户名搜索。

**登录流程**：输入手机号 → 校验格式 → 请求短信验证码 → 输入验证码 → 登录或创建账号 → 进入今日。验证码页显示目标号码的脱敏形式，支持系统短信验证码自动填充、修改号码、倒计时后重新发送。验证码错误或过期时保留号码并就地提示；短信发送失败时给重试，不清空输入。新用户首次登录后引导设置唯一用户名和昵称，跳过可选头像；已有用户直接恢复云端数据。更换手机号放在账号设置中，需验证当前账号和新号码；具体风控次数由服务端策略决定，界面显示服务端返回的剩余等待时间。登录失败停留原页，不自动创建空计划。

首次登录成功进入今日空态：标题「先建一个计划」，正文「设置要做的事和执行时间，之后就能在这里记录结果」，主按钮「创建计划」。暂不请求通知、相册、相机权限；权限只在使用相应功能时解释并触发。好友功能不进入首次使用的必经路径。

### 4.2 今日页

**结构**：导航栏「今日」+ 日期与计划时区说明入口 → 需要处理 → 本周可记录 → 截止事项 → 今日已记录 → 底部栏。区块仅在有内容时显示。今日已记录放在下方，提交后卡片留在页面但移动可能让用户怀疑消失，因此**设计约定**：当前会话中提交后卡片原位更新；下次进入页面再按区块重排。

```text
┌──────────────────────────────┐
│ 今日                   头像入口 │
│ 9月27日 周日                  │
│                              │
│ 需要处理  2项                 │
│ ┌──────────────────────────┐ │
│ │ 阅读   每天               │ │
│ │ 待处理          [记录结果] │ │
│ └──────────────────────────┘ │
│                              │
│ 本周可记录                    │
│ ┌──────────────────────────┐ │
│ │ 跑步   每周任选3天         │ │
│ │ 本周 2 / 3 · 还差1天       │ │
│ │ [记录今天]               │ │
│ └──────────────────────────┘ │
│                              │
│ 截止事项                     │
│ 提交材料  截止9月30日  [查看]  │
└──────────────────────────────┘
 今日       日历       计划      朋友
```

**卡片行为**：

| 情况 | 展示 | 主操作 |
| --- | --- | --- |
| 固定日，今日待处理 | 计划名、执行规则、`待处理` | 记录结果 |
| 固定日，今日已记录 | 明确结果、可选「补记/已修正」标签、同步状态 | 查看/修改 |
| 固定日，非选中日 | 不进入今日待处理 | 从计划列表进入详情；当天无记录按钮 |
| 每周目标未达标 | `本周 x / N`、还差几天，措辞为机会而非欠账 | 记录今天 |
| 每周目标已达标 | `本周 x / N · 已达标`，不催促；仍可记录更多天 | 查看/继续记录 |
| 一次性待完成 | 截止日期、相对天数；不写「今天必须」 | 查看/记录结果 |
| 一次性逾期 | `逾期 x 天`，持续可见 | 完成/失败/取消 |
| 无计划 | 首次使用空态 | 创建计划 |
| 有计划但今日无事 | 「今天没有固定日期任务」并保留周计划和截止事项；确实全空时引导查看计划 | 查看计划 |

**排序设计约定**：固定日待处理按提醒时间（未设提醒则按名称）排序；逾期一次性事项在截止区顶部；用户刚操作的卡片本次停留原位。分组不强加到今日，以免增加扫描成本。

### 4.3 创建计划

采用一个可滚动表单、按选择渐进露出字段；页面顶部始终显示「创建计划」，底部固定「保存计划」。信息分为四段：①名称与方向；②执行方式；③日期；④可选设置。保存前给一条人话摘要，如「从 10 月 1 日起，每周二、四记录『英语练习』」。

**字段与交互**：

| 字段 | 交互 | 约束 / 反馈 |
| --- | --- | --- |
| 名称 | 单行输入 | 必填；空值在保存时就地提示「填写计划名称」 |
| 方向 | 「要做」「不要做」双选项，附一句成功示例 | 选一次性时固定为「要做」，在规则选择处说明原因 |
| 执行方式 | 三张纯文字选项卡 | 固定日期示例「每周二、四」；周目标示例「一周任选 3 天」；一次性示例「截止前完成一次」 |
| 固定星期 | 周一至周日按钮，附「每天」快捷选项 | 至少一日；快捷项全选七天，用户再点单日可调整 |
| 每周目标 | 1–7 天 | 初始建议 3 天，明确可调整；保存的是用户最后选择值 |
| 开始/结束日期 | 日期选择器 | 循环计划开始必填、结束可选；结束不得早于开始 |
| 截止日期 | 日期选择器 | 一次性必填；仅可选择今天及未来日期；过去日期不可保存 |
| 分组、提醒、说明、数值单位 | 可选区 | 不设置也能保存；数值只用于回顾，不自动判定成功 |

**方向文案示例**：要做：「今天完成了阅读 / 今天没有完成」；不要做：「今天做到了，没有吸烟 / 今天发生了吸烟」。创建时用预览句让用户判断是否表达了真实目标，避免「已完成吸烟」之类反义表达。

**时区设计规则（已确认）**：创建页日期区显示「按计划时区：亚洲/上海」及说明入口。默认取创建时设备时区；保存后固定业务时区，不提供修改入口。后续设备时区变化不迁移历史。

**离开保护**：只在表单有改动时提示「继续编辑 / 放弃更改」。保存中按钮防重复点击；保存失败保留全部输入并给重试。保存成功返回今日，若计划未来才开始，给提示「已创建，10 月 1 日开始」，并可进入详情。

### 4.4 打卡与记录修改

从今日卡片或合法历史日期进入统一的结果页。页首显示计划名、业务日期、计划时区和方向；下方三项结果，最后是可选附加内容和提交按钮。结果按钮文案随方向变化，不用通用的「完成/未完成」套所有计划。

```text
阅读 · 9月27日
你今天的结果是？
[ ✓ 今天完成了 ]
[ × 今天没有完成 ]
[ — 今天跳过 ]

补充记录（选填）
备注 / 照片 / 数值

[保存结果]
```

不要做计划的成功/失败改为「今天做到了，没有吸烟」「今天发生了吸烟」。如果名称不是可直接拼接的行为，使用中性文案「今天做到了」「今天没有做到」，避免机械拼接产生病句；结果页副标题保留计划名。

**操作规则**：

- 选择结果不立即写入；点「保存结果」后才提交，降低误触。纯结果提交无需填附件。成功、失败、跳过同等可见，不把失败埋入菜单。
- 当天已有记录时标题改「修改 9 月 27 日的记录」，按钮改「保存修改」。保留原备注、照片和数值；修改结果或附件后显示「已修正」与最近修改时间。
- 过去日期首次提交显示「补记 9 月 20 日」，确认页显式写「记录日期：9 月 20 日；提交时间：今天」，保存后标「补记」。若后来修改，两个标签均保留。
- 非选中固定日、未来日期、计划生效前、暂停/归档后的非有效日期不提供提交入口；若由旧深链接进入，说明为何不可记录并提供返回。
- 一次性任务使用独立结果页：`标记完成`、`标记失败`、`取消任务`。逾期后完成显示「迟完成」。失败是终态；误记需进入原记录修正，不出现第二次新建式提交。一次性任务没有「跳过」。
- 提交成功提示使用轻量反馈「已记录成功/失败/跳过」，原卡片变为最新状态。离线则写「已保存到本机，联网后同步」。照片上传失败只影响照片附件，不撤销已保存的基本结果；给「重试上传照片」。

### 4.5 全局日历

页面顶部为月份切换与分组筛选；中间月历；下方是所选日期详情。周起始为周一。日期格保持可读数字，结果用小标记和辅助文字/无障碍标签；同一天多计划时不在格内塞入多枚彩点，改为聚合数量与所选日明细。

| 日期情况 | 月历表达 | 点开后的详情 |
| --- | --- | --- |
| 固定日成功/失败/跳过 | 对应状态标记 | 计划名、结果、备注摘要、补记/修正标签 |
| 固定日已过且无记录 | `○` + 无障碍「未记录」 | 显示未记录，可补记 |
| 固定日今天待处理 | 轻描边，不显示未记录 | 显示待处理，可记录 |
| 固定计划非选中日 | 不为该计划制造状态 | 不出现该计划的补记入口 |
| 周目标空白日 | 无该计划标记 | 不显示未记录或失败 |
| 周目标有主动记录 | 相应结果 | 可查看/修改；日期详情附本周进度 |
| 一次性任务 | 截止日给截止标识；完成日给结果 | 显示截止/实际完成日期及状态 |

月历下可展开周摘要：周目标 `2 / 3 · 本周未达标` 只在完整周结束后出现；当前周为「进行中」，部分周标「部分周 · 不计入达标统计」。筛选只影响当前视图，返回默认「全部分组」。选择过去日期后，「补记」只列当日合法可补记计划，不提供一个无约束的全局加号。

### 4.6 计划列表与分组

顶部「计划」+ 新建；默认展示运行中，再通过筛选查看暂停、归档及已结束的一次性任务。列表行包含名称、规则摘要、状态、当前进度；按分组折叠可浏览。「未分组」是真实可选位置，不强迫创建分组。

分组管理使用普通列表：新建、重命名、移动计划、删除分组。删除前明确说明「其中的计划会移到未分组，计划和历史记录不会删除」，按钮「删除分组」。计划移动只改变整理方式，不改变记录与统计。

### 4.7 计划详情与统计

首屏顺序：名称与运行状态 → 规则摘要 → 当前进度与主操作 → 小型日历 → 统计 → 历史记录 → 设置入口。适当折叠长历史，不用默认展开数十张记录卡。

| 计划类型 | 当前进度 | 长期统计 | 不展示 |
| --- | --- | --- | --- |
| 固定日期循环 | 本期应打卡日与已记录结果 | 完成率、连续成功次数、成功/失败/跳过/未记录分布 | 非选中日的失败/未记录 |
| 每周目标 N 天 | 本周 `x / N`，达标或进行中 | 历史达标周、连续达标周数、部分周说明 | 每日完成率、空白日未记录 |
| 一次性任务 | 截止日与状态；完成后写实际完成日 | 任务时间线 | 连续打卡、每日完成率 |

**固定日期完成率（已确认）**：成功次数 ÷（已结束的应打卡次数 − 跳过次数）。今天尚未提交时不计入分母；今天提交后计入，并更新统计截止日期。旁边显示分子/分母，避免早上就把今日算成失败。分母为零时展示「暂无可计算记录」，不显示 0%。

**连续记录**：固定日使用「连续成功 x 次」，仅每天全选时可称「连续 x 天」；跳过、失败、未记录中断。每周目标显示「连续达标 x 周」，部分周不参与。当前未结束周不提前判「未达标」。

详情中的每条历史同时显示业务日期、结果、文字备注摘要，以及必要的「补记」「已修正」。本人可进入完整记录，包括私有照片和数值；获授权好友使用独立只读视图。

### 4.8 计划编辑与生命周期

设置页分「基本信息」「执行规则」「提醒」「分享」「计划管理」。名称、分组、提醒、说明直接保存。修改固定日星期或周目标时，确认页写新规则生效时间与历史保留方式：例如「新规则明天起生效；此前记录仍按原规则统计」。周中修改周目标补充「本周将标为部分周，不计入周达标统计」。

暂停确认写「暂停后不再生成新记录日，也不发送提醒；历史保留」。恢复时写明从何时继续；归档写「停止执行，历史仍可查看」。删除确认列出历史打卡、照片、数值、分享权限均被删除，并并列提供「归档计划」；最终删除按钮使用「永久删除计划」。

### 4.9 朋友、授权与互动

朋友首页分「好友」「申请」两个区。通过唯一用户名搜索，只展示用户名、昵称和可选头像；搜索不到时不暴露其他私人信息。接受好友申请后，双方好友详情明确显示「还没有分享任何计划」。好友列表行不使用似乎能看全账号的概括性进度。

**分享路径**：从计划详情「分享给朋友」→ 选择已是好友的对象 → 预览对方看到的内容 → 确认授权。预览页列出计划名称、规则、当前进度、历史状态、文字备注、补记/已修正标记，并明确「照片、数值、其他计划和个人统计不会分享」。显著提示：「对方能看到这项计划已有的全部打卡状态和文字备注，包括过去的失败原因。」最后按钮写「分享这项计划给 {昵称}」，不写模糊的「确定」。

**朋友只读页**：显示计划标题、规则、进度、可见历史与备注；本人私人附件完全不渲染，也不显示「隐藏照片」占位。Emoji 回应与简短鼓励留言在记录或计划下发送。留言仅本人和留言好友互见，其他获授权好友看不到。无权限、撤销或被屏蔽后返回页显示「这项计划已无法查看」，清除可继续留言的入口。

**权限管理**：计划详情显示每位已授权好友，可逐个撤销。好友详情同时列出「我分享给 TA」「TA 分享给我」。删除好友/屏蔽时说明相关计划访问立即取消；已收到的历史鼓励仍留给计划拥有者查看。撤销权限后，获授权方的当前和历史数据都应失效。

### 4.10 提醒与个人设置

固定日提醒只在选中星期；周目标由用户选择提醒星期，达标后本周停止；一次性按用户选定的截止提醒规则发送。提醒编辑页实时显示人话摘要，如「每周二、四 20:00 提醒」或「周一、周三 18:00；本周达标后停止」。

通知权限在用户首次开启任意提醒时先说明用途，再触发系统权限弹窗。系统拒绝后仍保存 App 内提醒配置，但页面显示「系统通知已关闭」与「前往系统设置」。社交通知分「好友申请」「计划分享」「鼓励留言」独立开关，与打卡提醒分区。

个人设置包含资料、隐私、通知、账号、导出和删除账号。**数据导出（已确认）**：导出页逐项列出计划与规则、分组、打卡结果与文字备注、数值、私人照片、好友及分享关系；用户点「生成导出文件」后看到进度，完成后通过系统分享面板保存一个 ZIP。ZIP 内包含可读的 CSV、完整的 JSON 和照片文件；失败时保留页内重试入口，不在社交页公开导出链接。删除账号页先说明云端计划、历史和朋友访问会如何处理，再进行强确认；不使用预选勾选框诱导操作。

**一次性提醒（已确认）**：默认关闭。用户开启后可选「截止当天」「提前 1 天」「提前 3 天」及时间；确认页显示「9 月 29 日 20:00 提醒提交材料」。任务进入按时完成、迟完成、失败或取消后，后续提醒停止。系统通知权限关闭时仍显示所设规则，并提示去系统设置开启。

### 5.2 加载、空态与错误

| 场景 | 反馈与操作 |
| --- | --- |
| 首次加载 | 页面骨架与明确的加载占位；不暂时显示「今天无事」 |
| 无计划 | 解释创建后的价值，主按钮「创建计划」 |
| 今日无待处理 | 「今天没有固定日期任务」；仍可查看周计划与截止事项 |
| 日历无记录 | 「这一天没有记录」；只对合法日期提供补记 |
| 搜索无好友 | 「没有找到这个用户名」；保留输入便于修改 |
| 网络不可用 | 个人数据可读、打卡可保存到本机；朋友搜索/授权显示需联网 |
| 同步中 | 记录详情小型状态「同步中」，不阻塞继续使用 |
| 同步失败 | 「已保存到本机，同步失败」+「重试」；不暗示记录丢失 |
| 多设备冲突 | 对比两个版本的结果、备注与修改时间，说明系统当前保留版本；提供查看本机版本与确认/修正入口，不静默覆盖 |
| 图片上传失败 | 保留文字和结果；附件显示失败与重试 |
| 权限被系统拒绝 | 解释影响并给「前往系统设置」，不循环请求系统权限 |

**同步设计约定**：列表层只在同步异常时显示提示；详情层可查看「已保存到本机 → 同步中 → 已同步 / 同步失败」。这让正常操作保持安静，同时让用户在有疑虑时查到状态。

## 6. 文案规范

| 场景 | 使用 | 避免 |
| --- | --- | --- |
| 不要做计划成功 | 「今天做到了，没有吸烟」 | 「已完成吸烟」 |
| 用户未操作 | 「未记录」 | 「失败」「漏打卡即失败」 |
| 周目标尚未达标 | 「本周 2 / 3，还差 1 天」 | 「今天必须完成」 |
| 周目标结束 | 「本周未达标」 | 「你失败了」 |
| 一次性逾期 | 「已逾期 2 天」 | 自动消失或伪装为失败 |
| 补记 | 「补记 9 月 20 日」 | 只写「今天打卡」 |
| 历史修正 | 「已修正 · 最近修改 9 月 22 日」 | 悄悄覆盖旧记录 |
| 自主申报 | 「已记录成功」 | 「已认证成功」「已核实」 |
| 离线提交 | 「已保存到本机，联网后同步」 | 「云端保存成功」 |
| 分享确认 | 「对方可查看这项计划已有的状态和文字备注」 | 「与好友分享全部进度」这种范围不明的话 |

所有日期同时考虑业务日期和提交时间。列表优先显示业务日期；补记详情同时显示两个时间。涉及「今天/昨天」的相对词只在计划所属时区语义成立时使用，否则展示绝对日期。

## 7. 无障碍与适配

- Dynamic Type：页面和卡片纵向增长；标题最多不应被截成无法辨认的单行；按钮可换行，底部固定按钮避开键盘与安全区。
- VoiceOver：每张今日卡片读出计划名、执行规则、业务日期、状态、可执行动作；日历格读出日期及聚合状态，如「9 月 20 日，阅读未记录，跑步成功，共 2 项」。状态图标标记为装饰，避免重复朗读。
- Switch Control 与触控：全部交互具备至少 44 pt 命中区域；星期按钮提供选中状态；滑动菜单中的操作也可经可见入口完成。
- 颜色与形状：状态有文字、图形和色彩；高对比度模式下保留边框；深色模式使用语义色，不机械反转。
- 减少动态效果：提交反馈仍显示文字，不依赖动画传达成功。系统粗体、降低透明度等辅助功能下保持布局可读。
- 小屏、横屏与大字号：优先单列；月历日期格变窄时减少装饰，保留日期数字与可访问性摘要；不强行把七个周按钮挤成不可点击的小格。
- 本地化准备：日期、星期、时间、数值单位使用系统格式；本版中文文案先经人工校对，避免用计划名直接拼接产生病句。

## 10. 设计决策压力测试与确认记录

以下是依据 `grill-me → grilling` 方法建立的决策树：先厘清会影响整个体验的前置决策，再处理依赖它的局部页面。PRD 已确定的规则不重新提问；经本轮问答确定的方案已更新到对应页面规格。

| 前置决策 | 推荐方案 | 若改变，会影响 |
| --- | --- | --- |
| A. 用户主要任务是什么？ | 先执行与记录，再回顾；今日默认首页 | 导航顺序、首屏信息密度、打卡入口 |
| B. 是否允许系统替用户判定？ | 不允许；未知始终为未记录 | 全部状态文案、统计与日历 |
| C. 周目标是每天的待办吗？ | 不是；仅周总目标，空白日无状态 | 今日、提醒、日历、周统计 |
| D. 社交范围是什么？ | 逐计划逐好友授权，分享前预览历史文字备注 | 朋友 IA、权限管理、只读视图 |
| E. 正在进行的今天何时计入固定日期完成率？ | **已确认**：今日未提交时暂不计入；提交后计入，并显示统计截止日期 | 详情中的实时比率 |
| F. 计划所属时区能否修改？ | **已确认**：首版创建后固定；只展示，不提供修改入口 | 日期归属、提醒和跨设备行为 |
| G. 一次性任务能否设置过去的截止日期？ | **已确认**：新建时只能选择今天及未来日期 | 创建校验与任务状态 |
| H. 账号登录方式？ | **已确认**：手机号 + 短信验证码 | 登录、账号恢复、换绑与用户名设置 |
| I. 数据导出范围与格式？ | **已确认**：完整 ZIP，含 CSV、JSON、私人照片和关系数据 | 导出页说明与文件生成 |
| J. 一次性截止提醒默认值？ | **已确认**：默认关闭，用户按需选择截止当天、提前 1 天或 3 天 | 创建页和提醒设置 |

**本轮已确认的六项决策**：今日未打卡不计入完成率；计划时区创建后固定；一次性任务只能选择今天及未来截止日期；手机号验证码登录；完整 ZIP 导出；一次性任务提醒默认关闭。分享预览仍须让用户实际看到历史文字备注，尤其是很久以前的敏感内容，而不只给一个抽象的提示。若改变以上决策，应先更新状态模型和文案，再改视觉稿。
